# Synthetic capability package (not release)

Only on **DESKTOP-OS4Q8CP**, Windows 11, Docker Desktop Linux containers. No repository, Python, local credentials or existing DG installation is needed there. No Docker command is run on the development machine. Uses a dedicated project, three containers, three named volumes, no published ports, an internal network, generated in-memory credentials, and a disposable synthetic note. Pull/build requires target Internet access; it never invokes paid inference. The three images are version-tagged, **not digest-frozen**; this is not a release or production deployment.

1. Transfer only the ZIP and its SHA-256 separately. On the target, before expanding, verify `Get-FileHash -Algorithm SHA256 <zip>` equals the supplied full hash. Select an empty directory, run `Expand-Archive -LiteralPath <zip> -DestinationPath <empty-dir>` (PowerShell), then run:

   `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <empty-dir>\deploy\hosted\sandbox\Run-Sandbox.ps1 -PackageZip <zip> -ExpectedZipSha256 <full-hash> -ReportPath <separate-empty-parent>\dg-1309-report.json`

   The script rechecks ZIP and every extracted file before ANY Docker invocation; it aborts on an unexpected file, symlink, wrong host, occupied project/port, low free disk or old Compose. Report path must be outside extraction; do not transfer logs, env files, Docker volumes or credentials. Review output report before sharing.

2. Runtime budget: 1 CPU and 1.25–1.5 GiB per container, combined maximum 3 CPUs/4 GiB; 256 PID/container; 12 GiB initial free disk; 20-minute build/pull, 5-minute start, 2-minute individual probes, 35-minute overall deadline; 3 named volumes and no host ports or host-gateway. Check Docker Desktop disk allocation yourself (Docker build cache and pulled image layers are global and **not** hard-quota-isolated by Compose). On failure the report is FAIL/BLOCKED. The script always attempts `docker compose -p dg-hosted-1309-sandbox down -v --remove-orphans` **only for this project**. It does not prune images, build cache or other volumes. Check `docker compose -p dg-hosted-1309-sandbox -f <empty-dir>\deploy\hosted\sandbox\compose.yaml ps -a` after the run; if cleanup fails, stop and arrange owner-supervised cleanup only of this named project.

3. The data-service probe makes a real admin login, rejects an unsafe request without CSRF, ingests the named read-only `hosted-ingest` folder, checks exact synthetic `SpecNote` in isolated Neo4j, and rejects absent/private/escape paths. n8n's own CLI imports and executes the named mounted workflow; the `Read/Write Files from Disk` node reads `/files/workflows/sandbox-file-read.json`, the JSON extraction and Code node verify its content. A second n8n workflow tries `/etc/passwd` and must fail at the read node under `N8N_RESTRICT_FILE_ACCESS_TO`; failure to run that node is not accepted as denial proof. All results must be observed; no static PASS. n8n 2.4.8 CLI import/execute behavior cannot be guaranteed until actual target evidence, so report failure honestly rather than substituting a parse-only test.

Report includes only machine name, commit, ZIP hash, bounded check booleans/counts, status and cleanup status. Neo4j must first pass an authenticated `cypher-shell` health check (without putting the password in the process arguments) before data-service is started; `running` alone is insufficient for its startup index transaction. At `service-start`, a failed Neo4j wait (`neo4j-not-ready`), failed data-service `compose up` (`compose-up-nonzero`), or data-service readiness timeout (`readiness-timeout`) records only an allowlisted `startDetail` and Docker state for `neo4j` and `data-service` (status, numeric exit code, OOM flag). If data-service exits during readiness, the runner reads at most 120 log lines locally and emits only fixed `startSignature.phase` and `errorClass` labels (possibly `unknown`). At `n8n-named-file-read`, the runner records only a fixed `n8nDetail` label (`import-command-error`, `import-nonzero`, `execute-command-error`, `execute-nonzero`, `output-not-json`, or `unexpected-evidence`). If stdout is not a single JSON document, it adds a fixed `n8nOutputShape` (`empty`, `text-before-json`, `text-after-json`, `json-like-malformed`, or `text-only`). n8n's `--rawOutput` is not a complete stdout guarantee: the parser accepts a single exact `User settings loaded from: /home/node/.n8n/config` line before the JSON object, or no line, and rejects any other prefix/suffix; the named-read evidence and denied-read node still have to be verified independently. The notice allowance is based on the V7 output-shape label and n8n upstream behavior, **not** a confirmed raw-text match on the target. The runner never reports the CLI text or extracts an arbitrary JSON fragment. These are diagnostics, not proof of a cause. Never share raw logs, image metadata, error strings or credentials. Script does not retain raw CLI output, secrets, HTTP responses or container logs. An interrupted PowerShell process or host reboot can bypass `finally`; inspect and explicitly remove only the named sandbox project then. No Plan 03 SUMMARY until target runtime evidence passes.
