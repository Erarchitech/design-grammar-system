# Стенд DG на сервере (Contabo Cloud VPS 8, тестовые данные)

Профиль для многопользовательского теста, **не замороженный релиз**: образы Speckle берутся по
плавающим тегам, бэкап на старте = снимок диска хостера, данные тестовые. Полное восстановление
шести хранилищ доказывается параллельно (план 1309-04). Ничего здесь не покупает и не
разворачивает само: каждый шаг запускаете вы (или я по SSH на одноразовом сервере с вашим явным
разрешением).

## Что нужно заранее
1. Сервер: Ubuntu 24.04 (или 22.04), 8 vCPU / 24 ГБ, срок **1 месяц**, NVMe-вариант диска.
2. Три DNS-имени с A-записями на IP сервера (например `dg.`, `speckle.`, `objects.` под вашим
   доменом). Если домена нет, временный вариант: `dg.<ip-через-дефис>.nip.io` и т. п.; общий
   лимит Let's Encrypt на `nip.io` может не пропустить выпуск, это запасной путь.
3. SSH-ключ. Пароли и ключи в чат не отправлять.

## Шаги
На вашем ПК, из корня репозитория (архив около 4 МБ; отвергаются приватные ИМЕНА путей, а содержимое
файлов не сканируется; в архив попадает рабочее дерево, в том числе незакоммиченное, это записано в
`PACK-INFO.json`):
```
python deploy/hosted/server/pack_source.py --repo . --output dg-stand.tar.gz
scp dg-stand.tar.gz root@<IP>:/root/
```
На сервере:
```
mkdir -p /opt/dg && tar xzf /root/dg-stand.tar.gz -C /opt/dg && cd /opt/dg
bash deploy/hosted/server/bootstrap-server.sh          # Docker + файрвол 22/80/443
python3 deploy/hosted/server/make_env.py --example .env.example --output .env \
    --dg-host dg.example.org --speckle-host speckle.example.org \
    --object-host objects.example.org --acme-email you@example.org
bash deploy/hosted/server/deploy.sh                    # сборка, запуск, bootstrap Speckle
```
`make_env.py` создаёт `.env` со случайными секретами и не печатает их. Логин и пароль первого
администратора DG лежат в нём (`DG_BOOTSTRAP_ADMIN_USER/PASSWORD`); прочитайте на сервере и
смените пароль после входа.

## Проверка после запуска
- `https://<dg-имя>` открывается с действительным сертификатом (первый выпуск до минуты).
- Вход администратором; создание второго пользователя и проекта; чужой проект ему не виден.
- Все порты, кроме 22/80/443, снаружи закрыты (`nmap` с другой машины).
- `docker compose ... ps`: сервисы `running`, без перезапусков.

## Что я НЕ смог проверить (проверяется на сервере, поэтому первый запуск итеративный)
- Сборка и запуск на Linux: я проверял только разбор Compose и скрипты `bash -n` на Windows.
- Выпуск сертификатов (ACME) и достижимость из России.
- Рабочие процессы n8n: на чистом томе их нет. `import-n8n.sh` повторяет ваши заметки от
  2026-06-23, но для n8n 2.4.8 команды публикации не проверены; в крайнем случае импортируйте в
  интерфейсе n8n. Копии в репозитории могут быть старее ваших живых.
- Загрузка объектов Speckle через публичный адрес (`objects.`): в проекте помечена как не
  доказанная.
- Токены Speckle (`SPECKLE_WRITE/READ_TOKEN`) пустые намеренно: DG берёт токен из настроек
  Speckle в интерфейсе после создания пользователя.
- Ключ LLM-провайдера задаётся в интерфейсе (LLM settings), не в файлах.
- Хватает ли 24 ГБ: смотрите `docker stats` под нагрузкой тестировщиков.

## Известная проблема, которую набор уже обходит
`speckle/bootstrap-local.sql` вставляет строки в таблицы, которых нет на пустой базе, поэтому
монтирование в `docker-entrypoint-initdb.d` роняет первую инициализацию PostgreSQL (по чтению кода,
не запуском); при перезапуске контейнер стартует уже без init-скриптов, и bootstrap молча не
применяется. Серверный оверлей его не монтирует, а `deploy.sh` применяет файл после того, как
схема и встроенные приложения Speckle (`spklwebapp`, `explorer`) созданы.
