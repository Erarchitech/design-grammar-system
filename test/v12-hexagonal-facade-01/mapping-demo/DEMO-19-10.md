## Сюжет

**1. Проблема (1 мин).** На холсте фасад: потоки панелей и модулей, скрипт замеров, 14 слайдеров, ни одного компонента DG. Раньше классы DG привязывали вручную через METAGRAPH Objects + List Item по индексу. Новый класс в онтологии сдвигал индексы, и в OBJECT STATE попадали не те классы. Покажите пустой холст DG.

**2. Вход — меппинг начинается сам (2 мин).** Введите Username и Password, Connect = True.
- CONNECTOR: «Connected · Signed in · Map: 13?».
- В Rhino элементы окрашиваются: оранжевый — неоднозначно, жёлтый — предложено.
- В Web UI появляется сессия, таблицы «Расчётные выходы» и «Параметры DG» уже заполнены.
- Говорите: «Система прочитала холст: 7 потоков элементов, 18 расчётных выходов, 14 слайдеров. Дубли и объединения потоков отброшены по габаритам элементов».

**3. Пока думает LLM (2–3 мин).** Строка «Предложение LLM готовится». Пока ждём, откройте таблицы.
- Выходы сопоставлены со свойствами DG по совпадению значений с геометрией: VC = 3 у всех элементов Panels A → hasVertexCount.
- Слайдеры — это параметры DG, а не свойства.
- Детерминированная часть всегда одинакова; LLM даёт ещё один голос, решает человек.
- Когда предложение придёт, вопросов станет около 6, CONNECTOR покажет новое число.

**4. Ответы (3 мин), в DeGram или в Web UI.** Покажите карточку: заголовок в одну строку и по строке на компонент. В DeGram нажмите цветную кнопку «Panels A»: Grasshopper выйдет на передний план и приблизит компонент. На холсте вокруг предлагаемых компонентов видны рамки с тегами «DG ? …».
- **Panels A** и **Panels C**, вопрос «меппинг или проект?». Прочитайте текст вслух: «Свидетельства за GlassPanel: предложение LLM, названия на холсте…; но как GlassPanel нарушено R_GLASS_ASPECTRATIO_MIN ×120. Как BottomTriangularPanel всё выполняется». Это главный момент: LLM ошибся, правила проекта это показали, человек решает. Ответ — **BottomTriangularPanel**.
- Пакет классов → «Принять все предложенные классы».
- Пакет свойств → «Принять все предложенные свойства».
- «D (Planar)», одно значение → «Не свойство DG».
- Слайдеры → «Принять все как параметры DG».

Покажите отмену: в «Принятых решениях» нажмите «Отменить решение» у последнего ответа — вопрос вернулся; ответьте снова. После последнего ответа CONNECTOR ждёт 10 с («Map …»), затем применяет.

Ожидаемо: цвета зелёные, теги стали «DG ✓ …» и исчезли после применения, на CONNECTOR «Map ✓».

**5. Расстановка (2 мин) — ⚠ репетиция.** Справа от холста появляется группа «DG · автоматический меппинг (CONNECTOR)»:
- GRAPH DECONSTRUCT → METAGRAPH;
- 5 OBJECT STATE;
- 11 пар `R <Rule_Id>` + `PS <Rule_Id>`;
- PARAMETER STATE, DESIGN STATE (376 объектов, 976 значений), VALIDATOR.

Покажите вход `Object` у одного OBJECT STATE: текст `class:…#GlassPanel`, никакого List Item. «Привязка по идентичности: новые классы в онтологии её не сдвинут».

**6. VALIDATOR (1 мин) — ⚠ репетиция.** Panel на `VALIDATOR (auto)` → `Report`. На V1 по 11 правилам нарушений нет. `SendValid = False`, в Speckle ничего не уходит.

**7. Вариант V2 — обучение (2 мин) — ⚠ репетиция.** `& $rc script "$dg\dgmap_act_v2.py"`, Module Width F1 = 4400:
- появляется новая сессия с 0 вопросами, всё синее: элементы размечены по профилям, выученным из ответов в шаге 4;
- VALIDATOR показывает нарушения V2: R_GLASS_ASPECTRATIO_MAX ×12 и R_GP_WIDTH_MIN ×57 (по замерам 05.10). Это сигналы проекта, а не вопросы меппинга.

Затем `& $rc script "$dg\dgmap_reset_v1.py"`.

**8. Итог (1 мин).**
- Человек ответил на 6 вопросов, и система расставила DG до VALIDATOR.
- Следующие варианты размечаются без вопросов.
- Каждое решение хранится в графе с автором и датой как профиль.
- Revit (только чтение) использует те же профили: шаг 6 инструкции, по желанию.

## Если что-то пошло не так

| Симптом | Действие |
|---|---|
| «Предложение LLM: unavailable» или ждать дольше 5 минут | отвечать на 13 вопросов по таблице инструкции (раздел «Если LLM не пришёл») |
| 502 в панели «Меппинг» | `docker start data-service`, через 20 с Ctrl+Shift+R |
| Группа DG не появилась после «Map ✓» | выход `Mapping` у CONNECTOR, строка `placed …` / `nothing to place …`; запасной план — скриншоты |
| Вопросов 0 сразу после входа | профили не выключены: показать «обучение» (шаг 7) и вернуться к вопросам по скриншотам |
| Ошибся с ответом | «Отменить решение» у этого ответа (до применения); после применения — закрыть копию без сохранения, Claude выключает профиль ответа, открыть снова (новая сессия и вызов LLM) |
| Клик по компоненту в DeGram ничего не делает | LISTENER на холсте выключен (Run) или открыт не тот документ; в «Моделях» нажмите «Обновить» |
