# Автоматический меппинг в Grasshopper — runbook (Phase 1303, планы 1303-08 и 1303-09)

С 18.10 меппинг встроен в **CONNECTOR** (DG.gha). Компонент для меппинга, проводка и Custom Preview не нужны. На холсте без компонентов DG CONNECTOR после согласования сам расставляет их вплоть до VALIDATOR. Решения D-33…D-38 — в `.planning/phases/1303-pravilo-gh-obekt/1303-CONTEXT.md`.

## Как это работает

1. **Вход.** Username / Password / Project, Connect = True. Вход `AutoMap` (по умолчанию True) включает автоматический меппинг. Username и Password в .gh не сохраняются. Если подать их из Panel, они сохранятся в тексте Panel.
2. **Чтение холста** после каждого изменения, когда холст полторы секунды в покое:
   - **потоки элементов:** геометрия, подключённая к компонентам DG (OBJECT STATE и др.). Если такой нет: именованные источники геометрии расчётных компонентов и именованная конечная геометрия;
   - **дубли и объединения пропускаются.** Элементы сравниваются по габаритам. Пропускаются точная копия другого потока и поток, содержащий два или больше других («All panels», поверхности модулей над их контурами);
   - один элемент — одна ветка, а при одном списке — один объект;
   - контекст каждого потока: названия групп (с вложенными), scribble в той же группе или рядом, имя и никнейм компонента, класс, уже выбранный в OBJECT STATE;
   - **расчётные выходы** (кандидаты в свойства DG): конечные числовые выходы расчётных компонентов и именованные вычисляемые числа, чьи ветви совпадают с ветвями потока. Для каждого потока считается доля элементов, у которых значение равно признаку, вычисленному плагином (вершины, разрывы, пропорции, ширина, планарность, высота);
   - **именованные слайдеры** — кандидаты в параметры DG: имя, тексты вокруг, значение, диапазон.
3. **Сессия.** Если содержимое холста изменилось (отпечаток), CONNECTOR создаёт сессию в DG (`POST /mapping/sessions`, токен только в заголовке). Вопросы — в Web UI → Проекты → проект → Меппинг. Если после детерминированного расчёта вопросы остались, DG один раз спрашивает LLM. Ответ приходит в фоне примерно через 2–3 минуты и пересчитывает сессию, уже данные ответы сохраняются.
4. **Цвета в Rhino** по состоянию: подтверждено `#2E7D32`, авто по профилю `#1565C0`, предложено `#F9A825`, неоднозначно `#E65100`, без меппинга `#9E9E9E`. CONNECTOR проверяет сессию каждые 3 с.
5. **Применение.** Когда вопросов не осталось, CONNECTOR применяет сессию.
6. **Расстановка** (только на холсте без OBJECT STATE / PROPERTY STATE / VALIDATOR). Всё ставится одной группой «DG · автоматический меппинг (CONNECTOR)»:
   - GRAPH DECONSTRUCT → METAGRAPH;
   - OBJECT STATE на класс и измеряемый поток: `Object` = текст `class:<IRI>`, `Geometry` ← поток;
   - RULE BY ID (`RuleId` = Rule_Id) + PROPERTY STATE на каждое правило: `DataProperty` = IRI свойства, `PropValue` ← расчётный выход, `ObjState` ← OBJECT STATE;
   - PARAMETER STATE: по входу на каждый слайдер-параметр, имя входа = имя слайдера;
   - DESIGN STATE и VALIDATOR (`SendValid` = False, `Token` ← `CONNECTOR.Session`).

   Индексных List Item нет, поэтому новые классы в онтологии выбор не сдвигают. Потоки класса без расчётного выхода не ставятся; это видно в примечании в `Mapping`.

## Выходы CONNECTOR

| Выход | Что даёт |
|---|---|
| `Mapping` | сводка: элементы по состояниям, расчётные выходы, слайдеры, статус LLM, открытые вопросы, потоки, расстановка, id сессии |
| `ByClass` | ветка `{k}` — геометрия класса `ClassNames[k]` в порядке холста |
| `ClassNames` | классы применённого меппинга (по алфавиту) |
| `ClassObjects` | классы DG для входа `Object` у OBJECT STATE |
| `Sliders` | «слайдер → параметр DG / не параметр DG (состояние)» |

Ручная разводка на холсте, где OBJECT STATE уже стоят: Object ← `List Item(ClassObjects, k)`, Geometry ← `Tree Branch(ByClass, {k})`.

## Демо-скрипты RhinoCode

`$rc = "C:\Program Files\Rhino 8\System\RhinoCode.exe"`, `$dg = "C:\Users\Admin\source\repos\dg-mapping\test\v12-hexagonal-facade-01\mapping-demo\rhinocode"`, запуск: `& $rc script "$dg\<файл>"`.

| Файл | Действие |
|---|---|
| `dgmap_act_v1.py` … `dgmap_act_v4.py`, `dgmap_act_validate_v1.py` | ставят оба слайдера варианта (`Module Width F1`, `Наклон нечет сот`); дальше CONNECTOR меппит сам |
| `dgmap_refresh.py` (`dgmap_apply.py` — то же) | записывают сводку CONNECTOR в `%TEMP%\dgmap-rhinocode.log` (строки `EVIDENCE`) |
| `dgmap_reset_v1.py` | слайдеры варианта снова V1 |

При ошибке акт возвращает прежние значения слайдеров. Скрипты работают только с файлами, имя которых кончается на `-mapping.gh` (`…-mapping.gh` и очищенная копия `…-auto-mapping.gh`).

## Неполадки

| Симптом | Причина / действие |
|---|---|
| `Mapping`: «sign in to map automatically» | CONNECTOR не вошёл |
| `Mapping`: «DG refused the session (401 …)» | сессия входа истекла — Connect заново |
| `Mapping`: «… 403 PROJECT_FORBIDDEN» | CONNECTOR привязан к другому проекту |
| `Mapping`: «nothing to map» | к компонентам DG не подключена геометрия, видимой геометрии и именованных слайдеров нет |
| `Mapping`: «nothing to place …» или расстановки нет | на холсте уже есть состояния DG, или ни один класс не получил элементов |
| статус LLM «unavailable» | LLM недоступен или не уложился в 7 минут; вопросы остаются детерминированными |
| много сессий при перетаскивании слайдера | сессия создаётся после 1,5 с покоя; при необходимости `AutoMap` = False |

Запасной путь — прототип `../gh-mapping-intake.cs` (C# Script, план 1303-03).
