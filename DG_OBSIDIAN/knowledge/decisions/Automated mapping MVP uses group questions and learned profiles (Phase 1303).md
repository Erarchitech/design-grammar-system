# Автоматизированный меппинг (MVP Phase 1303): групповые вопросы и обучаемые профили

**Контекст.** Элементы из Grasshopper (выходы определения) и Revit (категория, семейство, тип, параметры) нужно сопоставить с классами DG проекта. Вопрос «это окно?» по каждому элементу не масштабируется. Он не решает и перекрытия: один элемент фасада может законно быть и окном, и стеной. Исследование: `docs/reviews/mapping-issue-investigation/…Active-Learning UX….md`. Срок — демо 19.10.2026.

**Решение (подтверждено владельцем 2026-10-17: «групповое + профили», GH + Revit вживую).**

- Конвейер: **свидетельства → группы → вопросы о последствиях → обучаемые профили**. Движок `data-service/mapping_engine.py` чистый и детерминированный. LLM в классификации не участвует, только поясняет ответы (план 07, линия отсечения).
- Свидетельства:
  - профили;
  - токены имён (аббревиатура, подпоследовательность, слово, синонимы из словаря);
  - согласованность с правилами: шаблон нарушения инвертирован; сравнения одного тела правила оцениваются **вместе** как конъюнкция; равенство весит больше диапазона;
  - IFC-подсказки;
  - совпадение численности групп с сессией другой платформы.
- Вопрос задаётся группе, а не элементу. Типы: пакетное подтверждение, назначение, выбор между классами, «ошибка меппинга или ошибка проекта?». Последний вопрос показывает последствия каждого варианта для правил, например: как HexagonalUnit — R… нарушено ×25, как GroundFloorUnit — выполняется.
- Разрешены несколько ролей (с учётом непересекаемых классов) и ответ «обе роли».
- Ответ создаёт профиль (селектор → роли). Уверенность профиля (c+4)/(c+r+5); при ≥ 0,8 следующий вариант или другая платформа размечаются автоматически («авто по профилю»).
- Нарушение правила при уверенном меппинге — сигнал проекта, а не вопрос.
- Хранение (D-32): MappingSession / MappingDecision / MappingProfile (`graph: 'Computgraph'`, `project`), связи `HAS_DECISION`, `CREATED_PROFILE`, `ASSIGNS_ROLE`→Class. `Representation` / `MAPPED_AS` в MVP не пишутся.
- Доступ: маршруты `/mapping/*` с политиками; коннектор (`dgk_`) только в своём проекте; решения и авторские профили принимает только участник проекта.
- Платформы: Grasshopper — прототип C# Script без пересборки DG.gha; Revit — только чтение через revit-mcp.

**Последствия.** `ByClass` и `ClassObjects` заменяют индексные List Item перед OBJECT STATE: классы подбираются по имени. Сохранение `Representation` и `MAPPED_AS`, компонент в DG.gha и IFC-маршрут вынесены за MVP. Живая проверка — репетиция 18.10 (`.planning/phases/1303-pravilo-gh-obekt/1303-TEST-GUIDE.md`).
