# MVP меппинга разрабатывается в отдельном git worktree, чтобы не прерывать Phase 1309

**Контекст.** Основная папка `C:\Users\Admin\source\repos\design-grammar-system` стоит на `feature/hosting-dg-pilot`. С ней работает агент 1309 в параллельной сессии Hermes; в папке его staged- и изменённые файлы. Переключение ветки или коммиты там прервали бы 1309. Одна ветка может быть открыта только в одной папке.

**Решение (вариант 1, владелец оставил его после объяснения).** `git worktree`: папка `C:\Users\Admin\source\repos\dg-mapping`, ветка `feature/mapping-mvp` от `535eb30`. Это не новый репозиторий, а вторая рабочая папка того же `.git`. В основной папке ничего не коммитится. Слияние — после демо 19.10 и после точки фиксации 1309.

Это отдельный случай, согласованный владельцем для 1303. Запрет worktree для GSD-агентов из Phase 1302 к нему не относится.

**Последствия.**

- Владелец удивился «новому репозиторию». Прежде чем создавать worktree, объяснить, что это такое, и дождаться ответа.
- GSD-инструменты не отслеживаются и скопированы в `.claude/` worktree целиком — не коммитить их. Хуки graphify переписывают `graphify-out/` — коммитить только явные пути.
- Образы Docker общие для обеих папок (compose-проект `design-grammar-system`). Пересборка из worktree заменяет образы, на которых работает локальный стек; откат — теги `:pre-1303`.
- При слиянии ожидаются конфликты в `Current priorities.md`, `00-home/index.md`, `.planning/STATE.md`, `.planning/ROADMAP.md`; разрешать вручную.
