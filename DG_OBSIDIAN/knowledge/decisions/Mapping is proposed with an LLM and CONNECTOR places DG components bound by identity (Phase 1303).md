# Меппинг предлагает LLM, а компоненты DG расставляет CONNECTOR со связями по идентичности (Phase 1303, D-33…D-38)

**Контекст.**
- Прототип C# Script `DG MAPPING` (план 1303-03) пришлось бы ставить вручную перед каждым меппингом. Владелец отверг это: меппинг должен предлагаться автоматически.
- Уточнение онтологии: слайдер — это параметр DG, а не свойство; значения свойств дают выходы расчётных компонентов.
- В ручной разводке фасада класс для OBJECT STATE выбирался через METAGRAPH Objects + List Item(индекс). Индексы сдвигались при добавлении классов в онтологию, и в OBJECT STATE попадали не те классы.

**Решение (владелец, 2026-10-18).**
- **D-33/D-34:**
  - меппинг встроен в CONNECTOR (DG.gha, вход `AutoMap`);
  - после входа CONNECTOR читает холст и создаёт сессию, если изменился отпечаток холста;
  - CONNECTOR опрашивает сессию каждые 3 с и применяет её, когда вопросов не осталось.
- **D-35:** названия групп, scribble, имена компонентов — словесные свидетельства (с русским лексиконом).
- **D-37:**
  - поток элементов → класс;
  - слайдер → параметр DG (вход PARAMETER STATE, ParameterId = имя слайдера);
  - выход расчётного компонента → свойство DG, по совпадению значений с признаками, которые плагин вычисляет сам, по имени, по тексту на холсте и по LLM;
  - выход голосует за класс своего потока через классы, в правилах которых есть его свойство;
  - дубли и объединения потоков пропускаются.

  LLM вызывается один раз на сессию через шлюз, в фоне, с короткими id (s1 / m1 / p1). Ответ проверяется по дайджесту и сохраняется как один голос среди детерминированных свидетельств. Решает человек. Точка вызова записана в `spec/REPRODUCIBILITY.md`.
- **D-38:** если на холсте ещё нет состояний DG, после применения CONNECTOR ставит:
  - GRAPH DECONSTRUCT → METAGRAPH;
  - OBJECT STATE на класс и измеряемый поток (`Object` = текст `class:<IRI>`);
  - RULE BY ID (`RuleId` = Rule_Id) + PROPERTY STATE на каждое правило;
  - PARAMETER STATE;
  - DESIGN STATE;
  - VALIDATOR (`SendValid` = False).

  Индексных List Item нет ни в одном месте.

**Последствия.**
- Проблема индексных выборщиков закрыта для расставленных компонентов: класс и правило заданы по идентичности.
- Поток класса, который не измеряет ни один выход, не ставится (об этом есть примечание). PROPERTY STATE сочетает один выход с элементами одного потока.
- Решение D-36 «слайдеры → свойства» заменено решением D-37.
- C# Script остаётся только запасным путём.
