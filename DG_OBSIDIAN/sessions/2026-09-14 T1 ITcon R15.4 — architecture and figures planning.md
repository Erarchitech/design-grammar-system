## Session decisions

- Use the wording **“the proposed DG-based system architecture”** for descriptions of the Design Grammars system.
- Treat all system descriptions built around the DG ontology as conceptual architecture, not demonstrated end-to-end operation.
- Ontograph is the principal living organisational graph-ontology. It develops with the organisation's CDE through controlled proposals, operator/ontology-steward approval, versioning, provenance, impact analysis and regression checks.
- The Structure of a DG Object covers three coordinated criteria: semantic description; links to BIM/IFC and parametric representations; and spatial topology/analysis.
- BOT is the semantic building-topology resource within the LBD approach.
- IFC is the BIM exchange and classification context, connected through documented class-level correspondences and bSDD references where appropriate.
- TopologicPy is the computational resource for non-manifold spatial topology and spatial analysis. TopologicPy-computed relations are not automatically identical to BOT relations; selected relations are interpreted through BOT only when mapping conditions and building semantics coincide.
- An LLM-assisted agent proposes candidate mappings; Ontograph grounding, external identifier checks, structural constraints and operator confirmation determine approved mappings.
- DG identity links source-specific representations and provenance; it does not imply automatic synchronisation of all source properties.

## Pipeline agreed for future figure/text work

```text
Parametric model / BIM model / CDE document update / direct DG interface input
    → extraction
    → DG identity resolution or minting
    → DG Object creation/update
    → Ontograph grounding
    → BOT/LBD and IFC/bSDD candidate references
    → operator review and approval
    → TopologicPy geometry/topology analysis
    → DG topology graph and provenance
    → selected BOT semantic interpretation
    → Ontograph-grounded Design Rules
    → Design State / ValidGraph evidence
```

The ordering is conceptual. A DG identity may be created before topology analysis so that partial imports and provenance remain addressable.

## Research conclusions

Perplexity, paper-search and web/citation checks support the distinction between TopologicPy as a computational library with a published semantic vocabulary/ontology and BOT as a formal building-topology ontology in the W3C LBD context. The repository's V8 artefacts contain a Topologic alignment file and a BOT alignment file; the external TopologicPy resource is not silently equated with the DG alignment artefact.
