## The finding that reshaped the round

**Topologic has a published OWL ontology** — `http://w3id.org/topologicpy#`, TTL at
`wassimj.github.io/topologicpy/ontology/topologicpy.ttl`. Verified by direct retrieval:
all eight core classes, the full parthood / adjacency / containment / typology / boundary
relation set, ~20 element classes, and **25 `rdfs:subClassOf` + 4 `rdfs:subPropertyOf`
axioms aligning it to BOT**.

This overturned the premise of the concurrent session's §6.12, which had argued BOT
survives while honestly recording its own defeat condition — that BOT buys little if the
schema's rules quantify over element terms. Its table showed exactly that failure
(`Facade`, `GlassPanel` → `bot:Element`, *"close to information-free"*). `top:` closes it.

**An earlier claim of mine was wrong and was corrected in session:** I had stated no
published OWL Topologic existed and built a "referenced vs supplied" criterion on it.

## What the paper now says

Three alignment modules, one question each, one attachment point each:

| Module | Vocabulary | Answers | Attaches at |
|---|---|---|---|
| Topology | `top:` (⊑ BOT) | how does this relate spatially? | core **Topology** concept |
| Classification | **IFC** via **bSDD** | what kind of entity does this term denote? | minted **Ontograph** class |
| Standards | W3C / OGC | how is this expressed and provenanced? | core + rule layer |

**Two attachment points is what delivers non-overlap** — even if both vocabularies held a
"Wall", one types the topological entity at the core band and the other classifies the
vocabulary term at the Ontograph.

**BOT is subsumed, neither bridged nor erased.** `top:` already does BOT's job upstream and
declares the subsumption, so a DG→BOT bridge would be a second path to a vocabulary the
topology module already reaches. BOT stays cited as the layer `top:` extends and as the
origin of the topology/classification division — which is documented: BOT's scope statement
limits it to *"referential topological concepts"*, `bot:Element` is deliberately
unconstrained, and classification is delegated to a named sibling, **PRODUCT/BPO**.

## Critical findings

- **IFC cannot take BOT's relational role.** BOT exists *because* ifcOWL's reified
  `IfcRel*` model is unusable for linked data — 1,331 classes / 1,599 properties versus 7 / 14.
  IFC takes the **classification** role; `top:` keeps relations. Reversing that would forfeit
  Table 1 [P71]'s *"Low — no full IfcOWL serialisation required"*.
- **The "IFC is huge" objection has two halves.** LLM search dissolves the *authoring* half
  (bSDD offers keyword search, not semantic); *reference-not-import* dissolves the *reasoning*
  half. The author's argument covered only the first.
- **Two uncited references repaired.** `Jabi & Chatzivasileiadi (2021)` and
  `Rasmussen et al. (2020)` were both in the reference list and cited nowhere in the body.
- **A stale ordinal this package would otherwise have introduced.** §2.2 counts the standards
  module *"third"*; merging two topology modules into one makes it the second. Fixed by naming
  rather than renumbering (T17).
- **Geometry gap and OPM overlap.** The core declares `Geometry` with no alignment, and OPM
  models per-property state chains close enough to `DesignState` to invite the question. Both
  are now declared non-alignments in §2.2 (T3).
