# Phase 1303 — автоматический меппинг в CONNECTOR: предложение LLM и расстановка компонентов DG до VALIDATOR

## Цель

Продолжение сессии 2026-10-17, накануне демо 19.10. Владелец поставил задачи по ходу сессии:

1. Объяснить индексы GSD: milestone v13.0 виден в обеих ветках, меппинга и hosting.
2. Отказаться от ручного компонента C# Script `DG MAPPING`: «меппинг должен предлагаться автоматически». Встроить меппинг в DG.gha и учитывать названия групп, тексты scribble и имена компонентов.
3. Уточнение онтологии. Слайдеры — это **параметры** DG. Свойства берутся из выходов расчётных компонентов (например, Area). Связи находит LLM, после согласования компоненты DG расставляются автономно. Проверять на файле без OBJECT STATE и убедиться, что закрыта проблема «индексные выборщики сдвинулись, поэтому в OBJECT STATE стоят не те классы».
4. Объём проверки: «весь цикл до VALIDATOR» на очищенной копии фасада.

## Сделано

- **Индексы GSD.** Меппинг идёт в v13.0, фаза 1303: планы `1303-NN`, требования DGMAP, решения D-xx. Hosting — фаза 1309: планы `1309-NN`, требования HOST. Номера не пересекаются; конфликты будут только в общих файлах STATE / ROADMAP / REQUIREMENTS при слиянии. Владелец: «оставить 1303, свести при слиянии».
- **1303-08 — автоматический приём в CONNECTOR** (D-33…D-36). CONNECTOR после входа сам:
  - читает холст после 1,5 с покоя;
  - создаёт сессию, только если изменился отпечаток холста;
  - опрашивает её каждые 3 с, раскрашивает элементы в Rhino;
  - применяет меппинг, когда вопросов не осталось.

  Текст на холсте (группы, scribble, имена) учитывается как словесное свидетельство, с русским лексиконом. Компонент C# Script больше не нужен.
- **1303-09 — роли онтологии, LLM и расстановка** (D-37, D-38):
  - слайдер → параметр DG (`batch-parameters`);
  - выход расчётного компонента → свойство DG. Свидетельства: совпадение значений с признаками, которые плагин вычисляет сам; аббревиатура в имени; текст на холсте; LLM. Типы вопросов: `batch-measures` и `map-measure`;
  - выход голосует за класс своего потока: H → hasTotalHeightM → Facade;
  - потоки-дубли и объединения отбрасываются по габаритам элементов;
  - LLM вызывается один раз на сессию, в фоне. В дайджесте короткие id s1 / m1 / p1, ответ проверяется по дайджесту и сохраняется в сессии. Тайм-аут шлюза для этого вызова — 420 с (`GenerationOptions.timeout_s`);
  - после применения CONNECTOR ставит группу «DG · автоматический меппинг (CONNECTOR)»: GRAPH DECONSTRUCT → METAGRAPH; OBJECT STATE на класс и измеряемый поток (`Object` = `class:<IRI>`); RULE BY ID (новый компонент) + PROPERTY STATE на правило; PARAMETER STATE; DESIGN STATE; VALIDATOR.
- **Очищенная копия** `v12-hexagonal-facade-01-auto-mapping.gh`, не в git. Убраны состояния DG, VALIDATION GRAPH, REINSTATE, LISTENER и 17 индексных List Item. Оставлены геометрия, Join Curves, Bounding Box и скрипт измерений.

## Проблемы

- [[knowledge/debugging/LLM mapping proposal lost measures and sliders on long native ids|LLM терял выходы и слайдеры из-за длинных id]]. Пустой ответ при 4000 токенах, тайм-аут 120 с, искажённые id. Исправлено: 24 000 токенов, 420 с, фоновый вызов, псевдонимы.
- [[knowledge/debugging/Clean-file mapping noise from union streams, tied outputs and a single-value fallback|Шум на чистом файле]]: потоки-объединения, ничьи между потоками, привязка по выходу с одним значением. Исправлено.
- [[knowledge/debugging/Facade gh copies sign in to CONNECTOR on open from Panels|Копии фасада сами входят в CONNECTOR]]. Пароль лежит в Panel открытым текстом; каждое открытие копии создаёт сессию, их накопилось около 10.
- RhinoCode видит Rhino только при открытом редакторе скриптов (`/runscript="_ScriptEditor"`). Окна Grasshopper «Unrecognized Objects» и «Getting started» блокируют скрипты; закрываются через WM_CLOSE (`close_gh_dialogs.ps1` во временной папке сессии).
- Владелец не понял вопрос «ошибка меппинга или проекта?» по Panels C: формулировку нужно сделать понятнее (см. «Следующие шаги»).
