# Session: 2026-07-26 — v9.0 UAT Group 4 E2E spine: publish, idempotency, provenance

## Goal

Finish Group 4 of `v9.0-PIPELINE-UAT.md`, continuing from the 2026-07-25 smoke test that had closed
4.1 (plumbing, quality blocked) and 4.2 (preview/undo, one FAIL) but left 4.3–4.6 pending.

## What Was Done

- Restored a working LLM key path (DeepSeek — no Anthropic/OpenAI key available), with a detour
  through PowerShell quoting issues (`curl.exe` double-quote stripping, `Invoke-RestMethod` throwing
  on error responses) and a self-inflicted overwrite of the real DeepSeek key with a placeholder that
  had to be restored.
- Pulled the live UrbanBlock_V7 canvas context and built a 5-entity synthetic proposals payload
  (Var/Const/IntF/Emg/Pat) using real untagged node GUIDs, deliberately choosing an IntF wired
  downstream of the Var slider (to make `PARAM_LINK` derivable) and a Pat subset of an existing tagged
  Pattern (to make `PATTERN_HOST_TO` derivable) — neither relationship existed on the canvas as tagged.
- **4.3 concurrent-solve safety** — forced a real mid-solve window by continuously dragging an integer
  slider with 115 downstream components, fired `preview_structure` on a delay. Pass: no crash, no
  corruption, `previewed: 5`.
- **4.4 accept/reject/partial + durability, 4.5 mixed undo** — wired DG STRUCTURE CONFIRM, partial
  accept (2 accept / 1 reject / 2 left pending), single Ctrl+Z restored the mixed state coherently,
  accept-all + save/close/reopen confirmed `source: recognized` survives and parses identically to a
  hand tag. Found that DG STRUCTURE CONFIRM's Pending/Status outputs don't refresh on undo (need a
  forced recompute afterward) — noted as a UX quirk, not a defect.
- **4.5 publish** — first attempt 404'd: the running `data-service` container predated Phase 36 entirely
  (`/computgraph/publish` route didn't exist in the image). Rebuilt the container — **F7**. Second
  attempt 422'd on a bare `Number` component with a null-inferred dataType, root-caused to
  `InferParameterDataType`'s narrow classification — **F5**. Workaround (ungroup) then a clean publish:
  exactly the predicted 11-node / 12-relationship subgraph, matching every relationship type in the
  schema including the two synthetic-proposal-only ones.
- **36 test 2 idempotency** — re-published via the HTTP route directly (component path already proven);
  zero count delta, all 9 dgIds byte-identical.
- **36 test 3 provenance** — `source`/`definitionId`/`publishedAt`/`dgId` all correct, but
  `provider`/`model`/`confidence` null on every recognized node — traced to a structural gap: the accept
  path never carries these fields forward, and the Cg* models/serializer have no such fields at all —
  **F6**.
- **36 test 4 ui-v2 display** — verified the served ui-v2 bundle was already current (no rebuild needed,
  unlike data-service) before checking; all 11 nodes rendered correctly with distinct per-label styling,
  WR-08 Behavior caption confirmed, per-project filter isolation confirmed.
- Wrote all results into `35-UAT.md` and `36-UAT.md`, updated the Group 4 status banner in
  `v9.0-PIPELINE-UAT.md`. Outstanding audit items dropped from 12 to 5 (all in phases 33/34, plus the
  one still-blocked 35 test 1).
