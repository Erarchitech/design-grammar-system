- ==Parametric definition== of a BIM model with input parameters linked to databases (material types) instead of manual BIM modelling
- Architectural design is challenging to fully grasp by isolating a single factor, as it **encompasses polymorphic data types** that span diverse dimensions—spatial, aesthetic, structural, and environmental. The design process morphs based on numerous interrelated components, each contributing a unique layer of complexity. This ==polymorphic nature== means that no single perspective can capture the full breadth of architectural design, which requires integrating these multifaceted data types to achieve a holistic and functional outcome.
- Introduce ==Classification system and Ontology==
- Introduce systematic approach to generative design merging all knowledge about project to make it fully parametric and ==cross-discipline assessment== of final design solution holistically instead of ad-hoc implementation of generative design tools for specific use case ignoring other factors
- Being able to map and score all types of data influencing final design solution
- Enable use of AI assissting design process throguh unification of architectural data 
- LCA Assessment integration with Generative Design
- ==Geometric Graph Grammar== (Article_005)
- Currently Generative design outputs after ad-hoc implementation and achieving specific design objectives handover to the next stage (e.g. from sale department to development design department) and it is crucial that only minimal changes are made by design team after generative system accepted design solution. Therefore design team is very limited to do the work from their perspective (other disciplines as well) as they don't have access to the generative system and cannot evaluate global effect of their changes properly. So they need to request sale department to recalculate the model with changed inputs manually and compare performance again. To overcome this bottleneck it is proposed to embed Generative system in the Core Datascape of project, so instead of exchanging specific design state model files between stakeholders all parties can synchronize their models with the Core Datascape where all vital design concepts are connected and stored as parametric definition of Generative system. Meanwhile all parties may have their own MVD and LoD for pepresentation of the model.
- In assence, the idea of fully integrated building information hub supporting entire lifecycle of the building matches **BIM Level 3**, but BIM Model is not capable by its nature to store generative data such as shape grammars, agent-based dynamic structures and rules controlling design process autonomously as it is object oriented and focused to describe specific state of the design, and assumes that user is fully responsible for the adhearing  information processes filling the model. In contrast, current research proposes that there should be an autonomious generative system fully integrated within whole buidling lifecycle with all building design states and representations. In the end, this system is assumed to be cloud-based and integrated with iBIM model compromising each other to acheave comprehensive building lifecycle management and embracing all aspects including detailed semantics for deep description of the model state and generative grammars  for autonomious control and evaluation of data flows and design changes. 
- The intent of introducing Generative System as a Design Core Datascape is to enhance data-driven approach to design as a whole, expand it to all dimensions of BIM
- Future studies should focus on interoperability in BIM to increase knowledge-integrated, ontology-based, IT-based managed, collaborative, automated, well-visualized, and sustainable outcomes throughout the project lifecycle.
- Modular and pluggable framework enables community-driven development
- Importnat to consider computational cost within Generative Assisstance 
- The idea of cross-platform and multidisciplinary generative copilot system contributes to **Integrated Project Delivery (IPD) ideology**
