<objective>
Give the parser a typed, non-throwing entry point and make `ObjectPropertyAtom` reachable.

`ResolveAtomType` (`SwrlRuleParser.cs:82-94`) today returns `"DataPropertyAtom"` for **every**
non-`swrlb:` predicate with two or more arguments. `ObjectPropertyAtom` is unreachable by
construction. Arity cannot distinguish the two — both are 2-argument — so the only honest
discriminator is the predicate IRI's kind in the OntoGraph, and the only honest answer when that
lookup cannot be made is `unsupported`.

Purpose: this is ALGN12-05. It also closes the silent-misclassification hole this milestone exists
to end — a rule that is genuinely about an object property is currently parsed, evaluated, and
reported as though it were about a datatype property, with no signal anywhere that a guess was made.

Output: `TryParse` returning `SwrlParseResult` (status + rule + diagnostics), an injected
`IPredicateKindResolver` with a null-object default, a Neo4j-backed implementation, and a `Parse`
that still throws exactly as before for existing callers.

**Two decisions the planner settled that CONTEXT and RESEARCH left open — implement these as
written, do not re-derive:**

1. **Resolver granularity is bulk-snapshot, not per-predicate live read.** RESEARCH open question 1
   flagged this. The deciding evidence: `RuleEvaluator.EvaluateRule` calls `SwrlRuleParser.Parse`
   whenever `rule.BodyAtoms` is empty, and `EvaluateRules` loops that over every rule — so a
   per-predicate live Neo4j read would be N round-trips on the exact hot path this phase is trying
   to make safer. The interface therefore exposes a synchronous `TryGetKind` answered from
   already-materialized state; the Neo4j implementation loads its snapshot once, up front, via an
   async factory and then answers in memory. This also keeps `IPredicateKindResolver` synchronous,
   which avoids a `.GetAwaiter().GetResult()` inside a synchronous parser (RESEARCH assumption A3).

2. **`SwrlRuleParser` stays a `public static class`.** RESEARCH Pattern 2 weighed static-with-optional-
   parameter against converting to an instantiable type and found the former lower-risk, because
   D-01 requires every current `Parse` caller to keep compiling. `TryParse` takes
   `IPredicateKindResolver? resolver = null` and null-coalesces to the null-object instance.

**Constraints still binding:** `DG.Core` multi-targets `net7.0;net9.0`, no .NET 8+ only BCL API.
Additive, never replacing. One rollup precedence (plan 01's `StatusRollup`).

**Reversibility note.** D-03 (unclassifiable atoms are emitted as `UnsupportedAtom` rather than
dropped or guessed) is marked **one-way** — this phase's own gate is written against it. It is not
gated behind a `checkpoint:decision` here because the alternative was already rejected upstream in
writing: dropping loses evidence and guessing manufactures a false verdict, and the ROADMAP gate
text ("no unsupported construct becomes an ordinary failure") only has meaning under D-03. Pausing
an autonomous run to re-ask a question whose answer is written into the gate would strand the run
for nothing. D-02's costly-to-reverse signature change is likewise settled by the additive design
above: no existing signature changes at all.
</objective>
