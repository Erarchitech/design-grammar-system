<objective>
Produce this phase's **exit evidence**. D-11 makes a live DE-01 re-run the gate, and states plainly
that unit tests alone are not sufficient. Plans 01–05 make the code correct; this plan proves it at
the boundary where the four legs actually meet.

The required outcome: `silent_disagreement_count = 0`, **or** every remaining disagreement explicitly
declared with a written reason. Those are the only two acceptable results. A run that cannot be
executed is not a third option — it is a blocked gate, and this plan is structured so that a missing
stack surfaces as a human checkpoint rather than as a silent pass or a silent fail.

Purpose: the whole milestone rests on the sentence *"silent disagreement is a failure; a declared one
is not."* This is where that sentence is enforced against real services.

**Two environment realities this plan exists to handle:**

1. **`data-service` has NO source volume mount.** A stale image silently runs pre-change code. This
   trap bit plan 1200-08 and Phase 38-06. Any task measuring behavior through data-service rebuilds
   first — no exceptions, and the rebuild is not optional even when the container is already running.
2. **The `neo4j` hostname resolves only inside compose.** Four `DesignStateValidationFlowTests` and
   four `test_dg_context.py` tests fail from the host for this reason. Those are
   environment-dependent and are **not** regressions; no task here treats them as failures to fix.

**Why this plan is not autonomous.** RESEARCH open question 2 flagged that live-stack availability is
uncertain at execution time. Rather than have a task silently pass on an unreachable service (the
runner degrades gracefully per D-13, so an unavailable leg produces a typed outcome, not a crash —
which is exactly how an unattended run could report "done" having proved nothing), the measuring work
sits behind a blocking human checkpoint that confirms the stack is up before anything is measured.
</objective>
