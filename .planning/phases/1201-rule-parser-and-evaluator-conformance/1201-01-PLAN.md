<objective>
The **tracer slice** for this phase: one production-quality end-to-end path proving the typed-status
mechanism works, before plans 02–04 expand it to every case.

The path proven here is: **unsupported builtin → typed `EvidenceStatus.Unsupported` on
`RuleEvaluationResult.Status` → rolled up by the single shipped precedence → legacy `Passed`
unchanged.** That is the narrowest slice that exercises every mechanism the rest of the phase
depends on (a shared precedence, an additive status field, a per-binding outcome that is neither a
throw nor a `failed`, and an allow-list constant read by both production and test).

Purpose: D-07 is the fulcrum decision. `RuleEvaluator.cs:130`/`:138` throw `NotSupportedException`,
the catch-all at `:52-56` swallows it, and the binding lands in `failingBindings` — so today an
unsupported builtin is reported as **a rule violation**. That single defect is the exact thing the
ROADMAP gate forbids ("no unsupported construct becomes an ordinary failure"), and fixing it first
de-risks D-06/D-08 in plan 02.

Output: `StatusRollup` (the extracted single precedence), `SupportedBuiltins` (the D-15 allow-list),
an additive `Status` on `RuleEvaluationResult`, and a `RuleEvaluator` that returns `Unsupported`
for an unimplemented builtin instead of throwing.

**Non-negotiable constraints for every task in this plan:**
- `DG.Core` multi-targets `net7.0;net9.0`. No .NET 8+ only BCL API. (Phase 32.1 shipped
  `ArgumentException.ThrowIfNullOrWhiteSpace`; Phase 38-05 shipped `JsonObjectCreationHandling.Populate`;
  both broke the net7.0 leg.) Copy signatures from code already in this repo rather than reaching
  for a newer convenience API.
- The precedence order is **already shipped and byte-identical in two languages**. Adopt it verbatim.
  Authoring a second table is the cross-language drift this milestone exists to eliminate.
</objective>

  <behavior>
    - StatusRollup.Precedence exposes the eight statuses in the shipped order and nothing else.
    - StatusRollup.Rollup over a set containing Passed and Unsupported returns Unsupported.
    - StatusRollup.Rollup over a set containing Failed and Unsupported returns Failed (Failed
      outranks Unsupported in the shipped order — this is the shipped semantics, adopted verbatim).
    - StatusRollup.Rollup over an empty input returns NotEvaluated.
    - StatusRollup.Precedence contains every member of EvidenceStatus exactly once (a completeness
      guard, so a future enum member cannot silently fall off the end).
    - EvidenceEnvelopeFactory.Build still produces the same envelope-level status it produced before
      the extraction, for a mixed row set.
    - SupportedBuiltins.Names contains exactly the six predicates and is case-insensitive on lookup.

  <action>
Create `DG/src/DG.Core/Contracts/StatusRollup.cs` in namespace `DG.Core.Contracts` as a
`public static class`. Move the precedence array out of `EvidenceEnvelopeFactory` into it as
`public static readonly IReadOnlyList&lt;EvidenceStatus&gt; Precedence`, preserving the shipped order
exactly: Error, Failed, Indeterminate, Unsupported, Unknown, NotEvaluated, NoPopulation, Passed.
Carry over the existing doc-comment's operative constraint — it is an explicit ordered list walked
front-to-back, never an ordinal max/min and never boolean arithmetic — and add a cross-reference to
`data-service/evidence_contract.py` and `spec/EVIDENCE-CONTRACT.md`, which is where the order is
normatively owned.

Add `public static EvidenceStatus Rollup(IEnumerable&lt;EvidenceStatus&gt; statuses)`: materialize into a
`HashSet&lt;EvidenceStatus&gt;`, return `EvidenceStatus.NotEvaluated` when empty (matching the existing
`RollupStatus` zero-row default), then walk `Precedence` and return the first member present. Keep
the existing unreachable-tier `InvalidOperationException` guard with its message intact.

Rewrite `EvidenceEnvelopeFactory` so it no longer declares its own array: delete the private
`RollupPrecedence` field and have the private `RollupStatus` delegate to
`StatusRollup.Rollup(rows.Select(r =&gt; r.CanonicalStatus))`. `Build`'s public signature and every
other behavior stay byte-for-byte the same — this is a pure extraction, per D-05 additive-not-
replacing. Do not change the zero-row default, do not change row sorting, do not change
`ToLegacyBoolean`.

Create `DG/src/DG.Core/Validation/SupportedBuiltins.cs` in namespace `DG.Core.Validation`, a
`public static class` holding the D-15 allow-list: a
`public static readonly IReadOnlySet&lt;string&gt; Names` built from a `HashSet&lt;string&gt;` with
`StringComparer.OrdinalIgnoreCase`, containing the six predicates in their canonical spelling —
swrlb:lessThan, swrlb:greaterThan, swrlb:lessThanOrEqual, swrlb:greaterThanOrEqual, swrlb:equal,
swrlb:notEqual. Add `public static bool IsSupported(string? predicateIri)` returning false for null
or whitespace and otherwise `Names.Contains(predicateIri.Trim())`. Add a second member
`public static readonly IReadOnlySet&lt;string&gt; NonNumericCapableNames` holding just swrlb:equal and
swrlb:notEqual — those are the only two `RuleEvaluator.EvaluateBuiltin` can evaluate when the
arguments do not convert to decimal (`RuleEvaluator.cs:136-137`); the other four are numeric-only.
Document in the class doc-comment that `spec/SWRL-SUBSET.md` (created in plan 04) is the prose
counterpart and that the two are bound together by a conformance test, so changing one without the
other fails the build.

`IReadOnlySet&lt;T&gt;` exists since .NET 5 and is net7.0-safe. Do not use collection-expression or
frozen-collection APIs.

    - That same result's FailingBindings is empty — the unsupported binding is NOT counted as a
      violation (this is the specific defect D-07 names).
    - That same result's Passed is false (canonical→boolean is lossy and defined; Unsupported maps
      to false per EVIDENCE-CONTRACT section 5).
    - EvaluateRule for a rule whose body violates swrlb:greaterThan over a real binding still
      returns Status = Failed and Passed = false, with the violating binding in FailingBindings.
    - EvaluateRule for a satisfied rule over a real binding still returns Status = Passed and
      Passed = true.
    - A builtin called with fewer than 2 arguments returns Status = Unsupported (malformed arity is
      outside the implemented subset), not Failed.
    - A rule mixing one unsupported-builtin binding and one genuinely-violating binding rolls up to
      Failed, per the shipped precedence — and the message names both situations.
  </behavior>
  <action>
Add to `RuleEvaluationResult` a single additive property:
`public DG.Core.Contracts.EvidenceStatus Status { get; init; }`. Document it as the **authoritative**
outcome and document the existing `bool Passed` as **retained and non-authoritative**, citing
`spec/EVIDENCE-CONTRACT.md` section 5 and Phase 1200 D-03/D-04: the canonical→boolean direction is
lossy and defined, the boolean→canonical direction is forbidden. Do not remove `Passed`, do not
change its type, do not change its existing computation in this task.

In `RuleEvaluator`, introduce a private per-binding outcome representation so each binding yields a
typed status rather than a bool-or-throw. The minimal shape: a private readonly record struct
`BindingOutcome(EvidenceStatus Status, string? Detail)` inside `RuleEvaluator`, and change
`EvaluateBody`/`EvaluateAtom`/`EvaluateBuiltin` to return it instead of `bool`.

Semantics to preserve exactly while doing so: today `EvaluateBody` returning **true** means the rule
body matched, which — because these are violation-pattern rules (CLAUDE.md § Graph Schema v4: "body
atoms fire when constraint is violated") — means the binding is a **violation**. Keep that inversion.
A body that fully matches yields `Failed` for that binding; a body that does not match yields
`Passed` for that binding. Do not "fix" the inversion here; it is the established rule semantics and
changing it is out of scope.

In `EvaluateBuiltin`, replace both `throw new NotSupportedException(...)` sites (`:130` and `:138`)
with a returned `Unsupported` outcome whose Detail follows the `ErrorMessageTemplates`
What+Where+How-to-fix wording: what happened (the predicate is outside the implemented subset),
where (the builtin atom and its predicate IRI), and how to fix (either express the rule with one of
the supported comparison builtins, or accept the typed non-verdict). Gate the numeric branch on
`SupportedBuiltins.IsSupported(predicate)` first, so an unrecognized predicate short-circuits to
`Unsupported` before any decimal conversion is attempted; keep the existing six-way switch for the
recognized ones. When the predicate is recognized but the arguments do not convert to decimal, fall
through to the non-numeric branch only for the two members of
`SupportedBuiltins.NonNumericCapableNames`, and return `Unsupported` otherwise — preserving today's
behavior at `:138` but as a status rather than a throw. Replace the arity throw at `:114` with an
`Unsupported` outcome as well.

In `EvaluateRule`, collect per-binding outcomes into a list. Derive the rule-level `Status` by
calling `StatusRollup.Rollup` over those per-binding statuses — **do not write a second precedence**.
Keep `failingBindings` populated only from bindings whose outcome is `Failed`; an `Unsupported`
binding must never land in `FailingBindings`. Set the legacy `Passed` to
`EvidenceEnvelopeFactory.ToLegacyBoolean(status)` so the two surfaces cannot disagree.

Leave the `catch (Exception ex)` at `:52-56` in place for now but change its body: an outcome of
`EvidenceStatus.Error` (genuine unexpected fault) rather than a silent `failingBindings.Add`.
Plan 02 narrows what can still reach it. Record its detail in the message.

Compose the `Message` from the rolled-up status so the existing string-reading callers still get a
human-readable line: for `Failed` keep the existing "Rule violated by N binding(s)." wording, for
`Unsupported` state which construct was unsupported, for `Passed` keep "Rule passed for all
bindings."

Extend the existing `DG/tests/DG.Tests/RuleEvaluatorTests.cs` with one xunit `[Fact]` per bullet in
the behavior block. Do not create a second evaluator test file.
