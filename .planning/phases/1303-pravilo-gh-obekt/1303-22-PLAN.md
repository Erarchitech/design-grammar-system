<objective>
D-62 (requirement DGOPN-06): every participant class of a rule reaches the property calculator of the rule's measured property, so the calculator is bound to the model elements mapped to those classes.

Purpose: today a calculator's classes are derived bottom-up from the Revit categories its script reads (`context_classes`), `resolve()` raises `BOX_CLASS_AMBIGUOUS` for any request that spans two ClassAtom classes, and `ensure_rule_classes` silently skips rules with more than one class. One multi-participant rule would stop script generation for the whole project. Live example (`str-openings-01`): the generated calculator of `hasMinProjectionClearanceMm` reads Wall, Column and Beam; the rule speaks of columns and walls projected onto a slab.

Runs after 1303-17, which changes `resolve` (shared/blocked, warnings), the `generate`/`ensure_rule_classes` call order and the `_Session` fake; build on those signatures.
</objective>
