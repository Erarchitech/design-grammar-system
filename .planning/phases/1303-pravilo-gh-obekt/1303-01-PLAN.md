- `check_constraint(c, value) -> bool` with tolerance 1e-9 for `==`/`!=`.

Evidence functions, each returning a list of `Evidence(class_local, kind, weight, detail)` (frozen dataclass, `kind` ∈ profile|name|rule|ifc|population) and, for rules, conflict records:
1. `ev_profiles(feats, profiles)`: an active profile matches when every selector key equals the feature value (string compare case-insensitive; numbers compared exactly after int/float normalisation) and, when `profile.platform != "*"`, the platform matches. Each role gets `+w_profile * confidence`; each `excludedRoles` entry gets `-w_profile * confidence`.
2. `ev_name(feats, classes)`: tokens from `source`, `family`, `type`, `name`, `category` (split like class labels). Per class: exact acronym match of a whole source/family/type token → `w_name_acronym`; subsequence acronym (letters of the token appear in order among the class acronym and start with its first letter, e.g. `gu` for `gfu`) → `w_name_subsequence`; each shared word token (length ≥ 3) → `w_name_token`; cap per class `w_name_cap`. Detail text names the matched token.
3. `ev_rules(feats, constraints)`: for each class with constraints whose property value is present: satisfied → `+w_rule_satisfied` each (cap `w_rule_cap` per class); violated → `w_rule_violated` each and a conflict `{ruleId, classLocal, detail}`; not measured → nothing.
4. `ev_ifc(feats, classes)`: `ClassInfo.ifc_hints` entries like `IfcPlate` or `IfcPlate.CURTAIN_PANEL`; match on entity (and predefined type when the hint has one) → `w_ifc`.
5. `ev_population(group_size, populations)`: when `populations` (class_local → count) is given and exactly one class has `count == group_size` → `w_population` for that class (group level).

`ClassInfo(iri, label, synonyms=(), ifc_hints=())` frozen dataclass; synonyms are extra tokens for `ev_name`. Classes with no evidence never become candidates.

<task type="auto">
  <name>Task 2: Aggregation, grouping, questions, decisions, profiles and evaluation</name>
  <files>data-service/mapping_engine.py</files>
  <action>
Add to `mapping_engine.py`:

`compute(descriptors, classes, constraints, profiles=(), disjoint=(), populations=None, platform_default="grasshopper", config=None) -> dict`:
1. Validate: list of dicts, unique `nativeId`, `len <= max_elements`; otherwise raise `MappingInputError(code, detail)` with codes `MAPPING_INPUT_INVALID` / `MAPPING_TOO_MANY_ELEMENTS`.
2. Sort descriptors by nativeId. For each element compute features and per-class score = `prior + Σ weights` (profiles, name, rules, ifc); confidence = logistic(score) rounded to 4 decimals. Candidates = classes with confidence ≥ `tau_candidate`, sorted by (−confidence, class label).
3. Disjointness: `disjoint` is a list of (classLocalA, classLocalB); if two candidates are disjoint, keep both as candidates but mark the element `blocked_by_disjoint` (forces a disambiguate question; the both option is not offered for that pair).
4. Element state, evaluated in this order:
   - **Profile precedence:** if the element matches ≥ 1 profile with confidence ≥ `profile_auto`, its roles are the union of those profiles' `roles` minus every matching `excludedRoles`; state `auto` unless one of those roles has a blocking conflict (then `ambiguous`). Other candidates are still listed but do not create ambiguity.
   - **Blocking conflict (D-25):** a role class has a violated constraint **and** some other candidate class is rule-consistent for the element (≥ 1 satisfied and 0 violated constraints). A violation without such an alternative is attached as a `designSignals` entry and does not change the state. Profiles with `acceptsViolations` containing the rule id never produce a blocking conflict for that rule.
   - Without an auto profile: `suggested` when the top candidate has confidence ≥ `tau_clear`, no blocking conflict, and either it is the only candidate or the margin to the second is ≥ `margin_delta`; `ambiguous` when ≥ 2 candidates are within `margin_delta`, when the top two are disjoint, when the top candidate has a blocking conflict, or when the only candidate is below `tau_clear` (this last case gets an `assign` question); `unmapped` when there is no candidate.
5. Groups: signature = the element's `SELECTOR_FEATURES` values that are present + sorted candidate class locals (top two) + state class (clear / ambiguous / auto / unmapped). `groupId = "G-" + sha1(canonical signature json)[:8]`. Group candidates aggregate member evidence (mean confidence; evidence de-duplicated by detail with counts). `ruleImpact` per candidate class: for each rule of that class count satisfied / violated / notMeasured over members. Population evidence (`ev_population`) is applied at group level when `populations` is given, then the group state is recomputed.
6. Questions (D-15, D-26): one `batch-assign` question over all groups in state `suggested` (options `accept-all`, `none`); one question per group in state `ambiguous`: type `mapping-or-design` when a blocking conflict exists (options `class:<alt>`, `design-error:<conflicting class>`, `both` unless disjoint, `none`), else `disambiguate` (options `class:<each candidate>`, `both` unless disjoint, `split:<feature>` when a feature in `SELECTOR_FEATURES` or `properties.*` takes ≥ 2 values inside the group — choose the one with the highest information gain over the members' top candidate, ties by name, `none`). `questionId = "Q-" + sha1(type + sorted groupIds)[:8]`. Every question carries `consequences` built from `ruleImpact` (effect `passes`, `violated`, `applies`, with counts) and deterministic `text` (English) and `textRu` (Russian) built from templates, e.g. EN "25 elements from HU (5 vertices). As HexagonalUnit: R_HEX_HASVERTEXCOUNT_REQ_6_V violated ×25. As GroundFloorUnit: R_GF_HASVERTEXCOUNT_REQ_5_V passes ×25. Mapping error or design error?" and RU "25 элементов из HU (5 вершин). Как HexagonalUnit: R_HEX_HASVERTEXCOUNT_REQ_6_V нарушено ×25. Как GroundFloorUnit: R_GF_HASVERTEXCOUNT_REQ_5_V выполняется ×25. Это ошибка меппинга или ошибка проекта?". Groups ordered by `priority = uncertainty × log(1 + size) × (1 + rules affected)` with uncertainty = 1 − margin (ambiguous) or 1 − top confidence (suggested), ties by groupId; questions ordered by their highest group priority.
7. Return the MappingSession body of 1303-API-CONTRACT §3 without `sessionId`, `createdAt`, `createdBy`, `label`, `project` (the store adds them): `{engineVersion, platform, summary, questions, groups, elements}`. Round all floats to 4 decimals.

`decide(result, descriptors, question_id, option_id, actor, at, group_ids=None, roles=None, profiles=())` → `(decisions, new_or_updated_profiles)`:
- Resolve the question (else `MappingInputError("MAPPING_QUESTION_NOT_FOUND")`) and option (else `MAPPING_OPTION_INVALID`).
- `accept-all`: one decision per included group (`group_ids` subset or all), roles = that group's top candidate.
- `class:<c>` → roles [c]; `design-error:<c>` → roles [c] and the induced profile gets `acceptsViolations` = rule ids violated by that group's members for class c; `both` → the two top candidates; `none` → roles [] and the induced profile gets `excludedRoles` = the group's candidates; `split:<feature>` → no decision; returns `([], [])` and the caller recomputes with the split applied (store the split request in the result as `splits: [{groupId, feature}]`; `compute` honours a `splits` argument by adding the feature to the signature of those members).
- Each decision follows 1303-API-CONTRACT §4: `decisionId = "D-" + sha1(questionId + groupId + optionId + at)[:12]`, `questionText`, `evidenceShown`, `consequencesShown`, `memberCount`.
- Profile induction `induce_profile(group_members_features, other_groups_features, roles, platform, project=None)`: start from the selector features constant across the group; greedily drop keys in this order: `type`, `family`, `geometry.closed`, `geometry.kind`, `category`, `source` — a key is dropped only if the reduced selector still matches no element of another group whose top candidate set differs; keep `platform` unless the remaining selector uses only `geometry.*`/`properties.*` keys; never include nativeId or coordinates. `profileId = "P-" + sha1(platform + canonical selector + sorted roles)[:12]`; an existing profile with the same id gets `confirmations + 1`. `confidence = (c + profile_alpha) / (c + r + profile_alpha + profile_beta)`.

`evaluate_against_gold(elements, gold) -> dict`: per class precision / recall / support and overall, counting only roles in states `confirmed` or `auto`.

`canonical_json(obj) -> str`: `json.dumps(obj, sort_keys=True, ensure_ascii=False, separators=(",", ":"))`.
