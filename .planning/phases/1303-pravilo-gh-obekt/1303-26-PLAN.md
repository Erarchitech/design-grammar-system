<objective>
Stage 2 of the multi-user demo test findings (F-06, D-78): a confirmed mapping becomes a model snapshot with a mapping view in the Model Viewer, so that the owner can check by eye that every element got the right class (D-79…D-84 in 1303-CONTEXT.md, requirement DGOPN-07).

Facts verified while planning (2026-10-30):
- The Model Viewer loads only a run's validation version (`ModelScreen.sceneResourceUrls`); that version holds the checked boxes (`dgEntityId`) and neutral `dgContext` nodes without UniqueId or class, so it cannot show a whole mapping. A separate Speckle version is needed.
- Mapping apply: `mapping_store.apply_session` queues an immutable batch; the connector (`runner._apply`) writes `DG_Class` / `DG_MappingState` through a `parameters` job and acknowledges with `{state, written, skipped}` → `mapping_store.acknowledge_batch` (route `POST /mapping/sessions/{session_id}/apply`, app.py ~6984). The session's elements carry `nativeId` (UniqueId), `roles[{classIri,label}]`, `state`; Revit descriptors carry `category` (`descriptors.py`).
- Connector jobs (D-73): `connector_jobs.submit/take/complete/add_context/wait`, chunked answers via `post_job_context` (`check_jobs.CONTEXT_CHUNK = 150`), routes `/connector/jobs/next|{id}/result|{id}/context`. The connector has no mesh code of its own: meshes come from the generated program (`revit_shell.py.tmpl`: `element_mesh`, `solid_mesh`, `box_mesh`, `bbox_corners`), executed by `check_jobs.execute_program` as `run(doc, family_filter, with_context)`.
- Revit checks: `_run_revit_check` (app.py ~2398) → dg-evaluator → `_publish_revit_runs` (one ValidationRun per rule) → background `_publish_revit_context`. dg-evaluator computes the StateId from the boxes and their values (`DG.Core.Validation.CheckEvaluation`), so a check's own state never equals a mapping snapshot: attaching is a separate link.
- Run grouping: `_state_summary` (app.py ~1015) projects statePayloadJson; `runGroups.groupRunsByState` groups by `r.state.stateId`.
- Viewer: `@speckle/viewer` 2.31 exports `ViewModes` / `ViewMode` with `EdgesPipeline` options `outlineColor` / `outlineThickness`; the overlay uses `FilteringExtension.setUserObjectColors` + `renderer.setMaterial` (`SpeckleViewport.jsx` ~409-522). Their combination with edges is unverified.
- D-50 palette: connector `palette.STATE_COLOURS` = UI `--mapping-*` tokens (MappingPanel.jsx ~134-150).
- Precedent for a standalone, Run-less DesignState: `POST /computgraph/candidates/accept` (spec/DATABASE.md).
- Russian «Состояния дизайна»: `ui-v2/src/i18n/dict/model.js`, `landing.js`, `screens.js`; demo pages `docs/demo/dg-demo-ru.html` (1), `dg-demo-facade-ru.html` (5).
