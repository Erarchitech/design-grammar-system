Facts verified while planning (2026-10-30):
- Decisions are group decisions: `mapping_engine.decide` assigns the chosen roles to every member of the question's groups and induces a learned profile over the group's features (`induce_profile`). There is no element-level answer yet; `compute(decided=...)` already honours a per-element `decided[nativeId]` (state confirmed, source human) inside one session.
- Profiles match by `profile_matches(profile, features)`; `features()` carries no `nativeId`, so a selector `{"nativeId": ...}` never matches today and needs an explicit branch in `compute`.
- Commit: `mapping_store.apply_session` requires every pending answer id and the session revision, builds the batch from `_batch_subset` (only members with a non-empty `decided` entry), activates `answer.draftProfiles` of accepted decisions, and `answers_of` marks an answer accepted when one of its items has a `proposal`.
- The connector polls only the session it created (`runner.poll_step`, `store.sessionId`) and delivers queued batches while the session has no `appliedAt`; `revit_io.write_parameters` writes `DG_Class` as the labels joined by `;`, empty when there are none.
- Route policy: `/mapping/sessions/{id}/decisions` and `/undo` are editor routes for members and delegated principals; the UI knows the member's role from `/auth/me` memberships.
- The snapshot node carries `mappingSessionId`; `GET /validation/snapshot/{project}/{state_id}` answers its elements with classIris/labels and state.

- Only editors of the project change classes: the override route carries the same principals, role and project binding as the decisions route; viewers see the dropdown read-only and the server refuses them anyway.
- An override for an element outside the session, or a class outside the project's OntoGraph, is refused (404 / MAPPING_INPUT_INVALID), so a crafted request cannot write arbitrary DG_Class text through the connector.
- A stale view cannot overwrite newer drafts: the commit keeps the revision check and the full pending set (409 refreshes the view).
- An exception is keyed by UniqueId within one project; it cannot reach another project's elements (profiles are project-scoped).
</threat_model>
