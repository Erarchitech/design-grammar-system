  <action>
Add the report assembly layer to `data-service/cg_structure_checks.py`.

`list_definition_ids(session, project) -> list[str]` runs one parameterized read returning the distinct `definitionId` values on Computgraph-scoped nodes for the project, ordered ascending, tagged `// op=CHECK_DEFINITION_IDS`.

`DefinitionResolutionError(Exception)` carries a `code` attribute and an `available` list. It is raised only by the resolver below and is caught by the route, which maps `code` onto the documented error code without re-deriving it.

`resolve_definition_id(session, project, definition_id=None) -> str` returns the supplied id unchanged when one was given. When none was given it lists the project's definitions: exactly one means return it; zero means raise with the no-definition code and an empty available list; more than one means raise with the ambiguous-definition code and the sorted available list, so the route can put them in the error hint. This keeps the report single-shaped rather than branching between a per-definition and an aggregate form.

`fetch_published_at(session, project, definition_id) -> str | None` runs one parameterized read returning the maximum `publishedAt` across the Computgraph nodes for that project and definition, tagged `// op=CHECK_PUBLISHED_AT`, returning None when nothing is published. This is the staleness signal the phase context requires the report to carry.

`build_validation_report(session, project, definition_id=None) -> dict` resolves the definition, fetches `publishedAt`, runs the structural checks, evaluates the rule mappings, and assembles the report with exactly the keys `spec/API.md` documents: `project`, `definitionId`, `publishedAt`, `checkedAt`, `findings`, `ruleResults`, `counts`. `checkedAt` is the current UTC time in the same ISO 8601 format the publish path emits. `counts` is an object with `violation`, `warning` and `info` integer keys derived from the findings' severities; a severity with no findings is present with a zero value, never omitted, so a consumer can index it unconditionally.

Give the function a docstring stating the determinism guarantee precisely: for an unchanged graph, `findings` and `ruleResults` are byte-identical across calls, and `checkedAt` is the only field permitted to differ. Also state that the whole path performs reads only and consults no model. Do not name any gateway module or adapter method in this file, including comments and docstrings - the SC4 gate greps for both identifiers.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client -> route | `project` and `definitionId` arrive untrusted and are forwarded into every scoped read |
| route -> error body | An error hint that echoes internal detail could disclose other projects' definition ids |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37-01 | Tampering | Cypher injection via the validate request body | high | mitigate | The route performs no Cypher of its own; it hands both fields to the checks module, whose queries bind them as parameters. Task 1 and Task 3 acceptance re-run the interpolation grep over the module |
| T-37-03 | Information Disclosure | The ambiguous-definition hint listing definitions from other projects | high | mitigate | `list_definition_ids` binds `project`, so the hint can only ever contain the caller's own project's ids; Task 3's integration tier asserts the hint contains exactly the three fixture-project ids and nothing else |
| T-37-09 | Spoofing | The validate path consulting a model, making the report non-reproducible | high | mitigate | SC4 is pinned twice: as a shell gate in Task 1 and Task 3 acceptance, and as a test assertion inside the suite so it survives a refactor |
| T-37-11 | Denial of Service | A project with a very large published definition producing an unbounded report | low | accept | Reports are bounded by the published entity count, which is bounded by what a Grasshopper canvas can hold; no pagination is added at MVP. Revisit if a definition ever exceeds a few thousand entities |
| T-37-SC | Tampering | npm/pip/cargo installs | low | accept | Zero new packages (37-RESEARCH.md Package Legitimacy Audit: not applicable). No install task exists in this plan |
