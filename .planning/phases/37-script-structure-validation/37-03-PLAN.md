Create `data-service/cg_structure_checks.py`.

Module docstring: state that this module performs deterministic, reproducible structural checks over the published Computgraph; that every query is parameterized and scoped by both `project` and `definitionId`; that the caller owns the Neo4j session; and that no model or provider is ever consulted from this module - findings are pure graph facts. Do not name any gateway module or adapter method anywhere in this file, including comments and docstrings: the SC4 gate greps this file for those two identifiers and requires zero matches.

Imports: `from __future__ import annotations`, `json`, `from typing import Any`. Nothing else at module scope.

Severity constants `SEVERITY_VIOLATION = "violation"`, `SEVERITY_WARNING = "warning"`, `SEVERITY_INFO = "info"` - the vocabulary is fixed by `spec/RULE-PARTITION-POLICY.md`, do not add a fourth level. `CHECK_IDS` is a tuple of the seven checkId strings in the order `run_structural_checks` emits them.

`convention_name_from_cg_id(cg_id)` returns the last colon-separated segment of a cgId, or an empty string for a falsy input. This is how the convention token (for example the parameter token ending in `HTotal`) is recovered - the published display-name properties carry only the bare name, never the convention token, so this derivation is the only way a finding can reference an entity the way an architect labelled it on canvas.

`_entity(label, cg_id, name)` returns the normative entity dict with keys `label`, `cgId`, `name`, `conventionName`, the last derived from the cgId.

`_finding(check_id, severity, what, where, how_to_fix, entities)` returns the normative finding dict with keys `checkId`, `severity`, `message`, `entities`. It composes `message` by joining the three parts with the same `What. Where: ... How to fix: ...` structure the existing Cypher-validation violations use. Every check calls this - no check builds a message string inline.

Then implement five session-injected check functions, each with the signature `(session: Any, project: str, definition_id: str) -> list[dict]`, each running exactly one `session.run(QUERY, {"project": project, "definitionId": definition_id})` call with the parameters bound as a dict, each Cypher literal ending in its own trailing `// op=` tag, and each returning findings sorted by cgId so repeated calls compare equal:

- `check_orphan_patterns` - match Pattern nodes scoped to project and definitionId that no relationship of the pattern-ownership type points at; severity violation; how-to-fix tells the architect to re-tag the Pattern under a Procedure group and re-publish.
- `check_procedures_without_interface` - match Procedure nodes scoped to project and definitionId with no outgoing interface relationship; severity violation; how-to-fix tells the architect to tag at least one interface group under the Procedure and re-publish. The finding must carry both the cgId and the `procedureName`, because SC1 requires the exact procedure to be nameable from the report.
- `check_dangling_param_links` - match a Parameter linked to an Interface where the Procedure owning the Parameter is not the Procedure owning the Interface; scope every matched node by project and definitionId; severity violation; the finding carries both the Parameter and the Interface as entities; how-to-fix tells the architect that the wire crosses a Procedure boundary and to either move the component into the owning Procedure group or remove the link.
- `check_algorithms_without_procedure` - match Algorithm nodes scoped to project and definitionId with no outgoing procedure relationship; severity violation. Algorithm nodes have no cgId, so the entity dict uses the `algIndex` rendered into the `name` field and an empty cgId; state this in a comment so a reader does not assume the field was forgotten.
- `check_parameters_without_datatype` - match Parameter nodes scoped to project and definitionId whose `dataType` property is null or an empty string; severity violation. Add a short comment noting this condition is currently unreachable through the publish path, which rejects an unrecognised dataType before any write, and that the check is retained deliberately as a guard against a future publish-path change or a graph mutated outside that path.
- `check_objects_without_behavior` - match Object nodes scoped to project and definitionId with no outgoing behavior relationship; severity violation; same deliberate-guard comment.

That is six functions - the five graph-shape checks plus the two defensive ones make six; implement all six here. The seventh (annotation conventions) is Task 2.

Every Cypher literal must be a plain triple-quoted string with the parameters referenced as bound `$project` / `$definitionId` placeholders. Never build a query with an f-string, `.format`, or percent interpolation - the cross-project-leakage and injection mitigations both depend on this.

Add the seventh check plus the aggregator to `data-service/cg_structure_checks.py`.

`parse_context_warnings(context_json)` is a pure function taking the raw `contextJson` string property and returning a list of warning strings. It must tolerate every degenerate input without raising: a null or empty string returns an empty list; a string that is not valid JSON returns an empty list; a JSON document that is not an object returns an empty list; an object whose `warnings` key is absent or is not a list returns an empty list; a list containing non-string members yields only the string members, order preserved. This function is the unit-testable core and must have no Neo4j dependency at all.

`check_annotation_conventions(session, project, definition_id)` runs one query returning `algIndex`, `algorithmName` and `contextJson` for every Algorithm scoped by project and definitionId, ordered by algIndex, with a trailing `// op=CHECK_ALGORITHM_CONTEXT_JSON` tag. For each row it calls `parse_context_warnings` on the `contextJson` value and emits one finding per warning string at severity info, with the warning text as the What part, the algorithm identified in the Where part, and a how-to-fix telling the architect to correct the annotation tag on canvas and re-publish if the normalization was not intended. Findings are sorted by algIndex then warning text.

Add a comment above this function stating plainly why it reads a JSON property instead of matching a graph pattern: the tolerated-variant normalization is resolved during canvas parsing, before the envelope is confirmed, so only the parsed kind enum reaches the published Parameter node. A Cypher pattern looking for the raw tag string would never fire against any real data. Phrase the comment without quoting a raw tag literal.

`run_structural_checks(session, project, definition_id) -> list[dict]` calls all seven checks in the order given by `CHECK_IDS`, concatenates their findings, and returns them sorted by the tuple of checkId, then the first entity's cgId, then the message. That final sort is what makes the determinism guarantee hold: two calls against an unchanged graph must produce byte-identical lists. Add a docstring stating that guarantee explicitly, and stating that this function performs reads only and writes nothing.
  </action>
