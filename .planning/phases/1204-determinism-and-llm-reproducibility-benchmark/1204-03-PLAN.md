<objective>
D-21 sample-indexed cassette key: add an optional `sample_index: int = 0` keyword parameter to `cassette_key` that, at 0, yields a byte-identical digest to today's eight-part sha256 (the ninth part is not appended), and at ≥1 appends a ninth pipe-joined part so k samples of one request get distinct cassettes; thread `sample_index` through `CassetteAdapter` (constructor-time, default 0) and prove the whole thing with flip-test rows, a distinct-key test, guard tests and a backward-compat byte-identity test in `TestCassette`.

Purpose: today `cassette_key` (cassette.py:69-99) hashes only the eight identity inputs, so k samples of the same request — the ALGN12-15 "LLM sampling" arm that records k=10 draws per item — would collide on one cassette filename and silently overwrite/replay one another (Correction 7). This plan ships the sample-index dimension on the existing cassette key, verified in isolation, so the later sampling sweep (record mode over k samples) has a key that distinguishes them while the committed Phase-35 cassettes keep resolving unchanged.

Output: extended `cassette_key` and `CassetteAdapter.__init__` in `data-service/tests/recognition_eval/cassette.py`, plus new `TestCassette` methods in `data-service/tests/test_recognition_eval.py`.
</objective>
