<objective>
Converge ObjState ID minting on `DesignStateIdGenerator` (D-04), resolving RESEARCH.md Pitfall 1's
signature mismatch with an explicit decision rather than a call-site swap.

Purpose: CONTEXT.md's Correction 1 establishes that the documented generator
(`ComputeObjectStateId`, hashing `projectId|objectInstanceId|variableName`) has **zero production
call sites**, while the ObjState ID that actually ships is minted by a private duplicate in
`ObjectStateComponent.cs:190-196` hashing `objectRef|label`. The live ID therefore includes Label
and omits project and variableName — the opposite of the documented contract on both counts, and
`DesignStateCompositionComponent.cs:156` folds those member ids into the aggregate, so DesignState
identity transitively inherits Label-sensitivity. A phase whose stated goal is a canonical identity
contract cannot ship two disagreeing minting paths.
Output: one minting function, the duplicate deleted, and a rebuilt plugin.

**Pitfall 1 resolution (the plan-time decision RESEARCH.md demands):** take option (b) from
RESEARCH.md — add an **additive overload** rather than force-fitting the existing 3-arg signature.
`ObjectStateComponent` has no `Project` input port (verified: its three ports are Object, Geometry,
Label) and no per-geometry-instance `variableName` concept; synthesizing fake values for either
would satisfy D-04 in name while destroying the semantic meaning the existing doc-comment promises.
The existing `ComputeObjectStateId(projectId, objectInstanceId, variableName)` stays untouched for
its documented per-rule-variable purpose. The new overload takes what the component actually has.
</objective>
