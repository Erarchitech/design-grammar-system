# Phase 1202 Plan 02: Canonical DesignState Projection, Hash, and Two-Layer Identity Summary

**Built a byte-identical C#/Python canonical DesignState projection extending Phase 1200's CanonicalJsonWriter/canonical_json hasher, proved cross-language parity with a shared 64-char hex vector (catching and fixing a real double-to-decimal scale divergence along the way), added an additive capture-event StateId overload declaring DesignState's two-layer identity, and populated the plan-01 replay fixture's canonical state hash.**

## Accomplishments

- `DesignStateCanonicalProjection` (C#): `Build(DesignState) -> JsonObject` and `ComputeHash(DesignState) -> string`, the latter a thin wrapper over `CanonicalJsonWriter.HashCanonical`. Geometry excluded by construction (verified: zero non-doc-comment lines reference `.Geometry`); StateId-sorted throughout (`StringComparer.Ordinal`); a `members` manifest listing every ObjState/ParamState/PropState as `{kind, stateId}`; NaN/Infinity numeric values throw `InvalidOperationException` naming the parameter rather than silently coercing.
- `DesignStateCanonicalProjectionTests.cs`: 11 Facts (exceeds the plan's 8-minimum) covering order-independence, geometry-exclusion equivalence, ClassIri/Label sensitivity, null-vs-absent representation, the members manifest shape, decimal conversion, and the NaN/Infinity fail-closed path. The shared vector constant was generated by building a scratch console harness referencing the compiled `DG.Core.dll` (the full `DG.Tests` assembly cannot compile yet — see Deviations) and running `ComputeHash` against a fixed `DesignState`, not guessed.
- `design_state_projection.py`: `build_projection(dict) -> dict` and `compute_state_hash(dict) -> str`, mirroring the C# key set and sorts exactly, calling `canonical_json.hash_canonical` exclusively. `test_design_state_projection.py`: 12 tests, including the cross-language parity assertion against the identical hard-coded hex constant the C# suite asserts.
- **Real cross-language bug found and fixed during parity proving**: a naive `Decimal(str(42.0))` in Python renders as `"42.0"` (scale 1), but C#'s `Convert.ToDecimal(42.0)` normalizes to scale 0 (`"42"`) per IEEE-754 shortest-round-trip semantics. Switched to `Decimal(repr(value)).normalize()`, verified against `42.0, 42.5, 0.1, 100.00, 2.50, 0.0, -0.0` to reproduce the C# leg's output exactly. Without this fix the shared vector hash would have silently diverged.
- `fixtures/golden/replay/mixed-verdicts.json`'s `expectedCanonicalStateHash` populated (`3D2D5EDF750FEA213CFB564E424C61F029220F2BF93B0B227EE6FEEC4F55A428`) plus a new `canonicalizationVersion: 1` key; `README.md` updated with a change-log entry and an explicit note on a known, deliberately-out-of-scope parity gap (see Decisions).
- `DesignStateIdGenerator.ComputeCaptureEventStateId(IEnumerable<string>, DateTimeOffset)` added additively; the class-level XML doc-comment rewritten to state the D-01 two-layer identity contract (capture-event node key vs. queryable-not-identity-bearing content hash) and the MERGE-no-longer-dedupes-a-recapture consequence. `ComputeDesignStateId`/`HashToHex16` verified byte-identical via `git diff` (zero removed lines touch either symbol). 7 new Facts added (20 total, up from 13), including a regression pin for `ComputeDesignStateId`'s fixed-vector output.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Python decimal conversion from double did not reproduce C#'s Convert.ToDecimal scale**
- **Found during:** Task 2 (cross-language parity proving)
- **Issue:** `Decimal(str(42.0))` yields scale-1 `"42.0"`; `Convert.ToDecimal(42.0)` in C# yields scale-0 `"42"`. Left unfixed, the shared vector hash would have silently diverged between the two languages the first time a whole-number float parameter value was hashed.
- **Fix:** Changed `design_state_projection.py`'s number-parameter conversion to `Decimal(repr(value)).normalize()`, verified against 7 representative values (whole numbers, fractions, trailing-zero decimals, positive/negative zero) to reproduce the C# leg exactly.
- **Files modified:** `data-service/design_state_projection.py`
- **Verification:** `test_compute_state_hash_matches_shared_cross_language_vector` passes with the identical literal asserted in the C# suite.
- **Committed in:** `7d1b118` (Task 2 commit)

**2. [Rule 3 - Blocking] `DG.Tests` assembly cannot compile — worked around, not fixed**
- **Found during:** Task 1 (attempting to run the vector test the normal way)
