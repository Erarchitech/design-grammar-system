<objective>
Close ALGN12-11 (snapshot/run-status separation) and reconcile the Python rollup to the shipped
precedence (D-12), then propagate both into the spec surfaces `CLAUDE.md` § Schema Change
Propagation names.

Purpose: `data-service/app.py:573-588` MERGEs a `:ValidationRun` and unconditionally SETs immutable
content (`rulesJson`, `statePayloadJson`, `createdAt`) alongside mutable status (`status`,
`ValidStatus`, `SendStatus`) onto one node. Because the MERGE key is `(graph, project, runId)`,
re-publishing the same runId silently overwrites the snapshot. And `get_validation_entity_sets`
at :846-870 uses failed-wins dedup, under which `error` loses to `failed` — the opposite of the
shipped precedence.
Output: an `ON CREATE SET` / `SET` split, a precedence-based rollup, and the spec declarations.

D-15 note carried forward: this is deliberately the cheapest defensible option. No physical
`:StateSnapshot` / `:Run` node split, no migration. The split remains available to a later phase
and is recorded as deferred.
