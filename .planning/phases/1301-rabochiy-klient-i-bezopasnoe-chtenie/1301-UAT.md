## Gaps

- **G-1 (major, DGCL-02): the agent cannot read the project's rules on a project with validation history.**
  `degram_project_graph` reads `GET /graph/{project}` first; `degram_variant/dg_client.py` refuses any answer over
  `MAX_RESPONSE_BYTES` (8 MiB) before `bounded_graph` can trim it, and the rules read (`GET /rules/{project}`) is never made
  when the graph read fails. Measured 2026-10-06 on `v12-hexagonal-facade-01`: `/graph` answer 8,571,722 bytes, 2,000 nodes
  (the server cap) and 4,151 relationships; `statePayloadJson` alone is 7,420,611 bytes (1,863 `ValidationEntity`, 21
  `ValidationRun`); the project has 11 `Rule` nodes. Twice `RESPONSE_TOO_LARGE`; no `/rules/` request in the data-service log.
  The tool description promises a bounded answer. Fix direction: read rules independently and return them with the graph
  marked missing; bound or exclude the heavy validation payloads on the graph read (client stream cap or a server-side
  projection), so the 2,000-node server cap stops being filled by validation records.
