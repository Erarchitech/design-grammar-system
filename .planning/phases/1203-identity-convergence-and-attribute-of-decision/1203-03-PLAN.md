<objective>
Close CR-01 (label-less anchor MERGE orphaning pre-publish bindings), WR-01 (mint never tags `graph`), and WR-03 (dead `ALLOWED_PROPERTIES` constant), and prove ALGN12-13's already-specified platform policy with tests.

Purpose: `spec/DG-ID.md` declares pre-minting before publish the intended workflow, but `mint_identity`'s anchor MERGE carries no label while the publish writer's MERGE does. The two never coincide, so a pre-publish mint creates an unlabeled orphan and the binding attached to it is lost once the entity is really published. D-10 fixes this by making the mint label-aware rather than by forbidding the workflow the spec endorses. D-12 treats ALGN12-13 as an evidence gap: the policy is already specified, so this plan writes the tests that hold it.

Output: a label-aware, `graph`-tagging `mint_identity`; a mint→bind→publish coincidence regression test; passing conflict/detach/provenance coverage; `ALLOWED_PROPERTIES` deleted.
</objective>

  <action>
Make the mint anchor coincide with the publish anchor.

Add an entity-kind input to the mint path. Per CONTEXT.md's Claude's Discretion grant on whether `/identity/mint` takes an explicit kind argument or resolves one, take the explicit-argument route: resolution would require mint to guess a label from a `cgId` string shape, which is exactly the kind of implicit coupling this milestone exists to remove.

Define a module-level `ENTITY_KINDS` collection in `dg_identity.py` enumerating the Computgraph entity labels that carry `dgId`. Per the project's schema documentation these are `Object`, `Procedure`, `Pattern`, `Parameter`, and `Interface` — confirm this set against `computgraph_publish.py`'s publish writers and `spec/DG-ID.md` before fixing it, and use the confirmed set.

Add `entity_kind` to `MintRequest` with a `field_validator` rejecting any value outside `ENTITY_KINDS`, following the exact validator pattern the existing `BindRepresentationRequest.platform` and `native_id_kind` fields already use. Thread it through the `/identity/mint` route into `mint_identity`.

Change `mint_identity`'s signature to accept the entity kind, and change its anchor MERGE so the matched node carries that label — the label must be applied as a Cypher label, and since Neo4j does not parameterize labels, the kind must be validated against `ENTITY_KINDS` before it reaches the query and then interpolated only from that validated allowlist. This is the one place a label is not parameterizable; make the allowlist check explicit and adjacent to the interpolation, and leave every value (cgId, definitionId, project, dgId) as a bound parameter. Add a comment at the interpolation site recording that the value is allowlist-constrained, so a later reader does not mistake it for unvalidated interpolation.

Add the `graph` tag to the same `SET` clause so a minted node is tagged `Computgraph` exactly as `_publish_parameters` tags the nodes it writes. This closes WR-01.

Update `mint_identity`'s docstring: it currently describes the anchor key as `(cgId, definitionId, project)` with no label. Restate it as a labelled anchor and explain that the label is what makes the mint coincide with publish instead of orphaning.

Update the single production caller in `app.py` and every existing call in `test_dg_identity.py` to pass the kind. The preflight inventory confirms `mint_identity` has exactly one production caller, so this is a contained change.

Write the regression tests described in the behavior block. Verify the anti-misbinding guard is untouched by running the existing binding tests alongside the new ones.
