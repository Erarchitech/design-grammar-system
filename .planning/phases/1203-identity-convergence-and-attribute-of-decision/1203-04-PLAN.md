<objective>
Implement `ATTRIBUTE_OF` as a real, project-scoped, provenance-carrying graph relation from `:Atom` to `:Parameter`, derived at publish time from the `inputBindings` resolution the system already performs in memory.

Purpose: D-01 selects branch A. The TBox already commits to `dgc:attributeOf` with domain `dgm:Atom` and range `dgc:Parameter`, and `PAPER-C-032` records CQ3's demonstration as exactly that shape. `PARAM_LINK` cannot express it — it is `Parameter` to `Interface` and says nothing about rules. The real bridge today is `inputBindings`, a config file resolved in memory and never persisted, which is invisible to Cypher and cannot answer CQ3's reverse direction at all. This plan persists a resolution the system already computes.

Output: `_attribute_of_from_bindings` (pure derivation) and `_publish_attribute_of` (parameterized MERGE) in `computgraph_publish.py`, wired into the publish transaction alongside `_publish_param_links`, with forward and reverse query tests.

**D-04 attachment decision, stated explicitly as the decision requires:** `ATTRIBUTE_OF` attaches to the rule's **`DataPropertyAtom`** — the atom carrying the data property whose value the bound parameters determine. Per `cypher_template.txt`'s atom-numbering convention, a rule's body atoms are `{Rule_Id}_A1` (`ClassAtom`), `{Rule_Id}_A2` (`DataPropertyAtom`), `{Rule_Id}_A3` (`BuiltinAtom`), with `{Rule_Id}_H1` the head. The `A2` position is therefore the `DataPropertyAtom`, matching `PAPER-C-032`'s citation of atom `A2` / `hasDistanceM`. The edge is selected by matching on `type = 'DataPropertyAtom'` rather than on the `_A2` suffix or on `HAS_BODY` order, so the attachment survives a rule whose atom numbering differs while remaining predictable enough for the reverse query.
</objective>
