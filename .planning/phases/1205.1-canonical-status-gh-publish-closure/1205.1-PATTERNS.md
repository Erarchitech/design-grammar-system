## Pattern Assignments

### P1 — Preserve typed outcomes before aggregate; сохранить legacy отдельно

**Основные tracked sources:** `RuleEvaluator.cs`, `RuleEvaluationResult.cs`, `ValidationPublishPackageBuilder.cs` (полные пути в таблице).

**Imports / core pattern:** `DG/src/DG.Core/Validation/RuleEvaluator.cs:1–4,23,95–99,111–112`:

```csharp
using System.Globalization;
using DG.Core.Contracts;
using DG.Core.Models;
using DG.Core.Parsing;

private readonly record struct BindingOutcome(EvidenceStatus Status, string? Detail);
```

```csharp
outcomes.Add(outcome);

if (outcome.Status == EvidenceStatus.Failed || outcome.Status == EvidenceStatus.Error)
{
    failingBindings.Add(binding);
}
```

```csharp
var status = StatusRollup.Rollup(outcomes.Select(o => o.Status));
var passed = EvidenceEnvelopeFactory.ToLegacyBoolean(status);
```

Применение: публичные per-binding результаты должны сохранять **исходный binding association**, status и detail до rollup. Сейчас return сохраняет только summary и FailingBindings (`:124–134`); добавить status в HTTP DTO недостаточно. Не выполнять evaluator второй раз и не размножать rule aggregate на objects.

**Compatibility analog:** `DG/src/DG.Core/Models/RuleEvaluationResult.cs:19–30`:

```csharp
public bool Passed { get; init; }
// ... existing non-authoritative / authoritative documentation ...
public DG.Core.Contracts.EvidenceStatus Status { get; init; }
public string Message { get; init; } = string.Empty;
public List<BindingRow> FailingBindings { get; } = new();
```

D-02 требует различать unavailable typed results и evaluated empty population. Отсутствие новой коллекции не считать Passed из default enum, не восстанавливать по Passed/FailingBindings: **unknown + diagnostic**. Legacy bool/lists остаются на прежнем алгоритме.

**Identity/grouping analog:** `DG/src/DG.Core/Validation/ValidationPublishPackageBuilder.cs:168–192` дедуплицирует ElementRefs в одном binding по DgEntityId; `:100,160` сортирует ordinal. Использовать эту association, а статусы contributing bindings агрегировать через `StatusRollup.Rollup`. Existing `statusByEntity: Dictionary<string,bool>` (`:52–85`) — только legacy branch, не образец нового canonical алгоритма.

**Missing result:** `:35–49` уже создает rule `NotEvaluated` и делает continue. Rule-level результат сохранить даже без entities; его наличие не разрешает привязать правило к произвольным objects. NoPopulation branch evaluator `:40–54` возвращает rule status до обхода bindings; binding без ElementRefs (`builder:59–62`) — другое состояние, не NoPopulation.

**Diagnostic/error pattern:** `RuleEvaluator.cs:74–92` genuine exceptions → Error; `:323–335` missing variable → Unknown с What/Where/How-to-fix. Short-circuit `:137–156` должен остаться: Passed atom прекращает violation-body раньше потенциального Unsupported atom.

**Tests:** `DG/tests/DG.Tests/ValidationPublishPackageBuilderTests.cs:30–51` создает два binding и shared/multiple ElementRefs, но RuleEvaluationResult содержит только legacy поля. Это ценный compatibility fixture, не нужно переписывать его так, чтобы старый caller исчез. Тест Unsupported `:218–251` не имеет ElementRef и проверяет только rule result — не использовать как доказательство entity wire. Natural Indeterminate branch в прочитанном evaluator отсутствует; transport-injection test честно маркировать отдельно.

**Factory analog:** `EvidenceEnvelopeFactory.cs:53–64`:

Существующий C# empty default — NotEvaluated (`StatusRollup.cs:50–52`); Python — NoPopulation (`evidence_contract.py:212–216`). Оба имеют explicit override; не менять глобальные defaults попутно. Rule outcomes должны участвовать в осмысленном envelope aggregate, но **никогда** в генерации фиктивных object rows и не подменять object verdict.

**Tests to copy:** `data-service/tests/test_evidence_contract.py:147–193` проверяет missing required, extra fields, forbid; `:40–44` enum equality со schema. `DG/tests/DG.Tests/EvidenceContractTests.cs:60–68` проверяет ту же authority. `:132–140,197–217` содержит literal `1.0.0` expectations — при versioning различать старые fixtures и новый producer. Эти C# tests не выполняют полноценный JSON Schema validator: string assertions не заменяют Python schema validation настоящих wire bytes.

**Normative constraint:** `spec/EVIDENCE-CONTRACT.md:195–198` требует rule NoPopulation в envelope без EvidenceRow; `:204–241` сохраняет legacy non-authoritative и запрещает bool→canonical. Именно этот gap закрывает D-01. `spec/DATABASE.md:158,198–208` связывает envelope property и canonical per-object read.

### P5 — Backward version dispatch и безопасные read boundaries

**Ближайший tracked backward-dispatch аналог:** `DG/src/DG.Core/Data/Neo4jValidGraphRepository.cs:339–362,440–459`.

```csharp
using var doc = JsonDocument.Parse(statePayloadJson);
var root = doc.RootElement;
// ... version guard before structural sniffing ...
if (root.ValueKind == JsonValueKind.Object
    && root.TryGetProperty("version", out var versionElement)
    && versionElement.ValueKind == JsonValueKind.String
    && versionElement.GetString() != "2")
{
    return null;
}
```

Затем explicit v2 path или versionless legacy ParamState fallback. `DesignStatePayloadV2Serializer.cs:66–69` strict writer-specific reader отвергает unsupported version. **Копировать принцип, не буквальные version values/structural sniff:** evidence имеет другой контракт. Этот guard сам пропускает non-string version до structural branch; это не образец полной строгой version validation. Не переносить известную двойственность DesignState readers (tests `:278–333`) в новый evidence reader и не исправлять ее в этой фазе.

**Existing backward tests:** `DG/tests/DG.Tests/Neo4jValidGraphRepositoryTests.cs:372–407` содержит future version rejection + current version + versionless legacy acceptance. Это матрица для new evidence reader: поддерживаемые старые данные / новая версия / unknown version / wrong type / malformed. Значения версий и policy должны быть сформулированы явно, не угаданы по наличию rule collection.

**Important legacy evidence input:** reader test helper `Neo4jValidGraphRepositoryTests.cs:477–482` использует `contractVersion:"1"`, тогда как factory пишет `1.0.0`. Сейчас reader не проверяет version (`repository:261`). Нельзя молча «нормализовать» этот token или объявить его valid semver. Plan-checker должен явно отличить исторический read-compat alias от нормативного new-write version; не переписывать все старые fixtures, скрыв breaking reader change.

**Canonical reader pattern:** `Neo4jValidGraphRepository.cs:276–301` сначала detects duplicate `(RuleId,ObjectId)` pairs, затем:

```csharp
var verdicts = rows
    .GroupBy(row => row.ObjectId, StringComparer.Ordinal)
    .Select(group => new PerObjectVerdict
    {
        ObjectId = group.Key,
        Status = StatusRollup.Rollup(group.Select(row => row.CanonicalStatus)),
        Source = VerdictSource.EvidenceEnvelope,
        HasDuplicateRuleObjectRows = collidingObjectIds.Contains(group.Key),
    })
    .OrderBy(v => v.ObjectId, StringComparer.Ordinal)
    .ToList();
```

## Shared Patterns

- **Authority:** schema — shape; EVIDENCE-CONTRACT — semantics; D-01–D-04 — актуальное разрешение изменений. Runtime map и rule collection не вводят девятый status.
- **Canonical ≠ legacy:** сохранить Passed, ValidStatus, OverallStatus и списки; не «исправлять» их значением canonical boolean mapping. Typed binding absence — unknown+diagnostic; missing rule result — отдельный NotEvaluated case.
- **Identity:** exact pair; ordinal ordering; repeated binding contributions roll up до одной producer row, разные identity не схлопывать по value. Read-side malformed/duplicate detection не ослаблять.
- **Validation layered:** Pydantic boundary → strict schema → persist capture → actual read. C# JsonSerializer обычно терпит неизвестные поля; это не доказательство version compatibility.
- **No population:** несколько zero-row rules сохраняются с ruleId/status; никаких placeholder objectId, warnings-as-serialized-map или одного aggregate вместо коллекции.
- **Test realism:** общий production serialization seam либо source-linked production; Pydantic actual request; авторизованный TestClient; fake только внешнего I/O; те же persisted bytes в Python view и C# reader. Handcrafted fixtures допустимы для contract unit cases, но не вместо GH regression.
- **Auth/tenancy:** connector guard до HTTP; реальные временные test principals; scoped parameterized writes; security regression остается независимым gate.
- **Safety:** только offline controlled execution. Нет commits/push, branch changes, secrets, live graph writes, restarts, paid calls, graph rebuild, архивов или публикационной работы. Dirty tree не очищается. Это не migration/backfill старого ошибочного passed.
