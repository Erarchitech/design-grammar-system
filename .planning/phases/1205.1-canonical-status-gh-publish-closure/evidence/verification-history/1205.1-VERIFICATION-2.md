## BLOCKER — CR-03-inmemory-container

`sourceRepresentation` объявлен как `dict[str, Any]` (`evidence_contract.py:185`). `validate_json_resources` обходит BaseModel → dict и только dict/list (`:231–247`), пропуская tuple. Named `build_envelope_with_rule_results` сначала создаёт old model, затем вызывает preflight и JSON-mode dump (`:358–362`). Pydantic сериализует tuple в array, превращая nonfinite float в null. Full v2 model видит уже очищенный payload и принимает его. Аналогичный обход `validate_envelope` (`:471–474`) не предотвращает преобразование.

Минимальное воспроизведение:

```python
build_envelope_with_rule_results(
    'p', 'd', 's', '1', 'test', [], [],
    source_representation={'x': (float('nan'),)},
).model_dump_json(exclude_none=True)
# Фактическое поле результата: "sourceRepresentation":{"x":[null]}
```

**Независимый probe:** `evidence/verifier-r2/inmemory_probe.py`; exact argv и traceback в `inmemory-probe.log`, **exit 1**. Original source не менялся.

| Контроль | Требование | Фактический результат |
|---|---|---|
| finite list `[1.5]` | valid | принят без потери числа |
| finite tuple `(1.5,)` | valid existing serialization | принят как `[1.5]` |
| list `[NaN]` | reject before dump | ValueError — правильно |
| tuple `(NaN,)` | reject before dump | принят, превращён в `[null]` |
| tuple `(+Infinity,)` | reject before dump | принят, превращён в `[null]` |
| tuple `(-Infinity,)` | reject before dump | принят, превращён в `[null]` |
| legacy `validate_envelope` с tuple NaN | reject before dump | validation проходит |

Для всех трёх ошибочно нормализованных v2 результатов реальные Python и свежесобранный C# reader принимают уже испорченное JSON. Сохранены `*-factory-output.json`, `*-reader.json` и `inmemory-probe.json`. Это **не** утверждение, что raw HTTP допускает tuple или прежний GET crash остался: JSON wire tuple не имеет, raw HTTP/GET controls теперь GREEN. Нарушено отдельное требование этой итерации **finite raw + in-memory before Pydantic JSON dump; не переписывать в null**. Direct legacy constructor defaults по-прежнему не требуется менять; failing assertion относится к explicit validator и новому named v2 factory.

Нужно закрыть границу до потери значения, сохранив valid controls, затем перепроверить независимо. Source fixes verifier не выполнял. Новых ограничений serializer API не навязываю: допустим обход всех поддерживаемых containers либо явный reject неподдерживаемого representation, но не silent replacement invalid number.
