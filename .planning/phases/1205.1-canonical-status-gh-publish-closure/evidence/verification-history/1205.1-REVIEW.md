### CR-01 — BLOCKER / critical: duplicate JSON members обходят строгий admission и могут заменить Unsupported на passed

**Файлы:**
- `C:/Users/Admin/source/repos/design-grammar-system/data-service/app.py:413–424, 451–461, 1187–1191`.
- `C:/Users/Admin/source/repos/design-grammar-system/data-service/evidence_contract.py:266–296`.
- `C:/Users/Admin/source/repos/design-grammar-system/DG/src/DG.Core/Contracts/EvidenceEnvelopeReader.cs:44–58, 94–101, 104–110`.

**Проблема.** Новый Python validator получает уже decoded dict. Стандартный JSON decoder сохраняет последний одинаковый ключ, поэтому exact-key coverage и version checks не видят конфликтов. В persisted reader также используется обычный `json.loads`. C# проверяет повторяющиеся поля только внутри `Fields`; historical root branch эту проверку не вызывает, а `Version` выбирает последнее значение через `TryGetProperty`.

**Воспроизводимость — выполненный isolated probe:**
1. В реальных сохранённых `evidence/wire/supported/request.json` bytes заменить единственную запись `"R_WIRE":"passed"` у OBJ_PASS на два одноимённых поля `"R_WIRE":"unsupported","R_WIRE":"passed"` (пробелы несущественны).
2. Пропустить bytes через настоящий `starlette.requests.Request.json`, затем неизменённый `ValidationPublishRequest.model_validate`. Получено `OBJ_PASS: {'R_WIRE': 'passed'}`; exception отсутствует. POST не выполнялся. Source trace: после этой admission handler строит canonical row прямым indexing (`app.py:2637–2645`) и выполняет внешние записи; дополнительных duplicate-member guards нет.
3. В valid v2 persisted JSON сделать row `canonicalStatus` дублированным: сначала unsupported, потом passed. Python `parse_evidence_envelope` принимает последний passed; actual C# harness `read` возвращает `envelopePresent=false`.
4. Literal raw JSON `{"contractVersion":"2.0.0","contractVersion":"1.0.0","canonicalStatus":"passed"}` принимается **обоими** historical readers. Python возвращает старый partial dict, C# — `envelopePresent=true`, empty verdicts. Это выбор tolerant branch из противоречивого discriminator, не одобренная совместимость с однозначным old token.

**Риск.** Malformed input не отклоняется до записи; существенный non-verdict теряется без диагностики. Валидаторы разных языков дают разный admission одного raw evidence. Existing duplicate-* тесты проверяют duplicate array identities, но не duplicate JSON members: dict/JsonNode fixtures уже уничтожают такие дубли.

**Исправление.** Отклонять повторяющиеся JSON member names при raw decode до model admission на publish boundary и persisted read; проверять root uniqueness в C# до version dispatch, включая historical branch. Не заменять этим существующую разрешённую duplicate-row collision policy. Добавить raw-string/bytes отрицательные tests для version/status/map/rows keys; malformed new publish должен завершаться без Speckle/graph writes. Сохранить unchanged valid old-token/no-rows inputs.

### CR-02 — BLOCKER / critical: RecursionError перенесён за пределы защищённого decode

**Файлы:**
- `C:/Users/Admin/source/repos/design-grammar-system/data-service/app.py:1187–1191, 1285`.

**Проблема.** Catch охватывает только `json.loads`. После успешного decode v2 читатель вызывает новый рекурсивный `_wire_input`, обходящий произвольное содержимое `sourceRepresentation`. Этот обход может выбросить RecursionError при глубине, ещё допустимой для decoder. `read_envelope_dict` ловит только schema/Pydantic ValidationError; ошибка доходит до view.

**Воспроизводимость — выполнено на настоящей функции, без app startup:** взять valid retained supported envelope `e`, удалить последнюю `}` из `json.dumps(e)` и дописать:

```python
raw = json.dumps(e)[:-1] + ',"sourceRepresentation":{"x":' + '[' * 700 + '0' + ']' * 700 + '}}'
```

`json.loads(raw)` проходит. `parse_evidence_envelope(raw)` выбрасывает `RecursionError: maximum recursion depth exceeded ...`, вместо None. Функция загружалась неизменённым AST node из `app.py` с настоящим `evidence_contract`, чтобы не инициализировать services/auth. На probe runtime recursion limit не изменялся. Для глубин 70/200/400 Python принимает input; на 700 произошёл указанный crash.

**Риск.** Заявленный D-03 safe corruption fallback остаётся неполным, а новая strict-v2 ветка добавляет рекурсивный failure mode. Тест из `'[' * 10000` падает внутри decoder и потому не обнаруживает проблему после него.

**Исправление.** Узко защитить всю admission boundary от RecursionError (не arbitrary blanket catch), либо ограничить глубину до рекурсивной нормализации. Добавить syntactically valid deeply nested v2 object и real view projection regression, сохранив valid-data controls и прежние historical fixtures. Не повышать interpreter recursion limit.

### CR-03 — BLOCKER / critical: NaN в metadata проходит Python strict v2 read и ломает JSON view response

**Файлы:**
- `C:/Users/Admin/source/repos/design-grammar-system/data-service/app.py:1187–1191, 1285`.
- `C:/Users/Admin/source/repos/design-grammar-system/data-service/evidence_contract.py:184, 243–249, 274–296`.
- `C:/Users/Admin/source/repos/design-grammar-system/spec/evidence-contract.schema.json:95, 163–166`.

**Проблема.** Python `json.loads` принимает не-JSON constants NaN/Infinity. `sourceRepresentation` допускает arbitrary object contents, а JSON Schema не проверяет JSON-синтаксис уже декодированного Python float. Model admission проходит, и reader возвращает **original dict** с non-finite value. Возврат исходного dict корректен для preservation, но требует сначала отклонить такие значения.

**Воспроизводимость — выполнено:** к valid v2 envelope добавить `"sourceRepresentation":{"x":NaN}`. Root `jsonschema` и `read_envelope_dict` приняли input; `parse_evidence_envelope` вернул dict. `starlette.responses.JSONResponse({'evidenceEnvelope': accepted})` выбросил `ValueError: Out of range float values are not JSON compliant`. Тот же raw JSON actual C# reader отверг: `envelopePresent=false`. Service/DB не запускались.

**Риск.** Corrupt evidence превращает renderable view в server error вместо absent evidence; cross-language strict admission различается. Новый v2 guard не обеспечивает обещанную безопасную обработку повреждённого JSON. Наличие прежнего tolerant parser не оправдывает дефект в закрываемом contract/corruption boundary.

**Исправление.** Использовать rejecting `parse_constant` для raw evidence и проверять finite JSON numbers в admitted arbitrary metadata (включая exponent overflow вроде `1e400`, которое не вызывает `parse_constant`). Аналогичное raw request admission не должно допускать invalid JSON constants. Добавить NaN/Infinity/-Infinity/overflow controls, actual response-serialization check и C# parity; fallback — None, не переписывание значений в null или passed.
