| Raw control (остальное — сохраненный full supported v2 envelope) | Root jsonschema | Python read_envelope_dict | Actual C# repository reader |
|---|---|---|---|
| Без изменений | accepted | accepted | EnvelopePresent=true |

| `inputHash: "A" * 64 + "\n"` | accepted | accepted | EnvelopePresent=false, verdicts=[] |

Причины:
- `EvidenceEnvelopeReader.cs:128–130`: `TryGetInt32` отвергает JSON lexical `1.0`, хотя schema `type: integer` (`schema:118–120`, v2 reference `:80`) допускает численно целое значение. Это не изменение exact **contractVersion** token: он остается строкой `2.0.0`.
- `EvidenceEnvelopeReader.cs:198–199`: `\A...\z` строже существующего schema `^[0-9A-F]{64}$` (`schema:167–175`, также row `:47–55`). Python regex `$` допускает финальный newline. По prose hash должен быть ровно 64 hex; вторая строка выявляет и разницу schema/prose, и reader parity. Нельзя просто объявить принимающий Python правильным в семантическом смысле; нужно согласовать authorities.
- Python dispatch `evidence_contract.py:266–296` принимает оба, C# `TryRead` отклоняет до projection (`EvidenceEnvelopeReader.cs:47–51`), и repository возвращает absent (`Neo4jValidGraphRepository.cs:261–264`). Это потеря **всех** object verdicts допустимого для Python envelope, не лишь форматная придирка.

Сохранены `evidence/verifier/admission-probe.{json,log}`, `integral-json-number-input.json`, `newline-hash-input.json` и реальные `*-reader.json`. Эти inputs handcrafted negative/boundary controls, **не** GH producer output. Обычный GH writer emitting integer 1 и не заполняющий hash этой ошибкой в выполненных сценариях не затронут. Тем не менее explicit reader-parity must-have FAILED; scope нельзя сузить до producer happy path после факта.

**Не исправлялось.** Требуются bounded исправление согласованного admission contract и regressions. Перезапуск этого probe должен стать GREEN, затем targeted compatibility/wire suites и SDK. Live rollout не требуется и не разрешен.
