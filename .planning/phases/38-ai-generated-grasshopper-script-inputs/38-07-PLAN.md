- `score_domain_compliance(candidates, bound_params) -> float` (SC1-a): the fraction of candidates for which `cg_input_sampler.validate_candidate` returns an empty violation list. **Import the runtime validator; do not reimplement the range/step logic here.**
- `score_rule_satisfaction(candidates, classification) -> float` (SC1-b): over candidates only, the fraction whose `ruleSatisfaction.claim == "satisfied"`. The caller must handle `None` explicitly.
- `score_diversity(candidates, bound_params) -> float` (SC1-d): the **minimum** pairwise `normalized_distance` across the set, reusing `cg_input_sampler.normalized_distance`. Returns `1.0` for a single-candidate set (vacuously diverse) rather than raising.
- `score_overclaim(candidates, classification) -> int` (SC1-e): the count of candidates claiming `satisfied` when `classification.determinability == "geometry-required"`. The threshold is exactly 0 and this is the phase's credibility metric — give it a docstring saying so.
- `score_candidate_set(candidates, bound_params, classification) -> dict` assembles all four plus the candidate count into one dict with keys `domainCompliance`, `ruleSatisfaction`, `diversity`, `overclaimCount`, `candidateCount`, for a single readable assertion site and for emission into the summary.

SC1-c is a property of a whole generation run rather than of a candidate set, so it is asserted directly in Task 2 rather than scored here.
