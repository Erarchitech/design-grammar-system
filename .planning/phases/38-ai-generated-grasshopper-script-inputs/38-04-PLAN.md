<objective>
Build the generation core: a deterministic Tier 0 sampler with a per-request dynamic domain validator, a Tier 1 LLM orchestrator that selects and explains within those bounds, and the `POST /computgraph/generate-inputs` route that exposes them — with the generate-side separation from any canvas or persistence path asserted by test.

Purpose: 38-RESEARCH.md §4.1 is decisive — constrained decoding is the only generation-time guarantee of in-range values, and it is unavailable here twice over: `to_strict_json_schema()` strips numeric bounds by design, and the bounds are per-parameter and dynamic anyway. The architecture is therefore forced to generate → validate → reject/retry. Tier 0 exists so that forcing does not leave the caller empty-handed when the model is useless.

Output: `cg_input_sampler.py`, `cg_input_generation.py`, a system prompt file, the route, and three test modules including the GHIN-04 import-boundary assertion.
</objective>

Create `data-service/cg_input_sampler.py`: pure functions, no LLM, no Neo4j, no I/O. Same determinism contract as `cg_topology.py` — the same input must always produce the same output, so no `random` without a fixed seed and no wall-clock reads.

Define `STRATEGIES = ("conservative", "balanced", "exploratory", "near-limit")`, `DEFAULT_CANDIDATE_COUNT = 4`, `MAX_CANDIDATE_COUNT = 8`, `NEAR_DUPLICATE_THRESHOLD = 0.10`.

`step_align(value, domain_min, domain_step)` snaps a value to the nearest `domain_min + k * domain_step`, returning `value` unchanged when `domain_step` is falsy. Round the step index with a tolerance rather than raw float comparison — `domainStep` is commonly `10**-decimalPlaces` and exact float equality will fail on values that are correct.

`validate_candidate(parameters, bound_params) -> list[dict]` is **the** dynamic validator, built per request from the actual parameter set. It returns a violation list — empty means valid. For each supplied parameter it checks, and emits a violation dict `{parameterId, code, message, domain}` for: a parameter not in `bound_params` (`unknown-parameter`); a missing required parameter (`missing-parameter`); a type mismatch against `stateType` (`type-mismatch`); `value < domainMin` or `value > domainMax` (`out-of-domain`); a value not step-aligned within tolerance (`step-misaligned`). Boolean parameters skip the range and step checks. Each `message` is What+Where+How-to-fix per the house error convention.

This function **never modifies a value**. State that in the docstring and name the reason: clamping is semantic distortion that hides model failure behind a valid-looking result (D-14). There must be no clamp helper in the module at all — its absence is asserted in Task 5.

`sample_tier0(bound_params, limit, strategy) -> dict` produces one deterministic, guaranteed-valid assignment per strategy:
- `conservative` — the low end of each domain (or the high end when the rule limit is a `>=` lower bound, so "conservative" always means "furthest inside the constraint")
- `balanced` — the domain midpoint, step-aligned
- `exploratory` — a fixed-seed Latin-hypercube-style stratified point: for parameter index `i` of `n`, take the `(i + 0.5) / n` quantile of its domain. Deterministic, no RNG, and spreads across the space rather than clustering
- `near-limit` — the value closest to the rule limit that still satisfies it, when `limit` is not `None`; otherwise the 90th-percentile point of each domain

Every produced value is `step_align`ed and then clipped into `[domainMin, domainMax]`, so Tier 0 output passes `validate_candidate` by construction. When `limit` is present and the classification is `direct-parameter`, respect it exactly; when `monotone-bound`, use the monotone direction to pick the safe side. When `limit` is `None`, sample the domain only.

`sample_candidate_set(bound_params, limit, count)` returns `count` assignments by cycling `STRATEGIES` and, past four, perturbing by one additional step in the exploratory direction so a fifth candidate is not a duplicate of the first.

`normalized_distance(a, b, bound_params)` scales each parameter to its own domain (`(v - min) / (max - min)`, and `0.0`/`1.0` for booleans) and returns the mean absolute difference across parameters. `is_near_duplicate(candidate, others, bound_params, threshold=NEAR_DUPLICATE_THRESHOLD)` returns True when the minimum distance to any of `others` is below `threshold`. A parameter with a degenerate domain (`domainMax == domainMin`) contributes 0 to the distance and must not divide by zero.
