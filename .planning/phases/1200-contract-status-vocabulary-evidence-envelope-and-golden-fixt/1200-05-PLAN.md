## Planner decision — RESEARCH.md Open Question 2

**The DE-01 runner is a Python orchestrator at `tools/de01/`, and the C# leg is reached by shelling
out to a minimal console harness at `DG/tools/DG.De01Harness/` and reading its JSON stdout.**

Rationale: data-service and dg-reasoner are both FastAPI services already reachable over HTTP; the
persisted-replay leg is a Neo4j read plus a data-service route. Python reaches three of four legs
naturally and already owns the `jsonschema` validation dependency. A dedicated console harness is
preferred over `dotnet test --filter` for the C# leg because the runner needs structured JSON on
stdout, and a test runner's output is a test report, not an evidence artifact.

**No CI infrastructure is created.** `.github/workflows/` does not exist in this repo and D-12's
"thin CI-invocable wrapper" is read as "a test runnable by a future CI and easy to invoke manually
today", per RESEARCH.md Pitfall 5.

**`legs.py`** — a `LegResult` dataclass (`leg_name`, `available`, `envelope`, `error`) and four
adapters, each of which never raises and always returns a `LegResult`, following the
`derive_valid_status` "Never raises" house style:

- `run_leg_data_service(fixture, config)` — POST the fixture-derived validation payload to
  data-service and read back the `evidenceEnvelope` from the response. Reuse
  `data-service/evidence_contract.py`'s models by importing them; do not reimplement the envelope.
- `run_leg_dg_reasoner(fixture, config)` — POST to `/shacl/validate` with the fixture's project,
  then map the `{conforms, results, counts}` envelope to canonical statuses. Map `conforms: None`
  with an `error` key to `CanonicalStatus.ERROR` carrying the reason; map a shape with zero
  focus-node results to `CanonicalStatus.NO_POPULATION` rather than `passed`, because pySHACL
  reports `conforms: true` for an empty target set and that is exactly the collapsed-status defect
  this contract exists to separate. Document that mapping decision inline.
- `run_leg_csharp(fixture, config)` — `subprocess.run` the `DG.De01Harness` project, capture stdout,
  parse it as the envelope. Map a non-zero exit or unparseable stdout to an `error` `LegResult`
  carrying stderr as the reason. Do not catch the harness's internal exception mapping — the harness
  already types `NotSupportedException` as `unsupported`; this adapter only handles the harness
  itself failing.
- `run_leg_replay(fixture, config)` — read the persisted run back through data-service's
  validation-run view and pull the `evidenceEnvelope`. When the graph is unseeded, the envelope is
  absent, or Neo4j is unreachable, return a typed `error` `LegResult` naming the missing
  precondition and pointing at `fixtures/golden/seed.cypher` — never a crash. Read the canonical
  envelope only; never derive a status from `ValidStatus`.

Every adapter validates its envelope with `evidence_contract.validate_envelope` before returning it,
and maps a validation failure to an `error` `LegResult` naming the schema violation — an envelope
that does not conform to the contract is not admissible evidence.

**`report.py`** — the comparison core and the two emitters.

`compare_legs(leg_results)` builds the union of all (rule, object) pairs seen in any available leg's
envelope, ordered ascending by `objectId` with ties broken by `ruleId`, and produces one
`ComparisonRow` per pair carrying each leg's status, warnings, input hash, output hash, and
service/version. For each row, classify:
- all available legs agree → `agreement`.
- legs differ, and every differing leg's status is one of `unsupported`, `error`,
  `not_evaluated`, or `indeterminate` AND carries a non-empty warning explaining it → a
  **declared non-equivalence**, recorded with the reason text.
- legs differ in any other way → a **silent disagreement**, counted in
  `silent_disagreement_count`.

This function is the single place a difference could be lost. It must have no branch that returns
agreement for unequal statuses, must not normalize or coerce any status before comparing, and must
not skip a pair because one leg lacks it. Write that constraint as a module docstring and assert it
in tests.

Also compute a per-status tally per leg by iterating rows and incrementing a bucket dict, copying
the shape of `reasoning.py`'s `counts` construction.

`emit_json_report(comparison, path)` writes the structured report: run metadata (timestamp, fixture
version, contract version, canonicalization version), a per-leg availability and service/version
block, the ordered comparison rows, the declared non-equivalences with reasons, the per-status
tallies, and `silent_disagreement_count`.

`emit_markdown_report(comparison, path)` writes the human-readable sibling: a header stating the
verdict and `silent_disagreement_count`, a per-leg availability table, a comparison table with one
row per (rule, object) pair and one column per leg showing the canonical status, a declared
non-equivalences section listing each with its reason, and a warnings appendix. PATTERNS.md records
that no in-repo Markdown-report generator exists to copy; build it from this spec.

**`report_schema.json`** — a draft 2020-12 JSON Schema for the DE-01 report itself, `$ref`-ing

vocabulary.

comparison, emits both reports, prints a one-line summary to stdout naming the report paths and the

unavailable does not affect the exit code — that is a typed outcome recorded in the report, per
D-13.
