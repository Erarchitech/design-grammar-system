<plan_decisions>
- **F4 is fixed by composing, not by discarding.** The alternative — dropping the stale record — has no safe API: `GH_UndoServer.Clear()` wipes the architect's entire design undo history, which is far worse than the bug. Composing keeps the stack coherent: the new record R2 becomes `[remove old preview objects, add new preview objects]`, so Ctrl+Z #1 restores the previous preview and removes the new one, and Ctrl+Z #2 then undoes R1's adds against objects that genuinely exist again.
- **Record creation moves ABOVE the auto-clear call.** Today `RemovePendingPreviewObjects(doc)` runs at `:295` and the record is constructed at `:298`. The order must invert so the removals can be recorded into the same record, and they must be added before the adds so undo replays them in the right order.
- **`RemovePendingPreviewObjects` gains an optional `GH_UndoRecord?` parameter rather than splitting into two methods.** `null` ⇒ today's non-undoable behaviour, which the explicit `clear_preview` path keeps using (UAT tests 2 and 4.2b depend on it, and `clear_preview` is documented as deliberately non-undoable). Non-null ⇒ each removal is preceded by a `GH_RemoveObjectAction`, matching the counterpart precedent already established by the WR-05 fix in `StructureConfirmComponent` (`:232`).
- **The legend scribble is recorded too.** It is removed by the same helper and would otherwise leave the same class of dangling action.
- **G12 gates only parameter kinds — `Var`, `Const`, `Emg`.** `Proc` and `Pat` carry no `dataType`; `IntF` carries `ifaceType`, not `dataType`. Gating them would block on a property they do not have.
- **The gate calls the parser, it does not re-implement it.** `CanvasAnnotationParser.InferParameterDataType` is `private static` (`:485`), so the plan adds one public wrapper — `TryInferParameterDataType` — that delegates to it verbatim. A second copy of the inference rules in the Grasshopper layer is exactly the Python/C# divergence AI-SPEC §4 warns produces F5-class failures.
- **Blocked ⇒ stays pending, and is reported.** Not rejected (the architect did not reject it) and not accepted (it would break publish). It stays in the registry with a `GH_RuntimeMessageLevel.Warning` naming the component and the fix, and the Status line reports the blocked count separately from accepted/rejected.
- **After `028ff0e` this gate will fire rarely** — bare `Number`/`Integer`/`Text`/geometry params now type successfully. That is the intended end state: the gate is the backstop for the genuinely untypeable member, and 35-13's E8 dimension needs it to exist in order to score against it.
</plan_decisions>
