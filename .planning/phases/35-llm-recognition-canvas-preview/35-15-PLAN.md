<plan_decisions>
- **A0 first, and its result is a gate on the whole sweep.** AI-SPEC §5: A0 is the negative control *and the harness's own validity test*. If A0 does not reproduce F3, stop — report the harness as unvalidated and do not publish any other arm's number. This ordering is not a preference; a sweep whose control passes is measuring something other than what it claims.
- **A frontier-class key is a hard prerequisite, not an assumption.** UAT F3 established that `deepseek-chat` returns 0 proposals from 14 candidates and `deepseek-v4-pro` returns empty text ×3 on the large prompt. If no Anthropic/OpenAI key is available at execution time, the plan stops after the A0/A1/A2 DeepSeek arms and reports SC1 as **still blocked on provider availability** — with the arms that did run and what they showed. Reporting a DeepSeek-only number as SC1 would repeat the exact error this phase exists to correct.
- **Arms in ablation order: A0 → A0f → A1 → A2 → A3 → A4 → A5.** Each step isolates one claim, so running them in order means a surprise is attributable to the change that produced it. AI-SPEC's pre-registered decision rule for F3 is applied verbatim to the results: `A0f ≫ A0` and `A2 ≫ A0` ⇒ both prompt and model contribute, fix the prompt first; `A2 ≈ A5` ⇒ the prompt was the whole story and DeepSeek suffices (the outcome the diagnosis predicts); `A2 ≈ A0` but `A5 ≫ A0` ⇒ a genuine capability limit and the spec's central claim was wrong — **record that outcome plainly if it happens.**
- **Budget ~$2–4 for the full sweep** (3 provider arms × ~20 fixtures, AI-SPEC §4b arithmetic). Cheap enough to run rather than skip. Record actual cost and token usage from the run logs.
- **The permutation sub-sweep runs on the winning arm only**, 3 fixed permutations of the few-shot order. If M1 varies by more than ~0.10 across permutations, the headline must be reported as a **range with the permutation spread**, not a point estimate, and the fixture ordering must be pinned and justified in the fixture file.
- **Replay re-run is part of the deliverable.** After recording, re-run the same command in `replay` mode and confirm identical metrics from the committed cassettes. This proves the CI gate is real and that the cassettes are complete — not that the model is deterministic, which it is not.
- **What this plan does NOT do, stated so the report cannot imply otherwise:** it does not calibrate the LLM judge (so E4-name and E7-soft stay reported-but-excluded), does not run the test–retest self-agreement session (needs a ≥ 4-week blind gap), does not run the external-peer calibration session (needs a second computational designer), and does not implement the AI-SPEC §7 production monitoring streams or review queue. All four are named in the report's "not measured" section and carried into `STATE.md` as follow-ups.
- **UAT bookkeeping uses single-line `expected:` / `result:` values.** The `query audit-uat` tooling silently drops entries written with block scalars, which would make a closed item look absent.
</plan_decisions>
