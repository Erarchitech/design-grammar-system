<plan_decisions>
- **Annotate in Grasshopper, not in JSON.** The reference must be produced by the same instrument that produces production ground truth — DG ENTITY TAG and DG OBJECT MARKER on the live canvas, then a `/computgraph/context/pull`. Hand-editing the expected file would make the reference an artifact of a different process than the thing being graded, and would lose the parser's own view of `dataType` (which E8 needs).
- **Two pulls, two purposes.** Pull 1 = the *tagged* context, from which the reference blocks are mechanically derived (kind, procedureIndex, name, memberIds, hostBlockId, publishable). Pull 2 = the *input* context, which must be the same canvas with the entity tags removed or ungrouped so only the Object marker, the algorithm scribble and the `_Proc` groups survive — matching what ROADMAP SC1 describes. Deriving the reference from the tagged pull is what keeps input and reference in one member-id vocabulary.
- **`publishable` comes from the parser, not from judgement.** For every parameter block, run the 35-09 `CanvasAnnotationParser.TryInferParameterDataType` seam over its members and record `publishable: false` when the inferred dataType is null. AI-SPEC §5 requires ≥ 1 `Const` on a bare `Number` component marked `publishable: false` as E8's positive test case — note that commit `028ff0e` now types bare `Number` as Float, so finding a genuinely unpublishable member may require a member the parser still cannot type. If none exists on the slice, record that explicitly as an uncovered composition requirement rather than fabricating one.
- **Scope is 2–3 procedures, ~60–80 nodes, ≥ 20 blocks, ≥ 2 abstain nodes.** UrbanBlock_V7 has 233 nodes / 221 untagged; annotating all of it is not an afternoon. Per-procedure scoping is the recommended production path (§4 Context Window Strategy), so the eval unit matching the production unit is correct rather than expedient.
- **Composition is selected against a checklist, and gaps are reported.** The slice must contain: ≥ 1 correct grouping that is **spatially interleaved** (FM-1); ≥ 2 relays or bare `Param`s that are **not** Interfaces (FM-2, and the direct adversary of Tier-0 rule R4); ≥ 2 disconnected/abandoned components marked `abstainExpected` (FM-3); ≥ 1 multi-member Pattern **and** ≥ 1 nested Pattern (FM-4); ≥ 2 components whose nickname misleads — `Num`, `H`, `TARGET SCR` all qualify and are all real on this canvas (FM-5); ≥ 1 `Const` on a bare `Number` (FM-6); ≥ 1 procedure with real inter-procedure `IntF` traffic (E3 needs a true positive, not only false ones). Any requirement the slice cannot satisfy is recorded in the summary as an untestable failure mode — silently omitting it would leave the eval claiming coverage it does not have.
- **`ipClass: "own"`** — the researcher's own canvas, so cassettes may store prompt bodies. This flag is what 35-13's cassette writer reads; a future collaborator's canvas would set `"third_party"` and the prompt body would stop being stored.
- **Freeze is its own commit, and the harness enforces it mechanically.** The `*.expected.json` commit must contain no change to the prompt, the few-shot or `cg_topology.py`. `corpus.assert_context_unchanged` re-hashes the context on every scoring run, which a rebase cannot defeat.
- **Test–retest and external-peer sessions are explicitly NOT in this plan.** AI-SPEC requires both alongside any reported M1 (self-agreement ceiling and peer-agreement floor). They need a ≥ 4-week gap and a second person, so they are scheduled work, not plan tasks. 35-15 must report M1 with that limitation stated rather than pretending the ceiling exists.
</plan_decisions>
