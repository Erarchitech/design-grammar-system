# Phase 35-11: Recognition Eval Substrate (Corpus A + Scoring Core) Summary

**Corpus A (`frame_ablated`) — a mechanically-ablated version of the tagged Frame fixture, generated and golden-file-pinned by one C# test — plus a stdlib-only Python scoring core (block matching + every SC1 metric) and a corpus loader that refuses to score an unprovenanced or unfrozen run.**

## Performance

- **Tasks:** 3 of 3
- **Files created:** 7
- **Commits:** 3 (one per task)

## Accomplishments

- **Built the ruler ROADMAP SC1 was missing.** Before this plan there was no offline way to score recognition output against a reference at all — "quality" was an anecdote. Corpus A closes that for the regression-net / harness-validity / Tier-1-ablation job; Corpus B (35-14) will close it for real SC1 evidence.
- **Input and reference cannot drift.** `FrameAblatedCorpusEmitterTests` is both the generator and the guard: it derives 31 reference blocks (`frame_ablated.expected.json`) from the tagged Frame fixture's entity groups, ablates those same groups into non-conforming nicknames, parses + serializes the result through the production `CanvasAnnotationParser` / `ComputgraphContextSerializer` path (`frame_ablated.context.json`), and asserts the freshly-regenerated output equals the committed files byte-for-byte. A fixture edit that would desynchronise the two fails the build, not the score.
- **Corpus A can never masquerade as Tier-0 evidence.** `tier0Evidence: false` is baked into the reference file as a field 35-13's harness must read and stamp `evidence: false` on any E0 row computed from it — because the wiring was authored by the same hand as the Tier-0 rules (35-05, commit `1492514`), scoring Tier 0 on it would be self-grading.
- **The block matcher's greedy shortcut is measured, not assumed.** `match_blocks` implements the AI-SPEC's exact 5-step rule (Jaccard, drop J=0, sort by `(-J, reference_block_id, proposal_index)`, greedy accept) and a unit test proves greedy equals a brute-force-optimal oracle on 3 small synthetic cases; a second test proves a J-tie for the same reference block logs a visible warning instead of resolving silently.
- **Every SC1 metric is an independently-tested function.** `m1_exact_rate`, `m2_near_rate`, `mean_jaccard`, `member_edit_distance`, `m5_segmentation` (ratio/fragmentation/fusion — the FM-4 over-segmentation catch), `nesting_agreement`, `silent_drop_count`, `abstention_recall`/`abstention_precision`, `grammar_citation_rate`, `confidence_spread_ok`, `brier_score`, `ece` (with per-bin counts, never a bare scalar), and `wilson_interval` — 48 tests across `test_recognition_scoring.py`, zero net-new dependencies (no scipy, no numpy).
- **A corpus refuses to score itself when unprovenanced or unfrozen.** `corpus.assert_provenance` rejects a result row missing any of the 8 required provenance fields or carrying `frozenAtCommit == "unfrozen"`; `corpus.assert_context_unchanged` recomputes the on-disk context file's SHA-256 and rejects a tampered/drifted context; `corpus.check_freeze_commit` flags (advisory) a `*.expected.json` staged alongside a change to the recognition prompt, the few-shot fixture, or `cg_topology.py`.

## Decisions Made

- **The generator is C#, not Python**, deviating deliberately from AI-SPEC's `scripts/build_frame_ablated.py` filename (the plan's own `plan_decisions` called this out in advance): the RawCanvas ⇒ cgContextJson v1 path lives entirely in `CanvasAnnotationParser` + `ComputgraphContextSerializer`, and a Python reimplementation would itself be a source of drift.
- **`frozenAtCommit` is pinned at true emit time and reused thereafter**, not recomputed from `git rev-parse HEAD` on every test run. This was necessary, not just tidy: recomputing it every run would make the golden-file byte-comparison fail starting with the very next unrelated commit to this shared tree, since HEAD advances regardless of what this test does. The emitter reads the value back from the already-committed reference file when one exists, and only calls `git rev-parse HEAD` when generating the file for the first time. `annotatedAt` is a fixed literal (`2026-07-08`, the date the tags were authored) for the same reason.
- **`publishable` is computed by actually calling `CanvasAnnotationParser.TryInferParameterDataType`** per parameter group, not hand-classified — this produced some non-obvious results worth recording: `11_Var_LenTotal`, `11_Var_HTotal`, `12_Var_HFooter`, `12_Var_FooterCount` (Number Sliders with no `slider` JSON property, unlike `11_Var_SpansCount`), `11_Const_ptZero` (Construct Point), `11_Const_vecY` (Unit Y), and 5 of the 11 line/curve-shaped `EmergentParam` groups all came back `publishable: false`, because the fixture's underlying components don't satisfy the parser's widget/primitive-param typing rules. This is Corpus A behaving exactly as designed — zero new human judgement, the parser's real classifier is the only arbiter.
- **`nesting_agreement`'s call contract is intentionally left open for 35-13.** `StructureProposal` (`cg_schemas.py`) carries no `hostBlockId` field, so the function takes an optional `proposal_index -> host_proposal_index` map the caller resolves however the eventual harness encodes nesting, defaulting to "every proposal is top-level" (vacuously `1.0`) when nothing is supplied.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — blocking issue] Data-service verify command run against the container's live `/mnt/repo` mount instead of the plan's literal `docker compose exec -T data-service python -m pytest tests/test_recognition_scoring.py -q`**
- **Found during:** Task 2/3 verification
- **Issue:** `data-service`'s Docker image bakes `/app` in at build time; it is not a live bind mount of the source tree (only `./data-service/data:/app/data` and a read-only `.:/mnt/repo:ro` are mounted). The running container had not been rebuilt since these new test-only files were added, so the plan's literal command failed with `file or directory not found: tests/test_recognition_scoring.py`.
- **Fix:** Ran the identical pytest invocation against the same container's already-available read-only `/mnt/repo` bind mount instead (`docker compose exec -T data-service sh -c "cd /mnt/repo/data-service && python -m pytest tests/... -q"`) — same interpreter, same installed dependencies, same test code, different working directory. Deliberately did **not** rebuild or restart the `data-service` container: another Claude Code session is actively using it concurrently (Phase 36, per this plan's shared-tree warning), and a rebuild/restart mid-session risked disrupting that work for a verification-only concern.
- **Result:** `tests/test_recognition_scoring.py` — 48/48 pass. Full `tests/` suite — 407/407 pass, 0 failed (no regressions).
- **Commits:** `0b0b0b7`, `66ee77e`
