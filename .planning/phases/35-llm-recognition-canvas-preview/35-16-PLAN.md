<objective>
Fix `CanvasAnnotationParser.ComputeHostPatternIds` so a pattern's host is resolved by *pattern-ness*, not by position in `RawCanvas.Groups`.

Purpose: today the lookup is `allGroups.FirstOrDefault(g => g.NestedGroupIds.Contains(nickname))`. A real Grasshopper extractor computes **transitive** containment, so a Procedure group legitimately lists every pattern inside it — including patterns nested one level deeper. When such a Procedure group appears earlier in `groups[]` than the true parent pattern, `FirstOrDefault` returns it, the `idByGroup` lookup fails (a Procedure is not a pending pattern), the code falls through to the strict-superset `MemberIds` fallback, finds nothing, and the nesting is **silently dropped** — `PATTERN_HOST_TO` never reaches Neo4j and the published Computgraph is flatter than the canvas.
Output: order-independent host resolution, with the order-independence itself under test.
</objective>

<plan_decisions>
- **Fix the selection, not the model.** The nesting model (`NestedGroupIds` naming a child's nickname, plus a strict-superset `MemberIds` fallback) is sound and UAT-proven. The defect is one `FirstOrDefault` that does not filter to candidate hosts. Restricting the search to groups that are themselves pending patterns is a one-expression change with no schema, serializer or publish impact.
- **Innermost wins when several patterns name the same child.** With transitive containment a child can be named by its parent *and* its grandparent. The correct host is the immediate one, so among pattern candidates prefer the one with the fewest `MemberIds` — the smallest enclosing pattern is the innermost. This also keeps the primary path consistent with the existing fallback, which already picks `OrderBy(p => p.Group.MemberIds.Count)`.
- **Non-pattern groups stop being candidates entirely.** A Procedure naming a pattern is real containment information, but it is not a *pattern* host; `HostPatternId` is by definition a pattern. Filtering them out is what makes the result order-independent.
- **The `MemberIds` strict-superset fallback is unchanged.** It still covers the case where no group's `NestedGroupIds` names the pattern at all (native GH nesting detected purely from member containment).
- **Order-independence is asserted, not argued.** A test shuffles `RawCanvas.Groups` across several permutations and asserts identical host assignments. A fix that merely reorders the fixture would pass a naive test; permuting the input is what actually proves the property.
- **No fixture change.** `frame-cg-context.json` lists only direct children (35-05's deliberate choice) and is already correct. This plan must not need to touch it — if it does, the fix changed behaviour it should not have.
</plan_decisions>
