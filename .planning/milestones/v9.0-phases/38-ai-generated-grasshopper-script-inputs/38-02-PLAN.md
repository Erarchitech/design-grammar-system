<objective>
Close JOIN A — the identity join between a Computgraph `Parameter` and the `ParameterId` that PARAMETER REINSTATE matches on — by capturing component input-param names on the canvas and deriving a `reinstateParameterId` at publish time.

Purpose: 38-RESEARCH.md §3.1 names this the single biggest unscoped risk in the phase. Today nothing forces the convention name of a Computgraph Parameter (`SpansCount`, from `11_Var_SpansCount`) to equal the NickName the architect typed on the PARAMETER STATE input. If they differ, a generated candidate is well-formed, passes every validator, and then silently no-ops on reinstate — the worst possible failure shape. The derivation is only possible if the canvas capture knows input-param names, and it currently does not: `CgNode.Nickname` is the *component's* nickname and `CgWire.ToParam` is a bare instance GUID.

Output: an additive `InputParams` list on `CgNode` with round-trip coverage, and a `reinstateParameterId` property persisted on every resolvable `:Parameter` node at publish.
</objective>

Add `derive_reinstate_parameter_ids(cg_context: dict) -> dict[str, str]` to `data-service/computgraph_publish.py`. It maps Computgraph parameter `cgId` to the resolved reinstate id.

The walk, for each `Parameter` in the context:
1. Collect the parameter's `memberIds` — the slider component instance GUIDs it groups.
2. Find every wire in `cg_context["raw"]["wires"]` (use the actual key path present in the parsed envelope) whose `fromNode` is one of those member ids.
3. For each such wire, take `toNode` and `toParam`; look up the node with `instanceId == toNode` in `cg_context["raw"]["nodes"]` and find the entry in its `inputParams` whose `instanceId == toParam`.
4. Only accept the match when the destination node is a PARAMETER STATE component. Identify it by its `componentGuid` — read the literal GUID from `ParameterStateComponent`'s `ComponentGuid` override and define it as a module-level constant `PARAMETER_STATE_COMPONENT_GUID` with a comment naming the source file, so the string exists in exactly one place.
5. The resolved value is that input param's `nickname` when non-blank, else `param_{index}` — mirroring `ParameterStateComponent.cs:68-71` exactly, including the `.Trim()`.

Resolution rules, stated as behaviour not preference:
- **Zero matches → omit the parameter from the returned dict.** The property is then simply absent on the node. Never write an empty string, never fall back to the convention name (D-04: a guessed value would surface only as a ReStatus miss at apply time).
- **More than one distinct resolved value for one parameter → omit it as well**, and log a single redacted warning naming the `cgId` and the competing values. An ambiguous join is not a join.
- The function must never raise: an unparseable context returns an empty dict.

Then extend the publish path:
- Call `derive_reinstate_parameter_ids` once while `parameterRows` is being assembled and set `row["reinstateParameterId"]` to the resolved value or `None`.
- Add `p.reinstateParameterId = row.reinstateParameterId` to the `SET` list in `_publish_parameters`, placed immediately after `p.dgId`. Setting a Cypher property to `null` removes it, which is exactly the intended "absent" semantics for an unresolved parameter — no branching needed.

Finally, extend the Frame context fixture in `data-service/tests/cg_fixtures.py` so its raw nodes carry `inputParams` and at least one wire runs from a slider member to a PARAMETER STATE input whose nickname differs from the parameter's convention name. That divergence is the whole point of JOIN A and the fixture must exercise it rather than the trivially-equal case.
