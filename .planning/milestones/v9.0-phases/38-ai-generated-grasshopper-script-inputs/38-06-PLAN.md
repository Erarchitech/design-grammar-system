<objective>
Add the candidate review surface to the ui-v2 Model screen: generate candidates for a rule, read them as rows with parameters as columns, see honestly what the system can and cannot claim, and accept one — with acceptance as the only action that writes anything.

Purpose: GHIN-04 and SC3 require generation and application to be strictly separated, and the architect is the separator. The UI is where that separation becomes an observable behaviour rather than an architectural claim. It is also where D-09's honesty requirement is either honoured or quietly lost — a satisfied-looking badge on a geometry-required rule would undo the whole determinability apparatus built in plan 38-03.

Output: an API client module, a candidate table component, and a panel wired into the existing Model screen.

Note: this phase was planned with `--skip-ui`, so no UI-SPEC.md exists. The visual contract is therefore "reuse the Model screen's existing idiom exactly" — the primitives, the Panel grouping, and the row/tile vocabulary already on that screen. Do not introduce a new visual language.
</objective>

Layout — one row per candidate, one column per bound parameter, following the DSE convention:

- `undeterminable` → a **neutral** `Badge` reading `not checkable from parameters` plus the `basis` text. Add a code comment naming D-09 and stating why: claiming satisfaction for a geometry-level rule would be a fabrication.

When `determinabilityClass === "geometry-required"`, render a `Callout` above the table stating that this rule depends on geometry and candidates are proposals only — the per-row neutral badge alone is too easy to skim past.

Actions cell: an `Accept` `Button` and a `Reject` `Button`. `Accept` is disabled while `busyCandidateId` matches, and replaced by a static accepted indicator when the candidate's derived state id is in `acceptedStateIds`. `Reject` calls `onReject` only — the component must contain no fetch, no API import, and no write of any kind. Add a comment stating that rejection is a local dismissal because rejected candidates leave no trace (D-19).

Export it from the `display` group in `ui-v2/src/components/index.js`, keeping the file's alphabetical-within-group ordering.
