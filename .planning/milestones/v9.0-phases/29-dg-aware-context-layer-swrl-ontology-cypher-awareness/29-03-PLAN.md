<objective>
Implement the deterministic context assembler (`assemble_context`) and wire the two CONTEXT.md-locked endpoints — `POST /context/assemble` and `GET /context/debug` — into app.py. This is the CTXA-01 + CTXA-05 core: prompt assembly injects the relevant V7 ontology concept subset (per layer), SWRL conventions, and selected Cypher catalog shapes, deterministically, with the debug endpoint returning exactly what assemble returns.

Purpose: Move all prompt-construction logic out of n8n's inline Function nodes (Build LLM Prompt / Build Cypher Prompt / Fetch Existing Entities / Smart Overrides) into one testable Python function.

Output: `assemble_context()` + `ContextAssembleRequest`/response models in dg_context.py; `/context/assemble` and `/context/debug` routes in app.py; `TestContextAssemble` + `TestDeterminism` in the test file.

## Resolved decisions carried by this plan

- **Pitfall 3 (Rule_Id edit-convention conflict) — RESOLVED.** The `rule_edit` context type documents the EXISTING convention: because the limit is embedded in `Rule_Id` by the `R_<DOMAIN>_<PROPERTY>_<LIMIT>_V` format, a numeric-threshold edit REGENERATES the Rule_Id and relies on the old-atom/old-Rule MATCH-DELETE cleanup (as n8n's "Prepare Graph Payload" already does). CONTEXT.md's "preserve iri/SWRL_label, change only Literal values" is scoped to the ONTOLOGY entities (Class/DatatypeProperty/ObjectProperty are matched by iri and their SWRL_label reused — never regenerated) and to the metagraph atom semantics (only Literal.lex changes for a threshold edit); it does NOT freeze Rule_Id, which is a derived key encoding the threshold. This keeps RING-02's (Phase 31) old-atom MATCH-DELETE diff-preview design applicable unchanged. A checkpoint:human-verify at the end of this plan confirms the edit-guidance text before it propagates downstream.

This plan depends on 29-01 (catalog loader) and 29-02 (SWRL + Computgraph blocks).

**Decisions honored (29-CONTEXT.md):** D-01 (new POST /context/assemble endpoint called before /llm/generate), D-02 (three request types: rule_ingest/rule_edit/graph_query), D-03 (deterministic keyword/entity matching for subset selection, no embeddings), D-04 (GET /context/debug shares the assemble code path), D-17 (static V7 catalog unioned at request time with a live Neo4j query for existing entities).
</objective>
