<objective>
Close the Phase 29 UAT Success Criterion 4 gap: a natural-language design-state
graph query returns "no design states were found" for ConfigurationC even though
they are visible in the Model Viewer.

Root cause (see 29-UAT.md + debug session): `dg_context.py` feeds the LLM an
aspirational Validgraph schema (`VALIDGRAPH_CONCEPTS.node_labels = [DesignState, Run]`)
and a matching `validate_cypher()` allow-list, but the real shipped write path
(`app.py store_validation_run()`) MERGEs a single `:ValidationRun` node per run and
serializes the whole design-state snapshot into `run.statePayloadJson`. No `:DesignState`
nodes exist for live runs, so the LLM's schema-correct `MATCH (:DesignState ...)` query
executes cleanly and returns zero rows.

This plan applies the smaller, immediate fix (direction "a" from the debug session):
converge `dg_context.py`'s Validgraph schema + validator allow-lists to the real
ValidationRun/statePayloadJson/HAS_ENTITY shape, and add a live per-project
existing-design-states helper (analogous to the existing `fetch_existing_entities()`,
D-17) so the assembled graph_query context carries real ValidationRun data the LLM can
reason over.

Purpose: Make the LLM generate a Cypher query that actually hits live data.
Output: Corrected `VALIDGRAPH_CONCEPTS`, corrected `validate_cypher()` allow-lists,
new `fetch_existing_design_states()` + `_summarize_state_payload()` helpers wired into
`assemble_context()`, plus regression tests.

FLAGGED BACKLOG (do NOT implement here): direction "b" — converging
`store_validation_run()` to also materialize first-class `:DesignState` graph nodes to
match CLAUDE.md's canonical v4/v7 schema table and the migration apparatus. That is a
schema/data-model decision affecting existing production data, the Grasshopper publish
path, and other ValidationRun consumers; it needs explicit human sign-off and its own
phase, per CLAUDE.md's guidance that hard-to-reverse architectural decisions get surfaced,
not auto-executed. Record it as a backlog item; do not add it as a task.
</objective>
