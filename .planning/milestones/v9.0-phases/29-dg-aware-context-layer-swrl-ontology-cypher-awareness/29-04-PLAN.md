<objective>
Implement the Cypher validator (`validate_cypher`) and the bounded retry loop (`generate_validated_cypher`), and expose the single n8n-facing wrapping endpoint `POST /context/generate-cypher`. This is CTXA-04 and the phase's primary security control (V5 Input Validation): no LLM-generated Cypher reaches Neo4j `tx/commit` until it passes schema + verb-policy validation.

Purpose: Replace n8n's ad hoc, untested "Parse LLM Output" / "Parse Cypher" JavaScript checks with a pytest-covered Python validator, and give n8n one call that returns valid Cypher or a final structured error — intermediate retry attempts stay invisible to n8n.

Output: `validate_cypher()` (importable pure function, no standalone HTTP surface), `generate_validated_cypher()` retry orchestrator, `POST /context/generate-cypher` route, and `TestValidator` + `TestRetryLoop`.

## Resolved decision carried by this plan

- **Open Question 1 (endpoint shape) — RESOLVED.** There is exactly ONE new n8n-facing endpoint: `POST /context/generate-cypher` wrapping prompt-in → validated-cypher-out (assemble is separate, per plan 29-03). `validate_cypher()` is a plain importable function called both by this endpoint and directly by pytest — no separate `/context/validate` HTTP surface is added (CONTEXT.md is explicit that "n8n makes one call"). Testability comes from the function, not an endpoint.

This plan depends on 29-03 (assembler + endpoint scaffolding + dg_context module surface).

**Decisions honored (29-CONTEXT.md):** D-05 (validation as a new data-service function/endpoint), D-06 (data-service retries internally with corrective feedback; n8n makes one call), D-07 (bounded retry: 2 retries, 3 attempts total), D-08 (structured violations `{valid, violations:[{code,message,path?}]}`).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM output → Neo4j tx/commit | The critical boundary: hallucinated/malformed Cypher must be blocked by validate_cypher before n8n ever POSTs to Neo4j |
| user rules_text/question → LLM prompt → Cypher | Prompt injection: rule text crafted to make the LLM emit destructive Cypher (DELETE/DETACH/DROP) outside the MERGE/SET allow-list |
| retry loop → LLM gateway adapter | In-process adapter reuse; the master secret is resolved once via resolve_active_provider and never logged into violation messages |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-01 | Tampering | validate_cypher (LLM-Cypher reaching Neo4j) | high | mitigate | Whitelist label/relationship/property + bracket-nesting gate rejects malformed/hallucinated Cypher before tx/commit (CTXA-04); TestValidator proves each rejection |
| T-29-02 | Tampering / Elevation of Privilege | verb-policy check (prompt injection via rules_text) | high | mitigate | Request-type-aware verb allow-list: ingest/edit → only MERGE/SET (reject DELETE/REMOVE/DETACH/DROP); graph_query → read-only (reuse is_write_query precedent). Hard validation failure, not just an unknown-label warning |
| T-29-03 | Information Disclosure | violation messages | low | accept | /context/* are internal n8n→data-service routes; no secrets flow through Cypher; master secret never appended to violation feedback |
| T-29-04 | Denial of Service | retry loop | medium | mitigate | Hard bound of 2 retries (3 attempts); TestRetryLoop asserts ≤3 adapter calls so a persistently-failing LLM cannot loop unbounded |
| T-29-SC | Tampering | pip installs | low | accept | Zero new packages (RESEARCH Package Legitimacy Audit: N/A) |
