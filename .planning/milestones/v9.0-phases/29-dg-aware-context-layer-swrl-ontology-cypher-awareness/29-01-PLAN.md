Each object has keys `id`, `name`, `description`, `swrl_pattern` (the SWRL atom pattern in violation-inverted body form), `cypher_template` (the parameterized MERGE/SET Cypher producing Rule/Atom/Var/Literal/Builtin nodes), and `worked_example` (a fully concrete instantiation).

    The six shapes, ids exactly: `max_limit`, `min_limit`, `range`, `ratio`, `boolean_requirement`, `existence_count`.
    - `max_limit`: Rule_Id format `R_<DOMAIN>_<PROPERTY>_MAX_<LIMIT>_V`; body atoms fire when the measured value EXCEEDS the limit (violation-inverted), using a `swrlb:greaterThan` Builtin atom against a Literal threshold. Worked example: "maximum building height 75 m" → `R_URB_HEIGHT_MAX_75_V`.
    - `min_limit`: mirror of max_limit with `swrlb:lessThan`; Rule_Id `..._MIN_<LIMIT>_V`.
    - `range`: PRESERVE the existing two-separate-violation-rules convention (per CONTEXT.md and cypher_template.txt SEMANTIC MAPPING) — the single `worked_example` documents the min-rule + max-rule PAIR together as two Rules, not one combined rule. No new schema shape.
    - `ratio`: two DatatypeProperties related by a `swrlb:divide` Builtin plus a comparison Builtin against a Literal.
    - `boolean_requirement`: a Boolean DatatypeProperty that must equal a required value; body fires when it does not (violation-inverted).
    - `existence_count`: NEW territory — model as a `swrlb:` Builtin atom pair against a `Literal` threshold, reusing ONLY the documented node labels (Class, DatatypeProperty, ObjectProperty, Rule, Atom, Var, Literal, Builtin) and relationships (HAS_BODY, HAS_HEAD, REFERS_TO, ARG). Introduce NO new node labels or relationship types. CRITICAL (Pitfall 1): every `Var` MERGE in `cypher_template` and `worked_example` MUST key on `name` + `project` (e.g. the merge clause includes both a `name` and a `project` property) — omitting `project` reintroduces the historical cross-project Var collision bug.

    All Cypher in `cypher_template`/`worked_example` uses only MERGE and SET (per cypher_template.txt OUTPUT RULES), keys Rule nodes on `Rule_Id`, Atom nodes on `Atom_Id`, uses `SWRL_label` (not `label`) for DatatypeProperty display, and backtick-quotes the reserved relationship-property words `order` and `pos`.
