<planning_decisions_recorded_here>
The three "Open for planning" items from `37-CONTEXT.md` and the two questions `37-RESEARCH.md` left open are resolved as follows. Task 1 and Task 2 write these into the specs; every later plan implements them.

1. **Rule-mapping file location and shape** - `llm/structure_rules.json`, file-first, sibling to `llm/cypher_catalog.json`. Envelope `{"version": <int>, "mappings": [{"ruleId", "operation", "params", "description"}]}`, loaded by a defensive loader that never raises. Adopted from 37-RESEARCH.md Open-for-Planning Item 1.
2. **Severity taxonomy** - reuse the existing SHACL mapping verbatim: `violation` / `warning` / `info`, with the same colour mapping already in `spec/RULE-PARTITION-POLICY.md`. `violation` for structural breakage, `warning` for a failed rule-mapped requirement, `info` for annotation-convention normalization. Adopted from 37-RESEARCH.md Open-for-Planning Item 2.
3. **Persist vs ephemeral** - ephemeral for MVP. No `Run`-like node is written; `POST /computgraph/validate` recomputes on every call. Overloading the existing `Run` node would conflate a BIM design-state run with a script-structure snapshot. Adopted from 37-RESEARCH.md Open-for-Planning Item 3.
4. **Partition-policy placement** (37-RESEARCH.md Open Question 1) - a lighter addendum, NOT a new numbered `D-` decision. No 37-CONTEXT.md decision letter maps to this point, so implying a formal governance decision would be inaccurate.
5. **The two currently-unreachable defensive checks** (37-RESEARCH.md Open Question 2) - keep both `parameter_without_datatype` and `object_without_behavior` in SVAL-01 scope. Cost is a few lines of Cypher each; they guard against a future publish-path refactor or a graph mutated outside the publish path.
6. **Report surface scope** (operator scope fence: lowest-cost option wins) - the report surface is the documented JSON contract in `spec/API.md`, pinned by a contract test. The GH-panel print is DEFERRED and named: it requires a new handler in the Grasshopper-side canvas command dispatcher, a new component, a dotnet rebuild, and live-Rhino verification - disproportionate for an MVP whose report is already consumable over plain HTTP. Record it in the summary as a named deferral, not a silent omission.
7. **`definitionId` optionality on validate** - when omitted, resolve the project's published definitions: exactly one -> use it; zero -> 422 `COMPUTGRAPH_VALIDATE_NO_DEFINITION`; more than one -> 422 `COMPUTGRAPH_VALIDATE_AMBIGUOUS_DEFINITION` with the available ids in the hint. This keeps the report single-shaped instead of branching between a per-definition and an aggregate form.
8. **Determinism and `checkedAt`** - `findings` and `ruleResults` must be byte-identical across repeated calls for an unchanged graph; `checkedAt` is the single permitted varying field and the determinism test excludes it.
9. **`namePattern` semantics** - a case-sensitive substring evaluated through a bound Cypher parameter, never a glob and never a regex. The asterisks in 37-CONTEXT.md's prose are markdown emphasis, not syntax.
</planning_decisions_recorded_here>
