Each entity in the assembled structure carries its `cgId`, its published display name, and a `conventionName` derived from the cgId's last segment. This derivation is load-bearing and must not be skipped: the publish path writes only the bare name onto the display-name property, so the convention token an architect actually reads on canvas exists nowhere else in the graph. `entityNames` is the grounding vocabulary: the sorted, deduplicated union of every entity's display name and convention name across the whole subgraph. `entityCount` is its length before truncation. When the entity count exceeds the cap, retain the first entities in the deterministic order the queries produced, set `truncated` to true, and leave `entityCount` reporting the untruncated total so a consumer can see what was dropped.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client -> Cypher | `project` and `definitionId` arrive untrusted and scope every subgraph read |
| HTTP client -> prompt | `question` is attacker-controllable text embedded in a prompt sent to a model |
| model -> data-service | The model's answer text re-enters the service and is returned to the caller |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37-01 | Tampering | Cypher injection via `project` / `definitionId` reaching the subgraph queries | high | mitigate | Both new query literals bind every scoping value as a Cypher parameter and are never interpolated; Task 1 acceptance requires both bound placeholders on every node in the pattern |
| T-37-02 | Spoofing | Prompt injection via `question` - making the model assert facts absent from the graph, or exfiltrate the guidance block | medium | mitigate | The question is rendered inside a clearly delimited block explicitly labelled untrusted, after the guidance rather than before it; the grounding post-check flags any convention-shaped token absent from the subgraph; and the endpoint has no execute path at all, so a successful injection yields at worst a flagged, ungrounded text answer. Task 3 pins the containment with a test asserting injected instruction text stays inside the delimited block |
| T-37-03 | Information Disclosure | Cross-project data leakage - a question about project A answered from project B's script | high | mitigate | `fetch_computgraph_subgraph` binds both `project` and `definitionId` on every node in both patterns; Task 3's integration tier asserts an unknown project produces a prompt containing none of the fixture project's entity names, asserted by name |
| T-37-04 | Denial of Service | An unbounded subgraph producing a prompt large enough to exhaust the provider's context or the request budget | low | mitigate | `CONSULT_MAX_ENTITIES` caps the entities entering the prompt; the response reports `truncated` and the untruncated `subgraphEntityCount`, so truncation is visible rather than silent |
| T-37-12 | Elevation of Privilege | Model output being executed as Cypher or written to the graph | high | mitigate | The consult pipeline contains no execute and no write path; the answer is carried through as text. `spec/API.md` states the read-only guarantee normatively (plan 37-02) and Task 2 acceptance requires the module's only new queries to be the two read-side subgraph fetches |
| T-37-SC | Tampering | npm/pip/cargo installs | low | accept | Zero new packages (37-RESEARCH.md Package Legitimacy Audit: not applicable - the in-process gateway, `neo4j`, `fastapi` and `pydantic` are already pinned in `data-service/requirements.txt`). No install task exists in this phase, so no legitimacy checkpoint is required |
