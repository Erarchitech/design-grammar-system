## Wire Contract (LOCKED — identical to Plan 01; restated so this side agrees byte-for-byte)

- Request line: `{"type":"<command>","parameters":{ ... }}` — UTF-8, `\n`-terminated, BOM-tolerant, one client at a time.
- Response line: `{"bridge":"dg","version":1,"status":"ok","result":<payload>}` or `{"bridge":"dg","version":1,"status":"error","error":{"message":...,"code":...}}` — single line, no BOM, `\n`-terminated.
- `get_canvas_context` result = cgContextJson v1 document as a nested JSON object; `get_selection` result = `{"selection":[...]}`; preview commands = `{"supported":false,...}` stub.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker container / any localhost process → TcpListener | Unauthenticated newline-JSON crosses the loopback socket into the Rhino process carrying design IP (canvas structure). |
| background accept-loop thread → Rhino UI thread | Canvas reads must cross onto the UI thread; the socket write must NOT. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-01 | Information Disclosure | TcpListener bind scope | high | mitigate | Bind `IPAddress.Loopback` only; never `IPAddress.Any`. Loopback traffic bypasses the Windows Firewall inbound path, so the canvas/design IP is never exposed to the LAN. Verified by the no-`IPAddress.Any` source assertion + Plan 04 live check. |
| T-33-04 | Denial of Service (resource exhaustion / port leak) | listener lifecycle | high | mitigate | Dedup on (Run,Port) + `TcpListener.Stop()` in both the Run=false branch and RemovedFromDocument, mirroring ConnectorComponent's try/finally disposal. Verified by dual-StopListener source assertion + Plan 04 repeated on/off check. |
| T-33-02 | Denial of Service | accept loop resilience | high | mitigate | Per-client try/catch that logs and continues; malformed lines routed to a BAD_REQUEST envelope by the dispatcher (Plan 01), never propagated to crash the loop. |
| T-33-03 | Denial of Service (single-client starvation) | accepted client read | medium | mitigate | `client.ReceiveTimeout` bounds a stuck client so the single-client slot is released; the loop returns to AcceptTcpClientAsync. |
| T-33-07 | Information Disclosure | unauthenticated bridge | medium | accept | Unauthenticated by design (CONTEXT: "No secrets over the bridge"); the sole access control is the 127.0.0.1 bind (ASVS V4 Partial — network-topology control, documented not gap). No auth added in v9.0. |
| T-33-SC | Tampering | package installs | low | accept | Zero new packages — only BCL `System.Net.Sockets`/`System.Text.Json`/`System.Threading` and already-referenced RhinoCommon. No install gate needed. |
</threat_model>
