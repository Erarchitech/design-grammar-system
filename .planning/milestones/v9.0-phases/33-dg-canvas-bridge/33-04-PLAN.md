What Claude built: the DG CANVAS LISTENER component (Plan 02) + data-service `POST /computgraph/context/pull`, the 4 `gh_*` MCP tools, and `gh_bridge.py` (Plan 03), wired end-to-end over a real loopback socket. Everything automatable (unit/integration suites, Release build) is already green; only the live Rhino round-trip remains, which cannot be automated in this repo's CI.

Prerequisites: Rhino 8 + Grasshopper open with the DG plugin loaded; `docker compose up -d` running the rebuilt data-service; a Grasshopper document with at least one DG-annotated procedure (any Frame-style canvas from Phase 32 fixtures works). Place a DG CANVAS LISTENER component on the canvas.

1. Set Port=8720, Run=true. Confirm the component's Status output reads a live/listening state and Grasshopper stays responsive (drag an unrelated slider — the listener must NOT flicker or restart; dedup check).
2. From inside the Docker network run: `docker compose exec data-service curl -s -X POST http://localhost:8000/computgraph/context/pull -H "Content-Type: application/json" -d '{"project":"p1"}'`. EXPECT: HTTP 200 and a cgContextJson v1 body (has documentId/procedures) with `"project":"p1"` stamped. (Success criterion 1.)
3. From the same shell, POST to `/mcp` with `{"jsonrpc":"2.0","id":1,"method":"tools/list"}` and confirm the tools array lists gh_get_context, gh_get_selection, gh_preview_structure, gh_clear_preview. Then call `tools/call` with name gh_get_context and arguments `{"project":"p1"}` and confirm `result.data` matches the document from step 2. (Success criterion 2.)
4. While the pull from step 2 is running, confirm the Rhino UI does not freeze (move the viewport / a slider). (Success criterion 4 — UI thread never blocks.)
5. Set Run=false (or close Rhino) and repeat the step-2 curl. EXPECT: a fast (within ~5-35s bounded budget, not an indefinite hang) structured error with code GH_BRIDGE_UNREACHABLE and the What+Where+How-to-fix hint. (Success criterion 3.)
6. Toggle Run false→true→false→true several times, each time re-running step 2. EXPECT: no `SocketException: Address already in use`, and the port is released each time Run=false (check with `netstat -ano | findstr 8720` on the host — nothing listening after Run=false). (Success criterion 4 — no port leak.)
