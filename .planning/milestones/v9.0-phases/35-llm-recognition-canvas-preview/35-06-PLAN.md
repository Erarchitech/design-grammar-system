<objective>
Add `data-service/cg_schemas.py`: the Pydantic v2 output contract for the proposed-structure object, plus `to_strict_json_schema()` — the adapter that turns Pydantic's JSON Schema into the restricted subset OpenAI-strict and Anthropic actually accept.

Purpose: gives Tier 1 a typed output shape that provider-native constrained decoding can enforce, and gives the retry loop a `schema_violation` code that names the offending field. Pydantic guarantees the *shape*; `validate_proposed_structure()` keeps guaranteeing the *safety*.
Output: a new schemas module + unit tests, with zero net-new runtime dependencies.
</objective>

<plan_decisions>
- **Field descriptions are prompt surface, not documentation.** Under provider-native structured outputs the schema's `description` strings are shown to the model. `suggestedName`'s description must state *"the name to CREATE… it is NOT expected to match the node's existing nickname"* and `rationale`'s must state *"cite GRAPH EVIDENCE… do NOT cite the naming grammar"* — these carry AI-SPEC §4b.2's grammar-anti-filter framing into the one place a strict-mode model definitely reads. Verbatim wording is in AI-SPEC §4b *Structured Outputs with Pydantic*.
- **Both kind spellings stay legal.** `ProposalKind` is a `Literal` over all twelve strings (`Proc`/`Procedure`, `Pat`/`Pattern`, `Var`/`VariableParam`, `Const`/`ConstantParam`, `Emg`/`EmergentParam`, `IntF`/`Interface`) — the exact set already in `cg_recognition.ALLOWED_PROPOSAL_KINDS`. Narrowing to one spelling would break either the C# `ToEntityTagKind()` short names or the catalog's long names the prompt teaches. `Algorithm` stays absent: proposals are group-level entities only.
- **`unrecognized` is `required` in the wire schema but defaults to `[]` in Python.** OpenAI strict mode expresses optionality as a null-union, never by omission — so every property must appear in `required`. This is the single most common cause of a 400 from strict mode and gets its own test.
- **Pinned as `pydantic>=2.7,<3` in requirements.txt.** The AI-SPEC flags this as a judgement call ("if the team's convention is transitive-deps-stay-undeclared, skip it"). Taking it: `llm_gateway.py:22` already does `from pydantic import BaseModel` directly, so the dependency is real and undeclared today, and the upper bound pins out a future FastAPI that ships Pydantic v3 — under which every `model_config` / `model_validate` / `model_json_schema` call in this phase changes meaning.
- **No `scipy`/`numpy`/`jsonschema` and no new package beyond the truthfulness fix.** AI-SPEC §2: net-new runtime dependencies zero.
</plan_decisions>

  <files>data-service/cg_schemas.py</files>
  <read_first>

  </read_first>
  <action>
    Add `to_strict_json_schema(model: type[BaseModel]) -> dict` to `cg_schemas.py`. Start from `model.model_json_schema()` and apply five transformations, each with a comment naming why:

    1. **Inline `$defs`** and resolve every `$ref` — Anthropic rejects external `$ref` and OpenAI's nested-`$defs` handling is version-sensitive. Flatten; the schema is small enough that flattening costs nothing.
    2. **Force `"additionalProperties": false`** on every object node, recursively — assert it rather than trusting `extra="forbid"` to have emitted it everywhere.
    3. **Force every key of `properties` into `required`**, recursively. `unrecognized` must be required despite defaulting to `[]` in Python.
    4. **Strip unsupported keywords** recursively: `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `minLength`, `maxLength`, `pattern`, `minItems`, `maxItems`. Pydantic's `ge=0.0`/`le=1.0` on `confidence` emits `minimum`/`maximum`; the bound is not lost because `model_validate()` still enforces it after parsing.
    5. Return a deep copy — never mutate Pydantic's cached schema object.

    Document in the function docstring that the emitted schema is **deliberately weaker** than the model, and that this is the intended three-layer split.
  </action>
  <verify>
    <automated>docker compose exec -T data-service python -m pytest tests/test_cg_schemas.py -q</automated>
  </verify>
  <acceptance_criteria>
    - `to_strict_json_schema(ProposedStructure)` returns a dict containing no `$defs` key and no `$ref` anywhere (recursive check)
    - Every object node in the returned schema has `additionalProperties is False`
    - For every object node, `set(node['required']) == set(node['properties'])` — including the root, where `unrecognized` is present in `required`
    - The returned schema contains none of: `minimum`, `maximum`, `minLength`, `maxLength`, `pattern`, `minItems`, `maxItems`
    - `ProposedStructure.model_json_schema()` still contains `minimum`/`maximum` afterwards (the emitter did not mutate Pydantic's cached schema)
  </acceptance_criteria>
