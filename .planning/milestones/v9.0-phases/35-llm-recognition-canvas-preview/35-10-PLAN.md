<objective>
Add `data-service/cg_topology.py` — Tier 0 of the hybrid: deterministic scope resolution, topology feature extraction, a rule classifier over those features, an order-stable merge, and the output-token budget function. No LLM, no network, no nondeterminism.

Purpose: the architecture change that is the substance of the AI-SPEC. Topologically-determined roles move out of the LLM's hands entirely, which removes the numerous, boring parameter-role nodes from the prompt — the primary defence against the F1 truncation class, at zero token cost — and closes UAT F2's silent scope widening at its source.
Output: a new pure-Python module plus per-rule unit tests, including the C#-parity table and the merge order-stability test.
</objective>

<plan_decisions>
- **The rule table is AI-SPEC §4's R1–R6 verbatim, including each rule's stated deferral condition.** R1: `in_degree == 0` and `widget_kind in {Slider, ValueList, Boolean}` ⇒ `Var`. R2: `in_degree == 0`, `out_degree > 0`, `widget_kind in {Panel, None}` ⇒ `Const` — **but defer when the node shares an untagged group with ≥ 1 other node**, because that is Pattern evidence. R3: `out_degree == 0` and `in_degree > 0` ⇒ `Emg`, with the same group-membership deferral. R4: `in_degree == 1`, `out_degree == 1`, `widget_kind == None`, and `name` starts with `Param` ⇒ `IntF` — restricted to bare `Param` components on purpose; a general pass-through rule would swallow ordinary single-in/single-out compute nodes, which are Pattern members. R5: fully isolated ⇒ abstain. R6: everything else ⇒ abstain.
- **`Const` is not restricted to widgets.** Frame's constants include `Construct Point` and `Unit Y`, so `widget_kind == None` must not disqualify R2. That is why R2 carries the group-membership deferral instead of a widget requirement.
- **Parity with C# is a test, not a comment.** A table-driven test enumerates the `ClassifyNodeKind` branches from `CanvasAnnotationParser.cs:557-605` and asserts the Python `widget_kind` returns the same label for each. If a case cannot be mirrored, the rule must abstain on it and a test must prove the abstention — a Python `Const` on a component C# types as `None` is exactly the UAT F5 detonation path.
- **`empty_procedure` is a field on the scope result, not an exception.** 35-12 turns it into the `empty_procedure_scope` violation (G9) with a user-actionable message. Returning a value keeps `cg_topology` free of the violation vocabulary and keeps the module exception-free.
- **`merge()` order contract:** Tier-0 decided rows first in a deterministic order, then Tier-1 proposals in the order the model returned them. Tier-0 rows sort by `(procedureIndex, kind, memberIds[0])`. This is G13 — array position is identity across the bridge.
- **`adjacent_tagged_procedures` reuses the existing one-hop wire-adjacency logic** already written in `_filtered_untagged_node_ids` (`cg_recognition.py:481-489`) rather than inventing a second traversal. 35-12 then deletes the old copy.
- **The module reads `componentGuid` but the prompt shows a derived `widget=` token.** The GUID is stable per component *type* and is the most reliable widget signal available (pitfall 7), but it is opaque and costly in tokens; Tier 0 consumes it, the prompt renders the derived label.
- **`nestedGroupIds` is absent from the serialized `untagged` DTO** (`ComputgraphContextSerializer.cs:243-250`) even though the raw canvas carries it. Feature extraction must not depend on nested untagged groups.
- **Expect Tier 0 to look weak on Corpus A and that is correct.** AI-SPEC §4's "hard, uncomfortable caveat": the wiring in the Frame fixture is authored by the same hand as these rules, so Corpus A's reference is stamped `tier0Evidence: false` and E0 numbers from it are printed but excluded. Write the rules; expect the first honest measurement from Corpus B.
</plan_decisions>
