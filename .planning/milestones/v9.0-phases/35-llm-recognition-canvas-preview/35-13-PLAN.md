<plan_decisions>
- **pytest, not promptfoo, not Phoenix.** promptfoo would add a Node toolchain to a Python service; Phoenix is a docker-compose service aimed at production tracing rather than offline scoring, and it would put the architect's canvas in a second place outside git. The existing suite already contains the `_FakeAdapterForRetry` precedent proving the pattern — no live LLM in the default path. Zero net-new dependencies.
- **Arms are configurations injected at the adapter and artifact boundary, never a forked pipeline.** An arm supplies: which few-shot fixture content to use, whether a system prompt is set, whether Tier 0 runs, which provider/model, and whether structured output is negotiated. A0/A0f need the *as-shipped* prompt — the pre-35-08 fixture and the no-system-prompt condition — so the arm loader reads those from git (`git show <pre-35-08-sha>:data-service/fixtures/frame_recognition_fewshot.json`) into a temp path rather than expecting them in the working tree. Fork-free is what makes A2-vs-A3 a real ablation instead of two different programs.
- **A0 runs first and is the harness's own validity test.** A0 must reproduce F3 — near-zero M1 with a non-zero `grammar_citation_rate`. *If A0 does not fail that way, the harness is wrong, not the model,* and no other arm's number is trustworthy. The harness encodes this as an explicit assertion, not a note.
- **Replay is the default and a miss is a loud failure.** `RECOGNITION_EVAL_MODE` ∈ `replay` (default, $0, no secrets) | `record` (live, writes cassettes) | `live` (live, writes nothing). A cassette miss in replay mode raises with the missing key and the exact refresh command. Falling through to a live call on a miss is the failure mode that turns a free CI gate into a metered one.
- **Never assert byte-identical model output anywhere.** `temperature=0` is *near*-deterministic, not deterministic — batching and MoE routing still jitter. Replay is exactly reproducible because it is a file read; re-recording is not. Every cassette refresh is its own commit carrying `recordedAt`, and must be reported with the metric delta against the recording it replaced.
- **The SC1 gate lives in the harness as a conjunction with a `--sc1-gate` threshold defaulting to 0.60.** Not the ROADMAP's bare "majority" (>0.50): at *n* ≈ 30 blocks the Wilson 95% interval around `p̂ = 0.60` is roughly [0.42, 0.75], so 0.53 and 0.47 are statistically indistinguishable and a 0.51 gate is decided by sampling noise. 0.60 is the smallest threshold clearing "majority" by more than one block's worth of noise at that *n*. The stricter **claim** threshold (Wilson lower bound > 0.50, i.e. 21/30 or 0.60 at n ≥ 100) is computed and reported separately — the ship gate and the dissertation claim are different questions.
- **E4-name and E7-soft are reported as uncalibrated and excluded from SC1.** They need an LLM judge, and the judge must clear ≥ 0.7 agreement on ≥ 20 human-labelled examples first (35-15 territory at the earliest). Building the judge now would produce a number nobody should use.
- **The example-order sub-sweep is a `--permutations` option, defaulting to 1.** Lu et al. show permuting the same demonstrations swings accuracy from near-SOTA to near-chance. The full 3-permutation sweep is a live-mode run (35-15); the plumbing lands here so it is not retrofitted later.
- **Deliberately out of scope, and stated so the omission is not read as coverage:** the LLM judge and its calibration, arms A4/A5 as *live* runs, the production `recognition_runs.jsonl` / `recognition_labels.jsonl` streams and the review queue (AI-SPEC §7), the test–retest ceiling and external-peer floor sessions, and provider prompt caching. The harness must `log()`/print which arms and dimensions were skipped in a run so a partial sweep never reads as a full one.
</plan_decisions>
