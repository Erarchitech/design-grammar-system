<plan_decisions>
- **`validate_proposed_structure()` (lines 95-360) is not touched.** It is the RCGN-04 safety contract, it is UAT-proven (`valid:true, attempts:1`), and its rules are relational to the submitted context — a member id existing, not being tagged, not being double-claimed — which no JSON Schema can express. The Pydantic layer sits *in front* of it, never instead of it. Any diff inside those lines is a defect in this plan's execution.
- **The retry bound stays `max_retries=2` ⇒ 3 attempts**, matching `dg_context.generate_validated_cypher`. What changes is *which* failures are eligible: `bad_json`, `schema_violation`, `tagged_overlap`, `duplicate_member`, `unknown_member_id` and `unaddressed_candidate` retry; `output_truncated`, `too_many_proposals`, `too_many_members` and `empty_procedure_scope` block without retry because they are deterministic in the scope, not formatting slips.
- **Corrective feedback is appended to the ORIGINAL prompt each attempt, not to the previous attempt's prompt.** Preserves the existing `append_recognition_feedback(prompt, violations)` contract at line 659 — feedback must not accumulate across attempts.
- **The prompt splits into a system half and a user half.** The system half is loaded from `prompts/recognition_system.md` (35-08) and passed as `GenerateRequest.system`. The user half keeps `_build_recognition_prompt`'s deterministic fixed section order (CTXA-05) and gains two new sections: the Tier-0 decisions block (`=== ALREADY DECIDED BY TOPOLOGY (do not re-propose these ids) ===`) and feature-enriched candidate lines replacing the current `position`-only lines. Listing Tier-0 decisions stops the model double-claiming *and* acts as an in-context worked example generated from the user's own canvas — the strongest few-shot available, and free.
- **Candidate lines render derived features, not raw data.** `widget=slider in=0 out=3 group="loose group A" adj_proc=[11] name="Line SDL" nick="TopChord"` — a handful of tokens carrying more decision-relevant signal than `position=[10,30]` plus a paragraph of wire lines the model must mentally join. `position` is dropped from candidate lines: it is FM-1's most seductive and least reliable signal.
- **The tagged-anchor block is summarised when scoped.** Full member lists for the target procedure, one-line `name`/`index`/member-*count* for the others (`_tagged_anchor_lines`, line 528). On a mostly-tagged canvas that block is the single largest section and most of it is irrelevant to the current procedure.
- **`json_object`-mode providers get a nudge in the user half.** DeepSeek's docs require the literal word "json" in the prompt and recommend showing a format example; when the negotiated mode is `json_object`, the output-instruction section includes a compact shape example. Branch on the negotiated mode, never on `provider == "openai"` — DeepSeek arrives through `OpenAIAdapter` via `baseUrl` and looks like OpenAI while supporting far less.
- **G10's 0.5 confidence floor is labelled a guess in the code.** It demotes rather than blocks: the proposal moves to `unrecognized[]` carrying the would-be kind as a hint. AI-SPEC is explicit that the number is provisional and must be re-derived from the accept-rate-vs-confidence curve once flywheel data exists — so it is a named module constant with that comment, and it is configurable per call.
- **Per-attempt logging is structured and redacted.** `attempt`, `provider`, `model`, `negotiated_mode`, `prompt_version`, `temperature`, `max_tokens`, `usage.*`, `finish_reason`, `tier0_decided_count`, `tier1_residual_count`, `violation_codes[]`, `latency_ms`. **Never the prompt body** (it contains the architect's canvas — 1b's third-party-IP constraint) and never the API key (LLMC-06). Only the final result surfaces to the caller; intermediate attempts stay internal, same as `generate_validated_cypher`.
- **No async conversion, no new endpoint, no Neo4j write.** The `/computgraph/recognize` route stays a thin delegating `def`; recognition still never persists (RCGN-04).
</plan_decisions>
