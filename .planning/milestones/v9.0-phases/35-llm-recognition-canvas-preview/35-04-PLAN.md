<plan_decisions>
- **Confirm UX (resolves CONTEXT "Claude's Discretion" #2):** inputs are `Accept` (text/list — proposal ids, or `*` for all), `Reject` (text/list — proposal ids), and `Apply` (boolean button, rising-edge trigger per the project's ReinstateComponent precedent so it fires once per click, not every solve). Output is a `Pending` text list (name, kind, confidence, member count) plus a `Status` text. A value-list of proposal ids is chosen over a bare "accept above confidence X" threshold for auditable, explicit selection; `*` covers the accept-all case.
- **Accept re-derives the permanent name (resolves 35-RESEARCH.md Open Question 2):** at accept-time, read the live canvas via `CanvasContextExtractor.ExtractRaw` + re-run `CanvasAnnotationNameFactory` to compute the convention-conformant nickname (and a fresh pattern index where applicable) rather than trusting the LLM's `suggestedName`, which may collide with tagging done between recognition and confirmation (mirrors the project's read-before-write discipline).
- **Accept restyle:** set the group's `Colour = CanvasAnnotationStyles.ForKind(kind, nested)` (permanent Phase-34 color, dropping the Preview desaturation), set the re-derived permanent `NickName` (dropping the `[?] ` prefix), and `doc.ValueTable.SetValue($"dg.recognized.{group.InstanceGuid}", "true")`. Optionally also stash `dg.recognized.{guid}.provider` / `.timestamp` at zero cost for Phase-36 provenance (CGPD-03) — permitted, not required.
- **Partial accept:** after Apply, accepted entries are removed from the PreviewRegistry (now permanent), rejected entries are removed (group deleted), and any proposal id in neither list stays pending in the registry.
- **New GUID** `A4C1F7E2-9B36-4D58-8E21-7F0A5C3B9D14` (verified absent from every existing ComponentGuid in DG/src/DG.Grasshopper/Components/).
