<objective>
Build the recognition backend: `cg_recognition.py` (a sibling of `dg_context.py`) that assembles a recognition prompt from the Computgraph concept catalog + a Frame few-shot + tagged anchors + untagged nodes/wires, calls the provider-agnostic LLM gateway, extracts JSON from the response, validates it against the submitted context with a bounded corrective-feedback retry, and exposes it as `POST /computgraph/recognize`. Also retire the three preview-command stub docstrings/tests on the Python bridge side.

Purpose: The AI half of the tag→recognize→preview→confirm pipeline (RCGN-01) plus its safety contract — no invented/overlapping member ids, no Neo4j write (RCGN-04).
Output: `cg_recognition.py`, its pytest suite, a Frame few-shot fixture, the `/computgraph/recognize` route, and updated bridge docstrings/tests. Fully pytest-verifiable in-container — no Rhino needed.
</objective>

<plan_decisions>
- **Input contract:** `RecognizeRequest` accepts a posted `cg_context` dict (the cgContextJson v1 envelope) plus optional `procedure_index: int | None`. Callers that want live canvas data call `/computgraph/context/pull` first, then post the result here (keeps the route synchronous, testable, and consistent with the no-message-queue architecture decision).
- **Output contract (32-RESEARCH.md §6):** `{"proposals": [{kind, suggestedName, procedureIndex, memberIds, confidence, rationale}], "unrecognized": [{memberIds, reason}]}`. `recognize_structure()` returns `{"valid": True, "proposal": <that object>, "attempts": N}` on success or `{"valid": False, "violations": [...], "attempts": N}` on final failure — mirroring `generate_validated_cypher()`'s return shape.
- **DoS bounds (Security V5, resolves 35-RESEARCH.md Security Domain open number):** `validate_proposed_structure` rejects a request with more than `MAX_PROPOSALS = 200` proposals, and any single proposal with more than `MAX_MEMBERS_PER_PROPOSAL = 1000` memberIds, as explicit `too_many_proposals` / `too_many_members` violations rather than rendering an unbounded preview.
- **Few-shot budget (resolves CONTEXT "Claude's Discretion" / 35-RESEARCH.md A4):** ship one trimmed Frame input→output example as `data-service/fixtures/frame_recognition_fewshot.json` and measure the assembled prompt byte size in a test; if the full example proves too large, fall back to one worked procedure. Lock the measured size as a test assertion.
- **JSON output discipline:** the recognition prompt explicitly instructs a single JSON object with no markdown fences and no commentary (opposite of the Cypher path's plain-text instruction); the `_extract_json` helper is the real mitigation, the instruction is advisory only.
</plan_decisions>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-35-01 | Tampering | validate_proposed_structure (memberIds) | high | mitigate | Hard-reject any proposal whose memberIds are unknown to the submitted context (`unknown_member_id`) or overlap a tagged ground-truth member (`tagged_overlap`) — a validator check, never a prompt instruction alone (V5, ASVS L1). |
