<plan_decisions>
- **preview_structure parameters shape (resolves 35-RESEARCH.md Open Question 1):** the bridge command's `parameters` is `{"proposals": [...]}` only. `unrecognized[]` blocks are report-only (returned by `/computgraph/recognize`) and are never rendered on canvas — there is nothing to preview for a block the LLM could not classify.
- **Write marshalling (resolves 35-RESEARCH.md Pattern 2 / Pitfall 3 — the one architectural decision the planner must make):** add `InvokeOnCanvasWrite(Func<GH_Document, object?>)` mirroring `InvokeOnCanvas`'s `TaskCompletionSource` shape, but the delegate MUTATES the document directly on the UI thread (NOT via `ScheduleSolution` — the bridge command does not run inside another component's `SolveInstance`, so there is no in-progress solution to defer around). After mutating, call `Grasshopper.Instances.InvalidateCanvas()` to force the redraw, then resolve the TaskCompletionSource — so the TCP response is sent only after the preview objects genuinely exist. This assumption (direct UI-thread mutation is safe for bridge-triggered writes) is verified in the Task 3 live-Rhino checkpoint (35-RESEARCH.md Assumption A2).
- **Scribble legend is text-only (Pitfall 4):** one `GH_Scribble` with plain text like `[?] N proposal(s) pending — run DG STRUCTURE CONFIRM`; no fill/border/color (GH_Scribble exposes none in this codebase's surface).
- **"Dashed" relaxed to desaturated + prefixed + legend (Pitfall 2 / Assumption A1):** GH_Group exposes no public dashed-border API; visual distinctiveness = `Preview()` alpha desaturation + `[?] ` NickName prefix + the scribble legend. Flag in the checkpoint.
</plan_decisions>
