## v11.0 Requirements

### Contract baseline and discrepancy register (CNTR) — Phase 1101

- [ ] **CNTR-01**: The exact publication repository commit, manifest values, artifact list, principal manuscript path, derivative policy, and source hashes are recorded in a versioned discrepancy/provenance register.
- [ ] **CNTR-02**: Every identified V7/V8, module-naming, Topologic, BOT, IFC/bSDD, DOI, namespace, count-scope, and manuscript-hash discrepancy is classified as resolved, accepted boundary, historical, compatibility-only, or blocker.
- [ ] **CNTR-03**: No implementation task may proceed against an unresolved critical contradiction between the R15.4 claim surface and the deposited V8 artifact set.

### Contract inventory and machine checks (CINV) — Phase 1102

- [ ] **CINV-01**: Automated checks verify manifest version, supersession, five layers, namespace/DOI status, core counts, alignment counts, SHACL shape count, disjointness count, required filenames, and catalogue entries against the actual artifacts.
- [ ] **CINV-02**: Count checks distinguish static OWL declaration IRIs, alignment axioms, companion graphs, runtime LPG nodes, RDF ABox individuals, and named individuals; no count is inferred from comments or raw duplicate text.
- [ ] **CINV-03**: The checker fails closed with an actionable report when an artifact is missing, malformed, stale, ambiguously scoped, or inconsistent with the manifest.
- [ ] **CINV-04**: The contract checker is runnable from a fresh checkout without credentials, live services, or unrecorded local state.

### V8 publication bundle (BUND) — Phase 1103

- [ ] **BUND-01**: The main repository contains the selected V8 ontology bundle, manifest, catalogue, alignment inventory, SHACL graph, disjointness overlay, and reproducibility documentation with their intended relative paths.
- [ ] **BUND-02**: Bundle transfer is selective and preserves licenses, provenance, filenames, module imports, catalogue resolution, and historical V7 artifacts where required; no generated/build/credential artifacts are copied.
- [ ] **BUND-03**: The deposited module roles are explicit: core TBox, standards alignment axioms, BOT alignment, local Topologic representation, catalogue, SHACL companion graph, and disjointness overlay.
- [ ] **BUND-04**: Any conflict between the paper-side three-role alignment architecture and the committed bundle is resolved by an explicit evidence-backed decision; no fictitious IFC/bSDD ontology module is created.

### Runtime ontology and V7 reference synchronization (RTON) — Phase 1104

- [ ] **RTON-01**: Current runtime ontology consumers use the approved V8 artifact or an explicitly documented compatibility profile, including the reasoner, ontology export, concept catalog, serializers, and test fixtures.
- [ ] **RTON-02**: Every retained V7 reference is labeled as historical lineage, compatibility input, archived evidence, or an approved V7 runtime profile; unclassified current-runtime V7 references remain a release blocker.
- [ ] **RTON-03**: V8 runtime loading preserves Grasshopper plugin and Design Grammars platform behavior on the existing successful paths, with additive/versioned handling for changed status or evidence metadata.
- [ ] **RTON-04**: Ontology documentation distinguishes five publication layers from historical four-layer/schema-v3 descriptions and does not present obsolete KnowledgeGraph/ValidationGraph terminology as current V8 contract.

### Normative specifications and propagation (SPEC) — Phase 1105

- [ ] **SPEC-01**: `spec/API.md`, `spec/DATABASE.md`, `spec/LPG-OWL-MAPPING.md`, `spec/RULE-PARTITION-POLICY.md`, `spec/DG-ID.md`, Cypher templates, dataset schemas, n8n prompts, SHACL documentation, and CLAUDE.md use consistent V8 contract terminology or explicit historical/compatibility labels.
- [ ] **SPEC-02**: API and persisted-record contracts expose verdict statuses `VALID`, `INVALID`, `INCOMPLETE`, `UNSUPPORTED`, `SKIPPED_WITH_REASON`, and `NOT_CHECKED`, while operational failures remain distinguishable as unavailable, timeout, cancelled, invalid-request, execution-error, port-occupied, project-unresolved, provider-unavailable, or publish-rejected.
- [ ] **SPEC-03**: Missing, stale, truncated, unavailable, or unsupported evidence never silently becomes `VALID` or `INVALID`; legacy Boolean fields remain compatibility fields with documented interpretation.
- [ ] **SPEC-04**: Deterministic re-execution requirements identify fixed artifact/configuration, snapshot, versions, scope, canonical output, and result hash; LLM outputs, provider behavior, live canvas state, timestamps, and live service availability are excluded from the deterministic claim.
