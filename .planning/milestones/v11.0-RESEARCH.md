## Critical contradictions requiring v11.0 resolution

### 1. Paper-side alignment architecture versus committed V8 bundle

The R15.2/R15.4 alignment decisions describe three alignment roles: topology, classification, and standards. The committed bundle still uses files named `*-extension-V8.owl`, contains BOT and Topologic artifacts, and has no dedicated IFC/bSDD classification module. The manifest is cautious, but the paper-side architecture can be read more strongly than the deposited files support.

**Required resolution:** choose and record whether the bundle is rebuilt to reproduce the paper-side architecture or the manuscript is narrowed to the current manifest-supported recording forms. Do not invent an IFC classification file.

### 2. Topologic status

The V8 README, alignment inventory, and Topologic file describe a local OWL representation and explicitly state that a formal versioned external OWL ontology is not imported. The R15.2 decision and parts of the manuscript refer to a published Topologic OWL ontology and a Topologic-to-BOT topology path.

**Required resolution:** reconcile external evidence, deposited representation, and manuscript wording. Until the artifact is rebuilt and verified, no claim may call the target a formal external versioned OWL ontology.

### 3. Main repository remains V7-based in critical runtime paths

The main runtime has no `ontology/DesignGrammar-V8.owl` and uses V7 defaults in at least:

- `dg-reasoner/reasoning.py`;
- `dg-reasoner/ontology_export.py`;
- `data-service/dg_knowledge.py`.

The repository also contains widespread V7 references. These require classification into historical, compatibility-only, and current-runtime/publication-facing references before migration.

### 4. Human-readable documentation drift

These files cannot be globally rewritten without preserving historical scope, but current claims must be corrected or explicitly marked historical.

## Runtime/evidence findings

### Status taxonomy

Current surfaces mix Boolean verdicts, lifecycle states, transport errors, SHACL conformance, auto-validation state, and evidence dispositions. This risks treating missing evidence as a failed design or treating an unavailable evaluator as a pass.

Required verdict statuses:

- `VALID`;
- `INVALID`;
- `INCOMPLETE`;
- `UNSUPPORTED`;
- `SKIPPED_WITH_REASON`;
- `NOT_CHECKED`.

Required operational states include:

- `UNAVAILABLE`;
- `TIMEOUT`;
- `CANCELLED`;
- `REQUEST_INVALID`;
- `EXECUTION_ERROR`;
- `PORT_OCCUPIED`;
- `PROJECT_UNRESOLVED`;
- `PROVIDER_UNAVAILABLE`;
- `PUBLISH_REJECTED`.

`blocked-not-failed` is an evidence/reporting disposition, not a compliance verdict.

### Layer boundaries

The following boundaries must be explicit in specifications and runtime evidence:

- **TBox:** static ontology declarations and selected overlays;
- **ABox:** runtime individuals projected from project-scoped LPG data;
- **LPG:** Neo4j operational source of truth and query/write substrate;
- **RDF:** evaluator projection, not a complete LPG semantic equivalence claim;
- **SHACL:** structural/data-integrity validation over the declared projected graph;
- **SWRL/DG validator:** project-specific design-compliance constraints;
- **Computgraph Cypher:** LPG-native structure checks;
- **LLM/KB:** proposal and knowledge consumers, not universal validators.

A successful result from one evaluator is evidence only for that evaluator and scope.

### Determinism boundary

Deterministic claims are supported for fixed parser/serializer inputs, DG-ID minting inputs, Tier-0 topology and candidate sampling, Cypher structural checks over an unchanged snapshot, command parsing/dispatch, KB checks against a pinned KB, and snapshot diffs with fixed algorithms.

They are not supported for LLM outputs, provider fallback, live canvas state, timestamps, live services, or the entire LLM-assisted pipeline.

A deterministic re-execution record should include contract/schema/serializer versions, scope, snapshot hash, ontology/TBox and overlay versions, shape/rule/KB versions, command registry version, execution disposition, and canonical output/result hash.
