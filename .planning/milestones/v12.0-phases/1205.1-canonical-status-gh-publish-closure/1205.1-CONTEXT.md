# Phase 1205.1 — Canonical Status GH Publish Closure

## Основание и разрешенный объем

Пользователь поручил «запускай closure-фазу» после аудита v12.0. Источник требований: `.planning/v12.0-MILESTONE-AUDIT.md`, BLOCKER-01. Это подтверждение запуска исправления выявленного semantic break, не принятие нового runtime-дизайна или отмена gates.

## Цель

Сохранить canonical status per-(rule,object) от DG.Core evaluator через production GH publish DTO/serialization до Python evidence envelope и persisted/read result. Unsupported и другие non-verdict outcomes не должны превращаться в passed/failed из-за boolean collapse.

## Требования

ALGN12-01, ALGN12-02, ALGN12-06, ALGN12-10. Зависимости: фазовые контракты 1200–1202 и auth boundary 1205.

## Критерии приемки

- Воспроизводящий тест сначала демонстрирует текущий Unsupported → passed defect.
- Regression использует production serialization, не вручную сконструированную замену wire DTO и не только DE-01 synthetic payload.
- Typed per-object outcomes сохранены; mixed objects/rules и sibling Unknown/Error/NotEvaluated/NoPopulation/Indeterminate пути изучены и покрыты в пределах реально достижимых состояний. NoPopulation не должен создавать фиктивный объект.
- Supported passed/failed behavior, единая StatusRollup precedence, auth и fail-closed tenant boundary сохранены.
- Выполнены применимые C#/Python regression suites, GH Release build и независимая verification.
- Публикационный контракт и актуальные спецификации синхронизированы точечно; исторические phase reports не переписаны как будто дефекта не существовало.

## Границы

Не включать unrelated renderer/hash tuple/identity/UI refactors, миграцию direct-Bolt, ротацию секретов, полную Nyquist reconciliation прежних фаз, manuscript или Phase40 live UAT. Не менять canonical vocabulary, не ослаблять DE-01, не помечать весь milestone passed после одного исправления. Если решение требует breaking contract или миграции, остановиться на decision checkpoint.

## Исполнение

Сначала research → отдельный planner → независимый plan-checker → execution → independent verification. Пользователь разрешил запуск closure; дополнительных общих вопросов об уже установленной цели не требуется. Нет разрешения на commit/push, переключение ветки, production mutations, restart контейнеров, чтение секретов или платные LLM вызовы. Dirty worktree сохранять. Запускать safe isolated tests; live actions отдельно согласовывать при необходимости.

## Подтвержденные решения владельца после research

Пользователь подтвердил предложенный набор: «Подтверждаю, сделай весь цикл самостоятельно».

- **D-04:** Автономно пройти planning → independent plan-check → execution → independent verification и необходимые исправления в согласованной области. Не запрашивать повторное одобрение этих решений или обычных технических шагов. Неразрешимый конфликт/необходимость расширить рискованный scope требует остановки.
