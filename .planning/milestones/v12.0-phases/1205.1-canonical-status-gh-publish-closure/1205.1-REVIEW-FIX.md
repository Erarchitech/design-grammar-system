### Явная техническая политика

Документирована в `spec/EVIDENCE-CONTRACT.md` §3.1.1 и ссылках API/DATABASE:

- decoded object keys уникальны на каждой глубине; repeated array row identities сохраняют установленную collision/rollup policy;
- JSON numeric values должны быть finite binary64; NaN/±Infinity, exponent overflow и integer magnitude overflow отвергаются, не переписываются в null;
- maximum 128 **containers**, root=1, scalar leaf глубину не увеличивает; это runtime/resource constraint, **не гарантия JSON Schema** и не универсальная защита от размера payload;
- full `canonicalizationVersion`: mathematical integer в диапазоне ±9007199254740991; decimal/exponent lexemes используют существующее binary64 decoding, integer values не ограничены Int32. Этот новый явный interoperability bound закреплён в schema; значение 1099511627776 сохранено допустимым. Writers по-прежнему emit 1;
- hash ровно 64 uppercase hex, dgId ровно `dg:` + 16 uppercase hex; final LF не допускается;
- historical projection продолжает игнорировать unused root metadata types/ranges, как утверждено ранее; full construction остаётся отдельным gate. Raw uniqueness/finite/depth guards действуют для всех токенов.

Exact `2.0.0` не нормализуется. Old literal `1` и `1.0.0` no-rows inputs не дополняются metadata/rows. Статусы, precedence, hash algorithms, frozen DE-01 verdicts, best-effort sidecar и auth/tenant policy не изменены.
