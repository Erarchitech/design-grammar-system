## Причины и исправления

### CR-01-R2: Unicode до модели и ответа

Python `json.loads` допускает escaped lone surrogate; прежний resource guard проверял только числа/глубину и не обходил имена members. Поэтому arbitrary metadata доходила до настоящего GET/JSONResponse и вызывала UnicodeEncodeError. Теперь общий preflight проверяет **все строки и ключи** строгим UTF-8 encoding; невалидный scalar Unicode вызывает ValueError до coercion/response. Это автоматически покрывает существующие raw publish, persisted evidence, SHACL и Python API wiring; `app.py` не изменён.

C# `JsonDocument.Parse` не полностью декодирует escaped strings. `property.Name` и `GetString()` могут выбрасывать InvalidOperationException позднее. Добавлено принудительное чтение всех string values и имён, с **узким catch непосредственно у этих операций**, плюс проверка UTF-16 scalar pairs до Parse для literal malformed input. Публичные `TryRead` и `IsStrictEnvelope` возвращают false; `TryRead` оставляет result=null. Repository outer catch не используется как доказательство.

Valid escaped pairs, supplementary Unicode, кириллица, U+FFFD как настоящий валидный scalar, разные composed/decomposed keys сохраняются. Escaped/literal spellings одного supplementary key по-прежнему считаются duplicate members. Нет replacement/normalization, изменений hash/identity или blanket catch.

### WR-01-R2 / CR-03-inmemory-container: явный pre-dump domain

Прежний обход пропускал tuple, хотя Pydantic сериализует её в array и превращает NaN/Infinity в null. Теперь built-in tuple обходится наравне с list, с тем же accounting глубины. Nonfinite значения и surrogate text обнаруживаются **до** named v2 factory dump, explicit legacy validation и in-memory read/full admission.

Вместо списка частичных запретов задан closed domain: JSON scalars, built-in dict со строковыми ключами, list/tuple и структурно раскрываемые Pydantic records существующего typed API. Остальные формы явно отвергаются до dump: set/frozenset/deque, generator/iterator, dataclass, namedtuple, custom mapping/iterable и container subclasses. Arbitrary iterables не потребляются. Конструктор legacy и его defaults не изменены.

`serializer_inventory.py` / `serializer-inventory.log` реально сравнивают сериализатор и guard: list/tuple/set/frozenset/generator/iterator/dataclass/namedtuple могут скрыть NaN→null; plain Any deque/custom mapping/custom iterable в установленном Pydantic сами дают serialization error. Все неподдерживаемые формы теперь получают explicit guard rejection независимо от serializer capabilities. Это не обещание поддержки всех произвольных Pydantic custom serializers.

Finite list/tuple, shared noncyclic aliases и Unicode внутри них сохранены; read возвращает исходный dictionary. List/dict/tuple-list/model cycles не проходят bound. Числовая binary64/safe-integer политика, exact версии `1`, `1.0.0`, `2.0.0`, depth 128 и различие duplicate members / duplicate rows не изменены.
