## 05-01 — Writer, strict request admission, diagnostics

- Preconditions подтверждены существующим 04-SUMMARY и preceding source: оба readers, cross-language/historical/DE-01 matrix и Core diagnostic members готовы. Родитель сообщил свежий pre-dispatch rerun 125 tests; этот результат не выдаётся за запуск исполнителя.
- `ValidationPublishClient.BuildRequest` явно устанавливает `EvidenceEnvelopeFactory.ContractVersionV2`, конвертирует rule Status через `EvidenceStatusNames.ToWireName`, копирует rule Warnings/Detail и entity CanonicalWarnings/CanonicalDetails с исходными ordinal keys. Existing canonicalStatuses copying сохранён. Null rule Detail опускается точечным JsonIgnore, без изменения глобальной сериализации legacy fields.
- Python проверяет raw request до coercion: только отсутствие version выбирает старый путь; null/bool/int/float/unknown/old/nonexact tokens отвергаются. New mode требует непустые уникальные declared rules, уникальные results с exact coverage, уникальные entity identities, unique in-scope ruleIds, exact canonicalStatuses coverage и recognized exact wire names. Diagnostics ограничены scope и правильными string/list types. Никакой whitespace normalization или bool/int conversion canonical tokens.
- `_build_publish_evidence_envelope` расширен keyword-only `rule_results` и `evidence_contract_version`. Старый three-argument call и алгоритм fallback сохранены буквально. Новый путь читает только canonical maps, не объединяет legacy lists и не размножает rule aggregate в object rows; вызывает настоящий `build_envelope_with_rule_results`.
- `build_rules_summary` оставляет legacy fields и добавляет canonical fields только при supplied non-null values. Главное хранение rule outcomes — отдельная `envelope.ruleResults`, не только rulesJson.
- Три zero-row правила проходят production JSON → actual request model → authenticated route → настоящий store/persist → захват параметра evidenceEnvelopeJson → actual view → C# repository reader с SHA-256 equality входных UTF-8 bytes. Два evaluated empty дают no_population, missing result даёт not_evaluated; entities/rows/verdicts пусты, fake object отсутствует.
- Diagnostics controls получают исходный Core package отдельным harness `core <scenario>`, затем сравнивают его реальные evaluator Unknown/Unsupported details и builder `typed_binding_outcome_unavailable` warnings с generated request и captured envelope. View возвращает exact envelope; C# получает те же bytes, API диагностик reader не расширялся.

## 05-02 — Outcome / compatibility / denial matrix

- Natural Passed/Failed, mixed short-circuit Passed/Unsupported одного правила, Unknown (missing variable), Error (реальный invalid integer literal), no_population, missing result not_evaluated, nonempty no-ElementRefs с реальным Failed rule и без object rows.
- Legacy-only BindingResults=null, explicit [] при nonempty population и missing typed association дают Unknown плюс diagnostics. Legacy Passed/списки остаются независимыми.
- Repeated binding reference, повторный ref одного объекта, несколько refs, shared ref с mixed outcomes и distinct equal-value objects проходят exact pair aggregation: одна producer row на пару, нет reader collisions.
- `contract_injected_indeterminate` явно использует test-only BindingResults injection. Естественная evaluator emission Indeterminate не заявляется.
- Mixed-zero-row case композирует два настоящих Core packages: evaluated empty rules и populated rule. Это необходимо из-за общего bindings population у одного Build invocation; outcomes не придуманы, mapper не скопирован. Production BuildRequest/serialization и весь downstream путь настоящие. Это не утверждение, что один текущий Publish invocation формирует разные populations.
- Отдельные hand-mutated controls проверяют strict token/coverage/identity/diagnostic denials, отсутствие map, invalid exact statuses, contradictory legacy lists и отсутствие version sniffing. Все rejection controls требуют 422 и zero external graph writes. Canonical rows не расширяются даже legacy-only ruleId из contradictory lists.
- Реальные temporary auth stores/session/CSRF, без dependency overrides. Unauthenticated → 401; пользователь с membership только P_FOREIGN → 403 для P_WIRE; никаких writes. Network guard запрещает external I/O, включая произвольный localhost.
- Old-client absent/null/invalid status map fallback проходит actual authenticated route/persist/view/C# с `1.0.0`, без envelope.ruleResults. Presence новых fields без version не включает v2.
- Legacy ruleId/Passed/FailedEntityIds/PassedEntityIds и entity identity/display/geometry/RuleIds/FailedRuleIds/PassedRuleIds/OverallStatus сравниваются Core → production wire. Original contradictory legacy Unsupported/Unknown behavior дополнительно фиксирован literal assertions. Actual outgoing Speckle payload сохраняет lists/OverallStatus; actual stored legacy rows сохраняют old statuses; `ValidStatus=[true,false,true]` проходит явное Publish-equivalent assignment и настоящий store без canonical boolean замены.
- Existing evidence sidecar best-effort behavior не изменён: HTTP 200 возможен при external write error. Два negative controls доказывают, что roundtrip helper FAILs при потерянной записи или swallowed exception; HTTP success не принимается за persistence proof.
