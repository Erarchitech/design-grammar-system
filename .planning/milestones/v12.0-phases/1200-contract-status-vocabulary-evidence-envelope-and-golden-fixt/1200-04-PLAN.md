## Planner decision — RESEARCH.md Open Question 1

**The C# canonicalization helper and envelope type live in `DG.Core`, in a new `DG.Core.Contracts`
namespace — not inline in the DE-01 harness.**

Rationale: D-06 requires the envelope to be emitted at every stage boundary that produces or
transforms a verdict, and the C# evaluator is one such boundary. An envelope constructed
out-of-band by the harness would be the harness's opinion about what the evaluator did, not the
evaluator's own emission — which defeats the purpose of localizing a mid-pipeline divergence. The
established pattern is explicit: contract types belong in `DG.Core` (no Grasshopper dependencies),
never in `DG.Grasshopper`. This does mean 1200 adds files under `DG.Core`.

**Scope bound:** adding the contract types is not migrating the codebase onto them. This plan does
**not** modify `RuleEvaluator.cs` or `ValidationPublishPackageBuilder.cs`. The evaluator keeps
returning boolean `Passed` and keeps throwing `NotSupportedException` for an unsupported builtin;
the DE-01 runner (plan 1200-05) catches that at its own call boundary and maps it to a typed
`unsupported`. Changing the evaluator to return `unsupported` instead of throwing is Phase 1201's
ALGN12-06 and appears in CONTEXT.md's deferred table.

`Canonicalize(JsonNode? node)` — walk the node tree explicitly and write the canonical form,
implementing all six rules. Do NOT delegate to `JsonSerializer.Serialize` — `System.Text.Json`
preserves declaration order and applies broader default escaping, so the serializer's defaults
cannot produce the canonical form. Write directly to a `StringBuilder`.

Rule implementation:
- Objects: enumerate properties, order them with `StringComparer.Ordinal` on the key, and re-emit.
  Ordinal comparison, not culture-aware — this is the rule that mirrors Python's code-point sort.
- Arrays: preserve element order (arrays are ordered data; only object keys are sorted).
- Integers: emit with no decimal point and no leading zeros.
- Non-integers: accept only `decimal`, emit as a fixed-point string with `CultureInfo.InvariantCulture`.
  Throw an explicit exception naming the offending path if a `double` or `float` is encountered,
  because IEEE-754 shortest-round-trip formatting differs between .NET and Python.
- Whitespace: none; separators are bare `,` and `:`.
- Strings and keys: normalize with `s.Normalize(NormalizationForm.FormC)` before writing.
- Escaping: escape only `"`, `\`, and control characters below 0x20, using the `\uXXXX` form for
  control characters. Leave all non-ASCII unescaped. Add an XML-doc note that this deliberately
  differs from `System.Text.Json`'s default broader escaping, that the equivalent Python setting is
  `ensure_ascii=False`, and that this is acceptable here because the canonical form is hashed and
  never rendered into HTML.
- NaN/Infinity: throw, with a message pointing the caller at the `Indeterminate` and `Error`
  statuses as the correct representation for a non-finite result.
