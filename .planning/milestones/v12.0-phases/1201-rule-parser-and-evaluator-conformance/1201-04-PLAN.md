<objective>
Make the boundary of the implemented subset both **readable** and **machine-checkable**, and prove
all eight ROADMAP parser cases behave as typed outcomes.

This is ALGN12-07 and the two remaining ROADMAP deliverables: the documented distinction between
schema-level SWRL atom types and the bounded C# evaluator subset, and the explicit refusal to claim
the C# path is a general SWRL/OWL reasoner.

Purpose: a prose-only boundary drifts from the code within one phase. D-15 fixes that by making a
single `DG.Core` constant the source of truth that both the evaluator and a conformance test read,
so a builtin added to the code without updating the doc — or vice versa — fails the build.

Output: `fixtures/golden/parser/` with a table-driven corpus, `spec/SWRL-SUBSET.md`, the drift-guard
test, and the propagation edits `CLAUDE.md` mandates.

**Frozen-fixture constraint, restated because this plan is the one that could violate it:**
`fixtures/golden/fixture.json` is frozen by Phase 1200 D-11. This plan **never edits it**. The new
corpus lives in a `parser/` subdirectory precisely so the frozen file is untouched (D-16), and
per-service copies of any fixture remain forbidden (1200 D-09).
</objective>

Its required content:

**Supported subset.** The atom types the parser emits and what each means, and the six supported
builtins with their numeric-versus-non-numeric applicability — four are numeric-comparison only, two
also compare non-numerics. Per the discretion CONTEXT left open, carry the allow-list **inline** in
the doc rather than generating it, and bind it to the code with the drift-guard test below; an
inline list is reviewable in a diff, and the test is what makes it safe.

**The recognize-versus-evaluate asymmetry.** State it plainly and early, because it is the single
most misreadable thing about this subset after Phase 1201: the parser can now *recognize* an
`ObjectPropertyAtom`, and the evaluator still cannot *evaluate* one. Both halves are correct and
deliberate. Quote the evaluator's actual refusal wording from the 1201-02 summary so the doc and the
runtime message say the same thing.

**Non-claims (D-14).** An explicit section listing what is not supported, each mapped to the status
it yields: ObjectPropertyAtom *evaluation* → `unsupported`; string and date builtins → `unsupported`;
negation → `unsupported`; OWL inference of any kind → `unsupported`; a predicate whose kind the
OntoGraph cannot resolve → `unsupported`; a variable with no value in the binding row → `unknown`;
an empty binding population → `no_population`; a rule in scope with no result produced →
`not_evaluated`. Open the section with the direct statement that the C# path is **not** a general
SWRL/OWL reasoner and does not claim to be — that sentence is the fourth ROADMAP deliverable.

**Relationship to the partition policy.** SHACL owns structural and data-integrity rules; the SWRL
VALIDATOR owns quantitative and parametric design rules. Link to `spec/RULE-PARTITION-POLICY.md`
rather than restating its content, so the two cannot drift.

already use for their existing cross-references — do not restructure either document.

Extend `SwrlSubsetConformanceTests.cs` with the drift guard. The test reads

block in the doc — a fenced block with one builtin name per line, introduced by prose explaining it
exists for the drift guard. Assert set equality in **both** directions and make the failure message
name which side has the extra entry, so a failing build tells the developer whether to edit the doc
or the code.

Add the second guard asserting every status named in the non-claims section parses via
`EvidenceStatusNames.TryParseWireName`, so the doc cannot name a ninth status the vocabulary does not
have.
