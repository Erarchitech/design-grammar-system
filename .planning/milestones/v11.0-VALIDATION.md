# Milestone v11.0 — Validation Strategy

**Status:** Planned, isolated; validation contract for future execution only.

## Validation model

v11.0 combines deterministic artifact checks, source-level contract checks, runtime regression tests, document integrity checks, and explicitly human-gated publication decisions. No human or live-environment result may be represented as an automated pass without recorded evidence.

## Dependency and isolation checks

Every plan must verify its declared `depends_on` phases before writing. Phase 1101 must establish the protected-path inventory and allowlist. Later plans must use path-scoped changes and pre/post assertions against protected active GSD paths. No plan may run `git reset`, `git clean`, broad checkout/restore, mass V7→V8 replacement, or unscoped staging.

While v9.0 is active, v11.0 plans remain under `.planning/milestones/v11.0-phases/`; they must not be moved into active `.planning/phases/`.

## Common status semantics

Verdict statuses: `VALID`, `INVALID`, `INCOMPLETE`, `UNSUPPORTED`, `SKIPPED_WITH_REASON`, `NOT_CHECKED`.

Operational statuses: `UNAVAILABLE`, `TIMEOUT`, `CANCELLED`, `REQUEST_INVALID`, `EXECUTION_ERROR`, `PORT_OCCUPIED`, `PROJECT_UNRESOLVED`, `PROVIDER_UNAVAILABLE`, `PUBLISH_REJECTED`.

`blocked-not-failed` is an evidence disposition, not a compliance verdict. Missing, stale, truncated, unavailable, or unsupported evidence must never become an implicit `VALID` or `INVALID` result.

## Deterministic verification boundary

Determinism may be asserted only for fixed artifacts/configuration, fixed input snapshots, fixed algorithms, and fixed versions. LLM responses, provider fallback, live canvas state, timestamps, external-service availability, and the complete LLM-assisted pipeline are excluded.
