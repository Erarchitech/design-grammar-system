# Roadmap: Design Grammar System v11.0 — V8 Publication Contract Alignment

**Planned:** 2026-09-13  
**Status:** Future (isolated; do not activate while v9.0, v9.1, or v10.0 is active)  
**Phase numbering:** `1101–1109`, exactly nine phase slots. No `1101.1` insertions are planned.  
**Depends on:** the V8 publication repository snapshot and R15.4 claim surface identified in `v11.0-CONTEXT.md`. The Phase 40, v9.1, and v10.0 gates are preserved as downstream activation constraints; v11.0 does not require future v9.1/v10.0 execution to occur before its own planning or execution, but must consume any available gate records and re-check their shared contracts.  
**Future milestone policy:** v11.1 is not planned. If approved scope later exceeds nine coherent phases, create a separate milestone rather than extending v11.0 silently.

> **Isolation contract:** This roadmap and `v11.0-REQUIREMENTS.md` are isolated future-milestone artifacts. They do not modify `.planning/phases/`, `.planning/STATE.md`, `.planning/PROJECT.md`'s Current Milestone, or active `.planning/REQUIREMENTS.md`. Do not invoke `/gsd-new-milestone` merely to register v11.0.

## Overview

v11.0 makes the Design Grammar System's publication, runtime, and evidence boundaries agree with the V8 deposit and the R15.4 manuscript. It imports only the selected publication artifacts, classifies historical V7 references instead of replacing them blindly, synchronizes runtime/spec/API/prompt/test contracts, establishes fail-closed status semantics, verifies TBox/ABox/LPG/RDF/SHACL/SWRL boundaries, reconciles alignment claims, preserves the principal manuscript policy, and produces a provenance-backed release-readiness report.

The milestone is deliberately separate from product-capability milestones:

- v9.0 remains the AI Workflow Intelligence feature milestone and receives only a narrow Phase 40 preflight.
- v9.1 remains the DG Canvas Chatbot Node milestone and receives an activation gate for shared surfaces.
- v10.0 remains the Script Intelligence milestone and receives an activation gate plus a Phase 47 rule-partition prerequisite.
- v11.0 owns the full repository/publication synchronization and evidence-boundary migration.

**9 phases, 37 requirements, planned as one isolated milestone.**

## Cross-milestone activation gates

### v9.0 Phase 40 gate

Phase 40 may include only a narrow V8 publication-contract preflight: version and filenames, five layers, count scope, TBox/ABox/SHACL/HermiT/determinism wording, literal namespace/DOI status, and graphify source-commit scope. It must not absorb the full v11.0 migration.

### v9.1 activation gate

Before v9.1 activation, verify shared serializer and `cgContextJson` compatibility, explicit operational/non-verdict statuses, provenance categories, publication terminology, confirmation trust sequence, and the existing v9.0 Phase 32–36 verification prerequisites. Qualify deterministic wording so it applies to fixed parsing/validation/dispatch/planning inputs, not live LLM or canvas behavior.

### v10.0 activation gate

Before v10.0 activation, verify TBox/ABox/LPG/RDF/SHACL/SWRL/Cypher ownership, fail-closed operation outcomes, identity bindings, evidence-bearing provenance, and the restricted deterministic scope. Before Phase 47, ratify the rule partition and prohibit hidden SWRL value-threshold semantics inside graph-native structure rules.

## Phases

### Phase 1101: Contract Baseline and Discrepancy Register

**Goal:** Freeze the exact V8 publication baseline and classify all known contradictions before implementation changes begin.  
**Requires:** Read-only baseline of the main repository, publication repository, R15.4 principal DOCX, and current planning/vault/graphify state.  
**Requirements:** CNTR-01, CNTR-02, CNTR-03

**Deliverables:**

- Versioned provenance/discrepancy register containing the publication commit, manifest values, selected artifact hashes, principal DOCX hash, derivative policy, and dirty-tree protection scope.
- Explicit decisions for the Topologic/BOT/module-naming/IFC-bSDD discrepancies and the principal DOCX hash discrepancy.
- Classification inventory for V7 references: historical, compatibility, current-runtime, publication-facing, or blocker.

**Success Criteria:**

1. A reviewer can identify the exact source commit and every release-blocking discrepancy.
2. No critical manuscript/artifact contradiction remains unclassified.
3. Protected parallel/generated/credential artifacts are excluded from the implementation allowlist.

**Plans:** 1 plan — `.planning/milestones/v11.0-phases/1101-contract-baseline-discrepancy-register/1101-01-PLAN.md`
