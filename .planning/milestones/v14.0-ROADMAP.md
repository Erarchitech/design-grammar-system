## Goal and ownership boundary

Architects connect a building-code source by file, permitted site or read-only Drive folder; DG enumerates and compares exact clauses, proposes requirements/rules from a pinned standard-linked company vocabulary, proposes measured Revit/GH bindings, and presents a traceable change set. Steward and project editor independently approve library meaning and project activation. Evaluation remains deterministic over the existing Design State/evidence/status boundary; unavailable data never produces a compliance pass.

| Existing owner (not transferred) | v14's additional product scope |

| v13/1302 DGKN-01…06: generic CDE SourceRevision, company vocabulary release/steward, project rule revisions, CAS/audit/history | Jurisdiction-library source/edition/clause schema, allowed standard URI/version refs, clause-level partial acceptance, normative library rule compilation and source connectors |
| v13/1303 DGBN-01…03: exact GH native identity/parameter binding, inspect/trace | Norm-to-class, class-to-object and property-to-measurement proposal/probe; GH final-output trace and bounded Revit/GH model probes for code clauses |

| v13/1307 DGRL: DeGram product slice acceptance; v13/1308 WEBUI and 1309 HOST | Independent normative two-jurisdiction/format UAT and operator change-review workflow; not a claim that DeGram or hosting is complete |

Missing upstream capability blocks its consumer; it is not silently reimplemented or marked passed. Before bulk norm ingest, assign and close existing rule-ingest F6/F13 collision risk. Contract changes follow CLAUDE.md schema propagation and the owners of v11/v12 normative boundaries. DeGram/Revit component edits require workspace preflight and distinct authorization.

## Activation and verification protocol

1. Keep v13 active through its own acceptance/closeout, including residual v12 debt disposition; v14 has no implied completion. At the explicit transition, reconcile any incomplete v13 prerequisite in the v14 dependency ledger, then move future requirements/roadmap into the active GSD files through an approved, non-destructive transition. 2. Discuss unresolved design decisions before writing executable phase plans: company/library/jurisdiction key and ACL; permitted source/dictionary versions and licences; steward vs project BIM-manager authority; second jurisdiction; Drive credential model; applicability/non-verdict contract; rights to Jev feature transfer; comparison thresholds and fixtures. A closed concept document is not an approved runtime contract.
3. Each phase provides unit/contract/negative fixtures and explicit raw evidence for its assigned IDs. Live external fetch, OAuth, CAD/Neo4j writes, paid inference, native component build/launch, deployment, data export and publication each require their own scope-specific authorization. Nothing in the roadmap grants these actions.
4. Run release UAT on immutable versions of source, vocabulary, mapping, model/definition, compiler/router and evaluator with expected/actual comparisons and clause-count denominators. Review false passes before token savings. Use the existing canonical evidence/status vocabulary; do not turn unknown, unsupported, inapplicable or failed parsing into passing validation.
