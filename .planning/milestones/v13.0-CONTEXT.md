## Goal and core value

An architect can carry a source-linked project requirement through approved rule authoring, an exact connection to a native model/script, measured validation, human selection and cross-person handover. The recipient can recover the decision and its evidence without the author's chat history.

DeGram is a minimal Hermes Desktop fork on the participant's PC. DG remains the authority for corporate knowledge, authorization and project rights. Existing DG web UI and the full Model Viewer are reused. Local MCP connects to Revit and Grasshopper; the DG addin connects native objects and script parts to DG. The LLM proposes/explains; a person approves changes and decisions; the appropriate evaluator supplies a scoped verdict.

## Non-negotiable boundaries

- Company vocabulary is shared only within the authorized company/CDE context. This is governance scope, not a requirement to store Ontograph physically in the CDE.
- Rules belong to one project and an explicit applicability scope. Project editing rights do not confer company vocabulary stewardship.
- Lessons learned are an authorized, provenance-bearing copy, followed by adaptation, validation and approval in the destination project. Copies evolve independently. A source-project pass is not destination evidence.
- Ontograph owns terms; Metagraph rules; ComputGraph script/model bindings; ValidGraph runs and checked states; SpecGraph sources and decision grounds. Runtime casing/profile is pinned at 1300 rather than silently renamed.
- CDE owns source documents/revisions and accepted material publication. No replacement CDE or sixth graph.
- No universal graph CRUD, unrestricted CAD code execution, whole-definition synthesis or autonomous model changes in this MVP.
