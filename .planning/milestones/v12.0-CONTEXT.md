## <decisions>

Eight decisions locked in discussion. Downstream agents must not re-ask these.

### D1 — New isolated milestone v12.0

The alignment plan's packages land in a **new isolated milestone**, not as v11.0 extensions
and not folded into Phase 40.

**Rationale:** v11.0's ROADMAP caps itself at nine slots and states explicitly that scope
beyond that creates a separate milestone rather than extending v11.0 silently. Folding into
Phase 40 would leave security/tenancy (Critical) unowned.

**Follows** the isolated-milestone pattern: artifacts live under `.planning/milestones/v12.0-*`,
`/gsd-new-milestone` is **not** invoked (it is destructive mid-flight — it clears
`.planning/phases/` and resets STATE while v9.0 Phase 40 is the live frontier).

### D2 — Phase numbering 1200–1205

Repo convention is `vX.Y → X·100 + Y·10` with a 10-phase cap. v12.0 → block **1200–1209**;
six phases occupy **1200–1205**.

> Corrects the "1201–1206" framing used during discussion — v11.0's own 1101–1109 sits in the
> 1100 block on the same rule, so v12.0 starts at 1200, not 1201.

### D3 — ID disambiguation: `ALIGN-P01..P16`

| Register | Prefix | Meaning | Source |
|---|---|---|---|

### D5 — Golden fixture is Phase 1200's deliverable

The cross-service fixture is **built inside the milestone**, not spiked beforehand.

Contents (per plan §11 item 3): one rule, all four atom types, two objects — **one passing and
one failing** — a Design State, and a geometry reference.

DE-01 runs that fixture through **Python data-service → dg-reasoner → C# evaluator → persisted
replay**, recording rule IDs, object IDs, statuses, warnings, input hashes, output hashes.

**Acceptance:** identical canonical statuses for supported cases; *explicit, typed*
non-equivalence for unsupported cases. A silent disagreement is a failure; a declared one is not.

Everything in 1201–1205 verifies against this one artifact. It is the milestone's spine.

### D6 — Pending UAT stays with Phase 40

The 10 pending/blocked items (phases 33, 34, 35, 37, 38) are **out of v12.0 scope**.
`gsd.md` item 013 names Phase 40 sole active closeout owner. v12.0 records them as an external
dependency with status `unknown` — never `pending-in-v12.0`, never inferred as passed.

ALIGN-P10 and ALIGN-P11 are therefore **routed away** from v12.0, not absorbed.

### D7 — Security/tenancy gets its own phase (1205)

ALIGN-P14 / risks R-11, R-16. Rated **Critical** impact, currently unowned by any milestone.

Scope: server-side user/tenant authorization; review of the direct Neo4j proxy exposure;
secret and default-credential handling (compose inventory records literal secrets).

**Gate semantics:** release-blocking for external multi-user evaluation. Unauthorized
cross-project access and direct-proxy access must **fail closed**. It does not block the paper.

## <success_criteria>

v12.0 succeeds when:

1. A single fixture produces **typed, comparable** verdicts across Python, dg-reasoner, C#, and
   persisted replay — with every non-equivalence declared rather than silent.
2. Empty population, unsupported built-ins, and missing bindings are **distinguishable** from
   a genuine pass or fail at every layer.
3. A mixed-outcome validation run **cannot** return one aggregate status for every object.
4. `publish → query → replay` reproduces a canonical state hash, or the excluded members are
   explicitly outside the normative contract.
5. The `ATTRIBUTE_OF` question is **answered**, with the ontology, code, and manuscript agreeing.
6. Unauthorized cross-project and direct-proxy access **fail closed**.
7. Deterministic-validator repeatability is reported **separately** from LLM proposal
   repeatability — no single number spans both.
