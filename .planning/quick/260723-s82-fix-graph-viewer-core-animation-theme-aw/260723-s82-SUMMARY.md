# Quick Task 260723-s82 — Summary

## What changed

The Graph Viewer thinking-core (shown while a prompt is processed) no longer paints a
dark radial backdrop + `lighter`-composited mp4 onto the canvas — the source of the
black contour on the light background. It now shows the user-produced
transparent-background GIF loops, picked by theme.

## Changes

- **`ui-v2/public/dg-think-dark.gif`** (new) — from `docs/DG_Think_Animation-black.gif`, shown in dark mode
- **`ui-v2/public/dg-think-light.gif`** (new) — from `docs/DG_Think_Animation-white.gif`, shown in light mode
- **`ui-v2/public/dg-think-sphere.mp4`** (deleted) — superseded, no remaining references
- **`ui-v2/src/graph/graphEngine.js`** — thinking-core rework:
  - `_initThinkVideo()` (blob-fetched `<video>` + canvas blit) → `_initThinkImg()`:
    a DOM `<img>` overlay inserted right after the canvas (same stacking layer,
    below UI panels), since `drawImage()` of an animated GIF freezes on frame 1
  - `src` chosen via `document.documentElement.dataset.theme`; swapped live on the
    existing `dg-theme` window event; listener + element removed in `stop()`
  - `drawThinkingCore()` positions/sizes the overlay each frame from screen-space
    `cx,cy` (CSS px, 1:1 — canvas transform is DPR-only) at the old video's 2.2R
    size, opacity driven by the `_think` intensity ramp
  - dark backdrop, `lighter` composite, and circular clip removed entirely
  - procedural fallback (GIF load failure) is now theme-aware source-over ink
    instead of white-on-dark
  - video play/pause/self-heal plumbing dropped from `startThinking()`/`updateThinking()`
