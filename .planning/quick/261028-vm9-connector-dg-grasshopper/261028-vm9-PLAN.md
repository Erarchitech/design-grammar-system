# Grasshopper CONNECTOR to a DG server (HTTPS graph read)

Source: the attached session `2026-10-28-224421-grasshopper-dg-connector.txt`. The CONNECTOR could only sign
in to `http://localhost:8000` and then opened Neo4j over Bolt with a bundle the multi-user profile withholds.
Publishing (`POST /computgraph/publish`, `POST /validation/publish`) already goes over HTTPS with the `dgk_`
session, so the missing piece is the read path.

Grasshopper -> CONNECTOR -> HTTPS API of the DG server -> Neo4j. No Neo4j password reaches the user's computer.

## Tasks

1. **Server read route.** `GET /connector-graph/{project}/{query_id}`, connector principal only, bound-project
   equality from the policy layer. `query_id` picks one of nine fixed read-only statements by name
   (`rules, atoms, objects, classes, objProperties, dataProperties, runs, standaloneStates, evidence`); the
   connector never sends Cypher; the project is only a bound parameter. Route policy row, route-inventory size
   pin, and the machine-checked block plus a prose bullet in `spec/SECURITY-BOUNDARY.md`.
2. **DG.Core read path.** `ConnectionInfo` gains `GraphApiUrl`/`GraphApiToken`. `GraphQuerySession` opens Bolt or
   the HTTPS graph API behind one `IGraphQuerySession`; the three repositories read through it and keep their
   row-to-model code unchanged. `Neo4jConnectorService` probes server mode with the cheapest named query.
3. **CONNECTOR component.** Optional last input `Server` (empty = `http://localhost:8000`, bare host = https)
   and last output `Server`; server mode when the server hands out no bundle or is remote; sign-out goes to the
   server the session was minted on; the mapping runner follows the Server input. Request keys of the three
   graph components include the new fields.

## Non-goals

- Revit connector and the DeGram connector installer. `Neo4jPredicateKindResolver` and
  `ValidationRunsQueryService` (no component uses them) stay Bolt-only.
- No change to the sign-in, session, publish or mapping routes.
